# 音(BGM・効果音)の実装 — 勉強資料

2026-10-26。設計と決めたことは [docs/design/audio.md](../design/audio.md)。ここでは、**使った用語・技術、見つけた問題と直し方**をまとめる。

## 1. 用語
| 用語 | 意味 |
|---|---|
| サンプル / サンプルレート | 音は、1秒を細かく刻んだ「音の高さの値」の列。1秒に何個あるかが、サンプルレート(このゲームの検査は48000Hz) |
| フレーム(音の) | 全チャンネル(左・右)の1サンプルずつの組。ステレオの1フレーム=2サンプル(画面のフレームとは別の言葉) |
| PCM | 圧縮していない、サンプルの列。スピーカーに送る直前の形 |
| デコード | mp3 などの圧縮を、PCM に戻すこと |
| ストリーミング | 曲全体をデコードして持たず、鳴らしながら少しずつ読む方式(長い曲のメモリ節約)。短い効果音は、先に全部デコードする(すぐ鳴らせる) |
| ミキサー | 複数の音の大きさを掛け合わせて、1つの出力にまとめる部分。ここでは「大きさの計算」だけを自前で行う |
| ゲイン | 音の大きさの倍率(0=無音、1=そのまま) |
| RMS | 音の「平均的な大きさ」(二乗平均の平方根)。検査で、鳴っているかを数字で見るために使った |
| リスナー | 音を聞く位置。このゲームでは、カメラ |
| クロスフェード | 今の曲を小さくしながら、次の曲を大きくして、切り替えること |
| 音声バックエンド | 実際に音を出す部分。差し替えられるように、インターフェース(`IAudioBackend`)の裏に置く |

## 2. 使った技術
### 計算は自前、再生だけライブラリ
距離による減衰・音量の層・ミュート・フェードは、`AudioSystem` / `AudioMixer` が計算し、miniaudio には「最終の大きさ」だけを渡す。
- **利点**: ルールを、音のデバイス無しで、自動テストできる(98項目)。ライブラリを替えても、ルールは変わらない。
- **代わりに**: ライブラリの3D音響の機能は使わない(左右の定位などは無い)。

### 大きさは、掛け算で重ねる
`マスター × 種類の音量 × 音ごとの音量 × ミュート × 距離 × フェード`。各層が独立なので、どれかを0にすれば無音、どれも他の層を知らなくてよい。

### ミュートは「要求の数え方」
`AddMute` は、ハンドル(番号)を返す。同じ対象に何度要求しても、**全部のハンドルが解除されるまで**ミュートのまま。(別々の理由でミュートした時に、片方の解除で音が戻らないため)。時間つきの要求は、`Update` で残り時間を減らして、0で自動解除する。ユーザーの設定(システム画面のスイッチ)は、別の旗で持つ。

### 「プツッ」を避ける
音の大きさを一瞬で変えると、波形が不連続になって、ノイズが出る。ミュート・解除は約0.08秒かけて、`muteFactor` を少しずつ動かす。

### 音の表をデータにする
音ごとの設定(ファイル・種類・音量・ループ・距離・同時数)を `Sounds/sounds.json` に書く。コードは id だけを知る(`PlaySe("ui_open")`)。音を替える・調整するのに、再ビルドが要らない。壊れた行は飛ばして警告し、範囲外の値は直す(落ちない)。

### 音が出せない環境でも落ちない
初期化に失敗したら、`AudioSystem` は何もしない状態で続く(`IsAvailable()` が偽)。呼び出す側は、毎回確認しなくてよい。

## 3. ゲームへのつなぎ方
- タイトル画面の開始で BGM、スタートで SE、メニューを開く・タブを切り替える時に SE。建物などの項目の選択、戻る、セーブ/ロード、終了では鳴らさない。
- メニューを「開いた」瞬間は、すでにある `SyncMenuTimeScale`(閉→開を見つけて、時間を止める所)に足した。ボタンでも Esc でも、1か所で拾える。
- タブの切り替えは、`GameMenu` が分かっていたが外に伝えていなかったので、`MenuResult::tabChanged` → `HudResult::menuTabChanged` で、上へ渡した。
- 音の更新に渡す時間は、実時間(`TimeManager`)。ゲーム内の時間(メニュー中は0)ではないので、時間が止まっていても、曲のフェードは進む。

## 4. 見つけた問題と直し方
| 問題 | 原因 | 直し |
|---|---|---|
| フェードインで始める、繰り返さない曲が、鳴らされなかった | 「聞こえない大きさなら鳴らし始めない」の判定が、フェードの始めの大きさ(0)で行われていた | 判定だけ、フェードを1として計算する |
| 鳴り終わった音の分のメモリが残り続ける | `AudioSystem::Update` が、一覧から外すだけで、バックエンドに片付けを伝えていなかった | 外す時に `m_backend->Stop(id)` を呼ぶ |
| 曲が約2秒で無音になる(検査だけ) | 実時間より速く波形を書き出すと、miniaudio のストリーミングの読み込みが追いつかない | 実際の再生では起きない。検査を、実時間(10ミリ秒ずつ待つ)で進める |
| ライセンス文の抜き出しで、最後の1行が欠けた | 切り出す範囲の指定が1行短かった | 全体を抜き出し、`*/` だけを除く |
| 検査で「SEが鳴らない」 | マスター音量0では、聞こえない音として、鳴らし始めない(設計どおり) | 検査の音量を0.002にした |
| (環境) Python が無い、Bash の `sed -i` が CRLF を壊す | Windows の標準環境 | PowerShell の `ReadAllText` / `WriteAllText`(BOM つき、行末を保つ)で編集 |

## 5. 検査のしかた(聴感以外)
聴こえ方の良し悪しは、私には確認できない。その代わりに、次を数字で確認した。
- 実際のmp3を、デバイス無しのエンジン(`noDevice`)で波形にして、RMS・ピークを測る: 鳴る、大きさが比例する(0.5で半分)、0で無音、終わる、ループする。
- `AudioSystem` を通して: マスター音量、種類の音量、ピンポイントのミュート(解除で戻る)、ユーザーのミュート、距離(近い>中間>遠い>範囲外は鳴らさない)。
- 実際のゲーム(診断コードで一時的に): 音量をほぼ0にして起動し、BGM が鳴っている状態(`CurrentBgmId`)、SE が始まって終わること(`ActiveVoiceCount`)を、ファイルに書き出して確認した。診断コードは、確認後に消した。
- 実機のデバイスを開けること、Release の配布フォルダ(別の作業フォルダから起動)が落ちずに動くこと。

## 6. オプション(音量の設定画面)と、エディタの音のパネル
### 用語
| 用語 | 意味 |
|---|---|
| ヒットテスト | カーソルが、どの部品の上にあるかを調べること(FindButtonAt) |
| ドラッグ(つかみ) | ボタンを押した瞬間に「つかむ」状態になり、離すまで、カーソルの位置で値を変え続けること。カーソルが部品の外へ出ても続く |
| 入力モード | 数字の欄を押した後、キーの入力を、その欄が受け取る状態。入力中は、同じキー(Esc・右クリック・Enter)の、ほかの意味(メニューを閉じる)を止める |
| 一時ファイル+置き換え | ファイルを書く時、別名の一時ファイルに書き切ってから、本物と置き換える。書き込み中に落ちても、元のファイルが壊れない |
| デバウンス(待ってから保存) | 値が変わり続けている間は書かず、止まってから1回だけ書くこと。ここでは、マウスのボタンを離してから |

### 技術
- **ゲーム内UIの部品の追加**: GameMenu は、「配置(Layout)」と「入力」だけを持ち、ゲームの中身を知らない作り。スライダー・数字欄を足す時も、ButtonKind に種類(Slider/NumberField)を足し、押された結果は MenuCommand(SetVolume)で返す形にした。音を鳴らす・保存するのは Game。
- **見た目は、スキンの後ろ**: スライダーの描き方は IUISkin::DrawSlider に足した(ProceduralUISkin が図形で描く)。画像素材に差し替える時も、GameMenu は変えない。つまみの動く範囲の決まり(両端は、高さの半分内側)を、描く側と入力側で、そろえる。
- **状態の更新の順番**: 配置を作る前に、つかみ中・入力中の状態を進める(スライダーの位置は前フレームの配置を使う)。こうすると、入力中の文字が、同じフレームの描画に出る。
- **エディタのパネルとゲーム内UIが、同じミキサーの値を見る**: 値の持ち主は1つ(AudioMixer)。どちらかで変えても、もう一方に出る。保存も、ミキサーの値が変わったかを見るだけなので、どちらで変えても保存される。
- **音ごとの音量の保存**: 表の値を直接書き換え、保存ボタンで書き戻す(SoundTable::SaveToFile)。保存しない限り、ファイルは変わらない。

### 見つけた問題と直し方
| 問題 | 原因 | 直し |
|---|---|---|
| Releaseの `x64\Release\GAME.exe` が、すぐ終わる | Releaseは、起動時に、exeのフォルダを作業フォルダにする。そこには、シェーダー・モデルが無い(配布用のフォルダだけにある) | 素材(SimpleShader.hlsl)がある場所を、exeのフォルダから上へ4段まで探して、見つかった所を作業フォルダにする |
| `0.8` が `0.800000011920929` と保存される | floatをdoubleにすると、誤差が見える | 3桁に丸めて書く |
| (検査) PowerShell の Move が使えない | Move は Move-Item の別名 | 関数名を MoveCursor に変えた |

### 画面での確認について
実際のウィンドウに、マウス・キー入力を送る確認は、ほかのウィンドウ(ブラウザ)が手前にあると、そちらに入力が行ってしまい危険。やめた。代わりに、診断コード(一時)で、ゲーム自身が、裏のバッファ(描いた絵)をファイルに保存して、見た目を確認した。操作の確認は、画面を使わない単体テスト(配置・スライダー・数字入力・端の値・入力のやめ方)で行った。

## 7. 次にやること
街の中の効果音(配置・住民など。距離による減衰が活きる) → ミュートのスイッチ(オプション) → エディタの音のパネルの拡張(距離などの編集・音の追加)。

## 8. 音のパック(素材の規約に合わせて、配布物に mp3 を入れない)
### 用語
| 用語 | 意味 |
|---|---|
| パック(アーカイブ) | 複数のファイルを、1つのファイルにまとめたもの。ゲームでは、素材を配る時によく使う |
| かき混ぜ(スクランブル / XOR) | データの各バイトに、鍵から作った乱数のバイトを、XOR(排他的論理和)する。もう一度同じ操作をすると戻る。**暗号としては弱い**が、「普通のプレイヤーでは開けない」ようにする目的には使える |
| xorshift32 | 少ない計算で、乱数の列を作る方法(シフトとXORだけ) |
| ハッシュ(FNV-1a) | データから決まる短い数。中身が壊れたか・正しく戻せたかを確かめる |
| ストリーミング | 全部を読み込まず、鳴らしながら少しずつ読む |
| デコーダー | mp3 などの圧縮を、音の波形に戻す部品 |

### 技術
- **パックの形式を自分で決めた**: 見出し(名前・大きさ・ハッシュ)+ かき混ぜた本体。読み込みでは、範囲を確かめながら読む(`Reader`)。途中で切れた・版が違う・大きさが合わない・名前が空・巨大な大きさの宣言、は全て読み込みの失敗にして、落とさない。中身のハッシュが合わないファイルだけ飛ばして、残りは読む。
- **同じ手順を2つの言語で**: 作る側(PowerShellの中のC#)と読む側(C++)で、かき混ぜ方を一致させる。ずれると読めないので、**PowerShellが作ったパックをC++が読んで、元のファイルと完全に一致する**ことを、テストで確認した。
- **メモリ上のデータを鳴らす**: miniaudio の `ma_resource_manager_register_encoded_data` で、名前をつけて登録すると、`ma_sound_init_from_file` が、ディスクより先に、これを使う。短い音は、これで足りた。
- **ストリーミングは、ディスクのファイルだけ**: 長い曲(BGM)は、登録したデータをストリーミングできなかった(鳴らせなかった)。そこで、`ma_decoder_init_memory` で、メモリ上のデータからデコーダーを作り、`ma_sound_init_from_data_source` で鳴らす形にした。デコーダーは、音より後に片付ける(`Impl::Voice`)。

### 見つけた問題と直し方
| 問題 | 原因 | 直し |
|---|---|---|
| パックから、効果音は鳴るのに、BGMだけ鳴らない | `stream` の曲は、miniaudio が、メモリに登録したデータを扱えない | 上の、デコーダー経由の鳴らし方 |
| (確認)「ID3」の文字がパックの中に見つかった | 2MBの中に、偶然、同じ3文字が並んだ(曲の先頭の位置ではなかった) | 位置を調べて、先頭ではない(かき混ぜられている)ことを確認 |
| (検査) PowerShell の `R` が使えない | `R` は `Invoke-History` の別名 | 別の関数名にした |

### 確認の考え方
「パックから鳴る」だけでなく、「**ディスクのファイルが無ければ、パックが無い時は鳴らない**」も確認した。これで、パックが使われていること(ディスクのmp3を、こっそり読んでいない)が分かる。配布用 zip を展開し直した、mp3 の無いフォルダで、BGM が鳴っている状態になることも、確認した。

### 限界(正直に)
かき混ぜた形式は、時間をかければ、元に戻せる(鍵が、ゲームの中にあるため)。規約の「容易に取り出せない」を満たすための、最低限の対応。もっと強くするなら、暗号(AESなど)を使う方法があるが、鍵がゲームの中にある限り、本質は変わらない。
