# 住居なしの住民の入居と、解体後の青マス

2026-10-29。設計は [docs/design/resident_outing.md](../design/resident_outing.md) の §18・§19。ここでは、仕組み・困った点・確かめたことを、自分で読み返す用にまとめる。

## 1. 用語
| 用語 | 意味 |
|---|---|
| 住居なし(Homeless) | 住んでいた住宅が解体された住民の状態。元の住宅の位置に立ち、外出も施設の利用もしない |
| 青マス | 道路の脇などに登録された、建物を置く目印のマス(`GridOrientationRegistry`)。向き(yaw)と基準の原点を持ち、先に登録された物が優先される |
| 道路の脇の帯(frontage zone) | 道路の縁から2マス(`kFrontageDepthCells`)の、道路が青マスを作る範囲 |
| 待ち(reserve) | 新しい住宅に、新しい住民を、まだ生まれさせない印。入居者を選ぶ間だけ |
| モーダル | 開いている間、後ろの画面を操作できない表示(今回の入居パネル) |

## 2. 入居の選択
### 2.1 なぜ「待ち」が要るか
住民は、約3秒ごとの判定(`RunDemandTick`)で、住宅に足りない分だけ、**自動で生まれる**。住宅を建てた直後に、パネルを出しても、判定が先に走ると、新しい住民が生まれてしまい、「選ぶ」意味が無くなる。そこで、住宅を建てた瞬間に `ReserveHouse` で待ちにし、選び終わる(または、やめる)まで、生まれさせない。
- 時間は、パネルが開いている間、止まるので、普通は判定が走らない。それでも、待ちを入れたのは、(a)ツールを選んでいる間も時間が止まる仕組みと、独立に正しく動かすため、(b)エディタなどで時間が動く場合でも、正しく動くため。

### 2.2 位置を飛ばさない
入居する住民は、元の位置から、新しい家へ**歩く**。住民の移動の経路づくり(`StartReturnFromHere`:「今の位置 → 家」)を、そのまま使った。家のidを新しい住宅にしてから呼ぶだけで、帰宅と同じ動きになる(到着すれば、家にいる状態)。
- 道が無い時は、立ち往生になる。ただし、立ち往生の**罰(満足度の低下)は、かけない**(`strandedPenalty=false`)。住民のせいではないので。道がつながれば、既にある「立ち往生の復旧」の仕組みが、新しい家へ向かわせる。

### 2.3 画面の作り
既存の「住民の情報」パネルと同じ作り(`IUISkin`を通す、配置と入力だけを持つ、中身は知らない)。ImGuiではなく、ゲーム内のUIなので、Releaseでも出る。
- 一覧が画面に入らない時は、**ページ送り**。1ページの行数は、画面の高さから求める。ページを送っても枠の大きさが変わらない(最大の行数で決める)。
- 閉じる操作: 「新しい住民を迎える」ボタン、Esc、右クリック。**パネルの外のクリックでは閉じない**(クリックが他のボタンに当たったと思って、誤って選ばないようにするため)。

## 3. 解体した跡の青マス
### 3.1 原因
建物を置く時に、敷地のマスを青マスに登録する(`SpawnBuilding`)。解体では、建物のオブジェクトと占有を消すだけで、**青マスの登録簿は触っていなかった**。道路を解体する時は、不要な青マスを消す処理があったが、建物には無かった。

### 3.2 直し方と、迷った点
「建物が登録したマスだけを消す」のが、素直な答え。でも、
- 建物の登録は、**先着優先**で、既に道路が作った青マスと重なる所は、登録されない。どのマスが「建物が作った物」かを、**記録していない**。
- 記録を足すと、セーブの形式を変える必要がある(古いセーブは、記録が無い)。
そこで、**今の状態から決める**方法にした。解体した敷地に重なる青マスのうち、
1. 道路の脇の帯に重なる → 道路が作った物なので、残す(建物が無い時から、青い)。
2. 今も建っている他の建物の敷地に重なる → 残す。
3. それ以外 → 消す。
道路を解体する時の処理(`RemoveCellsOverlappingExcept`)を、そのまま使える。
- 残る欠点: 道路の脇の帯の中で、建物が自分で登録したマス(道路のマスが無い所)は、消えない(帯の中は、道路が作る物として扱うため)。実際には、帯の中は、道路が先に作るので、建物が登録する余地は、ほとんど無い。

## 4. 確かめたこと
- **単体テスト**(`movein_test`、スクラッチ): 配置(画面6種 × 住民1/3/12/40人で、はみ出し・行の重なり・ボタンとの重なりが無い、全員がどこかのページに載る)、行のクリックで選ばれる、「新しい住民を迎える」、パネルの外のクリックは閉じない、ImGuiの上では反応しない、ページ送り(端では動かない・開き直すと最初のページ・住民が減ってもページが範囲に収まる)。**全て合格**。
- **ゲーム内**(Debugビルド・診断コード。確認後に削除済み):
  - 住宅を解体 → 住居なし1人 → 新しい住宅を建てる → **パネルが開き、時間が止まる**(倍率0)→ 住民を選ぶ → 待ちが外れ、パネルが閉じ、時間が戻る(12倍)。住民は、(-1.5, 0.5) から、道のり13を歩いて、新しい家(9, 1)へ着いた(帰宅中 → 家にいる)。住民の数は6人のまま、異常は0件。
  - 「新しい住民を迎える」: 住居なしの住民は残り(1人)、新しい住宅に新しい住民が生まれた(7人)。
  - 青マス: スーパー・映画館・カフェ・コンビニを置いて解体 → **登録が置く前と同じ数に戻った**(8→0、16→0、4→0、4→0)。住宅(道路の脇の帯に半分かかる位置)は、帯の中の2マスが残った(道路が作る物として残す設計。試験の街には、道路が作った青マスが無かったので、残ったのは、帯の判定のため)。
- Debug・Releaseとも、リビルドで警告・エラーなし。Releaseは起動して8秒動いた。

## 5. 確かめていないこと
- 実際のマウスでの操作(住民の行をクリック、ページ送りのボタン)。単体テストでは、同じ入力の処理を通した。
- 実際の道路を引いた街で、道路の脇の青マスが、建物の解体の後も残ること(試験の街には、道路が作った青マスが無かった)。**手で、道路を引いて、建物を置いて解体し、道路の脇の青マスが残る・建物の跡の青マスが消えるのを、見てほしい**。
- 住居なしの住民が、何十人もいる街での一覧(ページ送りは、単体テストだけ)。
