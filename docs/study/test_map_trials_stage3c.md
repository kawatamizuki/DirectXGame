# 学習メモ: 自動検証の総合検証(段階3-C)

## 1. 何をしたか
段階3-A・3-Bで作った自動検証を、長い期間・何回もの試行で動かし、決定論・状態の復元・データの保護・既存機能への影響・倍率の影響を確かめた。コードは変えず、一時的な診断コード(確認後に削除)で調べた。結果の表は `docs/design/test_map_trials.md` の「3-C の検証結果」。

## 2. 用語
| 用語 | 意味 |
|---|---|
| メモリリーク | 使い終わったメモリを返さず、使う量が増え続けること。一時的に増えて戻るのは、リークではない |
| ワーキングセット | プロセスが今、実際に使っているメモリの量 |
| 往復の忠実度 | 保存して読み込んだ街が、元の街と同じように動くか |
| 固定刻み(固定タイムステップ) | 1回の更新で進める時間を、いつも同じにすること。PCの速さ・倍率で、結果が変わらない |
| アキュムレーター | 経った時間を貯めておき、固定刻みの分だけ取り出して更新する仕組み |
| 浮動小数の誤差 | 0.333… のような数は、コンピューターでは、ぴったり表せない。足し算を重ねると、わずかにずれる |

## 3. 確かめ方の工夫
### 3.1 「実行前」を、1回往復させてから記録した
3-Aで分かった、読み込みの丸め(`visitHoursLeft` の -0.001 → 0)があるので、何もしなくても、往復すると街のバイトが少し変わる。
実行前の街を、先に1回、保存→読み込みしてから記録した。こうすると、「自動検証の後に戻った街」と、ぴったり比べられる。

### 3.2 リークかどうかは「回を重ねて、増え続けるか」で見た
試行の間、メモリは +8〜12MB 増えるが、試行の終わりには戻る。各回の終わりの値を並べて、増え続けていないかを見た(194〜199MB で、横ばい)。

### 3.3 往復の忠実度の試験(E10)
同じ所から、
- そのまま1560ステップ進めた街
- 保存→読み込み(乱数の状態も戻す)してから、1560ステップ進めた街
を比べた。完全に一致した。→ 保存していない途中の状態(経路の計算の結果など)が、結果を左右していない。`visitHoursLeft` の丸めも、動きに影響しない。

### 3.4 倍率で結果が変わる理由を、数で確かめた
同じ種・同じ2週で、倍率を変えて、抽選の回数を数えた: 倍率1=78、5=77、20=71、60=79。
コードでは、3秒ごとの需要の計算のタイマーが、3秒を超えた端数を捨てている:
```cpp
m_tickTimer += deltaTime;
if (m_tickTimer < kTickInterval) { return; }   // kTickInterval = 3秒
m_tickTimer = 0.0f;                             // 端数を捨てる
```
倍率20では1ステップが0.333秒。0.333を9回足しても、浮動小数の誤差で3.0にわずかに届かず、10回目(3.33秒)で計算する。だから、計算の回数が約1割少ない。

float で計算した、実際の間隔:
| 倍率 | 1ステップ | 3秒に達するステップ数 | 実際の間隔 |
|---|---|---|---|
| 1 | 0.0167秒 | 181 | 3.017秒 |
| 5 | 0.0833秒 | 37 | 3.083秒 |
| 20 | 0.333秒 | 10 | 3.333秒 |
| 60 | 1.0秒 | 3 | 3.000秒 |
倍率1でも、ぴったり3秒ではない(端数を捨てるため)。

## 4. 分かったこと
- 決定論: 同じマップ・種・倍率・設定なら、何回やっても、別の依頼に分けても、同じ指紋。
- 試行の独立: 毎回、原本から始まり、前の試行を引き継がない。
- データの保護: 原本・普段のセーブ・テスト用のクイックセーブは、通常の終了・中止・読み込みの失敗の、どの場合も変わらない。
- 状態の復元: 街・時計・倍率・種・乱数の状態・テストマップの使用状態が、実行前に戻る。
- 速さ: 住民18人・104週で、1回約1.7秒(倍率20・Debug)。回を重ねても遅くならない。
- 倍率: 結果が変わる主な原因は、「3秒ごとの計算の端数を捨てる」と「移動・利用の時間がステップ単位で丸まる」。通常のプレイは、フレームの間隔が毎回違うので、倍率1でも決定論ではない。

## 5. 改善の方針(段階4以降)
- 通常のプレイも検証も、**ゲーム内の時間で決めた固定刻み**で進める(アキュムレーター方式)。高速にするのは、描画を減らして、1フレームに多くのステップを回すことで行う。
- 3秒ごとの計算は、端数を捨てずに引く(`m_tickTimer -= kTickInterval`)か、ステップの回数で数える。
- どちらも住民の動きの結果を変えるので、承認と、前後の比較が必要。

## 6. 気をつけること
- 一時的な診断コードは、`DIAG-TEMP` の目印を付け、控え(コピー)から戻して、確実に消す。
- 診断が作ったファイル(耐久試験のCSVなど)も、消す。
- 大きな街のテストマップは、まだ無い。もっと大きな街での速さ・メモリは、実際の街を作ってから確かめる。
