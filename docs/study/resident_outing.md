# 住民の外出・施設の選択・週の仕組み — 勉強資料

2026-10-28。設計と仮の数値は [docs/design/resident_outing.md](../design/resident_outing.md)。ここでは、**使った用語・技術、見つけた問題と直し方**をまとめる。

## 1. 用語
| 用語 | 意味 |
|---|---|
| 重み付き抽選 | 候補に「重み」を付け、重みの比で確率的に1つ選ぶ。重み10と5なら、約2:1で選ばれる。強い候補が必ず選ばれるわけではない |
| 累積和(ルーレット選択) | 重みを順に引いていき、0未満になった所の候補を選ぶ方法(`PickWeightedIndex`)。0〜1の乱数を、重みの合計にかけて使う |
| 指数減衰 | 距離とともに `exp(−距離/目安)` で小さくなる。目安の距離で約37%(1/e) |
| 疑似乱数(xorshift32) | 少ない計算で作る乱数。**同じ種なら同じ列**なので、施設選びを再現できる(デバッグしやすい) |
| 決定的なハッシュ | 同じ入力から、いつも同じ散らばった値を作る(住民の特徴を、種から決める) |
| 状態機械 | 住民の状態(家・外出・施設の中・帰宅)と、その切り替え |
| イベントの数え上げ | 週末・起床を、フラグではなく**回数**で溜め、使う側が受け取って0に戻す(更新されない間の取りこぼしを防ぐ) |
| 判定の順序 | 週末の処理で、先に判定(ペナルティ)し、後で自然減少する。順序を逆にすると、新しく減った分を罰してしまう |

## 2. 使った技術
- **ルールを純粋な関数にする**: `ResidentLogic` は、画面・道路・時計を知らない(数値を渡すと結果を返す)。だから、ゲームを動かさずに、単体テストで、ルールの正しさ(確率の比・端の値・週末の順序)を確かめられた。
- **抽選の根拠を全て残す**: 候補ごとに、道のり・重み・確率・除外の理由(到達不可/体力不足)・選ばれたかを記録し、パネルで見られる。「なぜそこに行ったか」を追えることを、仕様の最優先にした。
- **仮の数値を1か所に**: `ResidentSimSettings` に集め、パネルで実行中に変えられる。コードの中に数字を散らさない。
- **時間の進み方を、区切りごとに切り替える**: 活動時間と就寝で、ゲーム内の1時間の実秒数が違う。1フレームで複数の区切りをまたいでも、区切りごとに処理する(`GameClock::Update`)。
- **住民ごとの違い**: 特徴(品質・値段・距離・自発性など)を、種から決めて、セーブする。同じ街でも、住民ごとに行き先が散らばる。
- **古いコードを消さない**: 仕事(通勤)は、`#if 0` と、使わないフィールドとして残し、何を止めたかをコメントに書いた。

## 3. 見つけた問題と直し方
| 問題 | 原因 | 直し |
|---|---|---|
| ビルドで `(` の構文エラーが大量に出た | プロジェクトでは、`windows.h` の `min`/`max` マクロが有効。`std::max(` がマクロに置き換えられる | `(std::max)(...)` と、括弧で囲む(既存のコードと同じ書き方) |
| 週末のペナルティが、すぐ悪化した | 不足の時間を、週の合計で数えていた。週の途中で改善しても罰していた | 「続いている時間」(状態が変わったら数え直す)にし、さらに、**週末の今も不足の時だけ**悪化させる(仕様: 週末までに改善できれば回避) |
| テスト用の街が読み込めなかった | PowerShell の関数に、`-2` を渡すと、数値ではなく**文字列**になっていた | 引数に型(`[double]`)を付けた |
| 週の境界の判定が、ずれるおそれ | 小数の時刻が、区切りの値ぴったりにならない | 区切りまでの秒数を計算し、ごく小さい誤差を許して、区切りの処理に入る |
| タイトル画面の間に、週が進んでしまう | タイトルの背景でも、時計は動いている | ゲームを始める時に、時計を最初の朝に戻す |

## 4. 確認のしかた
- 単体テスト(ルール): 確率は、**多数回の抽選の結果が、計算した確率に近い**ことで確かめる(例: 同じ条件の2つが半々、近い店が多いが遠い店も選ばれる)。端の値(0・上限・ちょうど80)・不正な入力・同じ種の再現も確かめる。
- ゲームの中(一時的な診断コードで、確認後に消した): テスト用の街で、12倍速で9週。週ごとの、来客・売上・資金・住民の状態をファイルに書き出して確認した。保存→読み込みの往復の前後の状態が一致することも、同じ方法で確認した。画面は、ゲーム自身に、描いた絵をファイルへ保存させて見た。

## 6. 追加: 歩く経路の修正と、住民の情報パネル
### 用語
| 用語 | 意味 |
|---|---|
| 接続点 | 建物から一番近い、道路上の点(建物から道路へ、垂直に下ろした足) |
| ノード | 経路探索のグラフの点。このゲームでは、道路区間の**端点だけ** |
| 光線(レイ)の当たり判定 | 画面のクリック位置から、3D空間へ光線を飛ばし、建物の箱(OBB)に当たるかを調べる。一番手前に当たった物を選ぶ |
| モーダルなUI | 開いている間、後ろの操作を受け付けない(画面全体が、そのUI)。パネルの外のクリックで閉じる |

### 技術と問題
- **斜めの出入り**: ノードが区間の端点だけなので、「建物 → 端点」と歩かせると、道路を斜めに横切った。**接続点を、経路に足す**(建物 → 接続点 → 道路に沿って → 接続点 → 建物)ことで直した。端点から入る組み合わせを2x2通り試して、短い方を使う。確認は、「全ての区間が、軸に平行」という、見た目の問題を数に直した検査にした。
- **経路の部品を切り出した**: 最初は `DemandSystem.cpp` の中に書いたが、画面・ゲームを知らない部品として `RoutePlanner` に切り出し、単体テストできるようにした。
- **UIの部品を、メニューと同じ作りに**: 配置・入力だけを持ち、中身は渡された行の一覧だけを見る(`ResidentInfoPanel`)。見た目はスキンの後ろ。住民のデータは、表示用のコピー(`ResidentInfo`)にして渡し、UIが `DemandSystem` の内部を知らないようにした。
- **時間を止める仕組みの使い回し**: メニューが開いている間、時間を止める仕組み(`SyncMenuTimeScale`)に、「パネルが開いている」も足しただけ。止める前の倍率を覚えて、閉じたら戻す。
- **小さな画面への対応**: 行が入りきらない時は、行を縮め、それでも入らなければ、上から入る分だけ出す(テストで、極端に小さい画面で、行が「閉じる」ボタンに食い込むことを見つけて、直した)。

## 7. 追加: 住民のクリックと追跡、当たり判定の表示
- **小さな物のクリック**: 当たり判定の箱を、少し大きくする。ローカルの箱は、物の拡大(scale)が掛かってワールドの大きさになるので、「ワールドで0.12マス」にしたければ、`0.12 ÷ 拡大` をローカルの箱に足す(`PickBounds`)。
- **優先順位**: 住民と建物の両方に当たった時は、住民を優先(住民のほうが小さく、狙って押すため)。見えない住民(建物の中)は、対象から外す。ただし、追跡中の住民だけは、対象にして、情報を開けるようにした。
- **当たり判定を見えるようにする**: 表示用の箱と、クリックの判定の箱を、**同じ関数**で作る。別々に作ると、見えている箱と実際の当たりがずれて、確認の意味が無くなる。
- **カメラの追跡**: 目標の注視点を、追う点にする(ズームの後に)。追うのをやめる合図は、ユーザーが自分で動かした時(キー・ドラッグ)。
- **既存のBounds表示**: Editingモードだけだった条件を外し、Playingでも出るようにした(スイッチがOFFなら出ないので、見た目は変わらない)。
- **設定ファイルの汚れに注意**: 診断のために、表示のスイッチ(`hit_boxes`)をONにすると、設定ファイル(`Settings/editor.json`)に保存されて、次の起動でも表示されてしまう。確認の後に、元に戻した。

## 8. 追加: クリックとドラッグの見分け、デバッグ表示の切り分け
- **クリックとドラッグを、同じボタンで**: 押した瞬間は、まだ、どちらか分からない。押した位置を覚えておき、押している間に、しきい値(6ピクセル)より動いたら「ドラッグ」、動かずに離したら「クリック」とする(`ClickDragGesture`)。そのため、クリックの処理は、押した時ではなく**離した時**に行う。数ピクセルの手ぶれで、ドラッグにならないよう、しきい値を設ける。
- **ほかの操作との取り合い**: 左ボタンは、建物・道路を置く道具(特に自由描きのドラッグ)も使う。だから、配置中は、カメラのドラッグを始めない。UIの上で押した時も、始めない(始める条件は、呼び出し側が渡す)。
- **つかんだ点**: ドラッグが始まるまでに動いた数ピクセルも、カメラに反映するため、つかむ点を「押した位置」にする(始まった瞬間の位置にすると、少し遅れて付いてくる感じになる)。
- **デバッグ表示は、Releaseに入れない**: 当たり判定の箱の描画は `#ifdef ENABLE_EDITOR` の中。スイッチ・F3のキーも、Debugだけ。ゲームの表示として必要な「選択・追跡のしるし」は、別に作り(足元の四角・輪)、箱の表示と混ざらないようにした。
