# 建物の解体(Gate 1): 住居なしの住民・施設の解体・占有の作り直し

## 作ったもの
メニューの「建築」に、ツール「解体」を追加(1棟100円)。建物を、クリック、または、押したままなぞって選び(赤い×のプレビュー)、離した時に一括で解体する。道路の解体は、まだ無い(Gate 2以降)。

## 設計の判断と、その理由

### 1. 住民の「家」は、idで持ち、0を「家が無い」の印にした
- 住民は、家を `homeObjectId`(GameObjectのid。添字でもポインタでもない)で持っている。建物を消しても、住民のデータ(需要・体力・特徴・履歴)は、そのまま残る。
- 家が解体されたら、`homeObjectId = 0` にし、元の家の位置を `homePosition` に覚える。**ポインタや添字を持たない**ので、`Despawn`(末尾と入れ替えて消す)で添字がずれても、壊れない。
- `0` は「未割当」の意味で、GameObjectのidは1から始まる。「0を家のidとして検索してしまう」事故(`GetResidentInfoForHome(0)` が、家の無い住民に当たる)を、明示的に防いだ。

### 2. 住民の状態に `Homeless` を足した。外出中の住民は、位置を飛ばさない
- 家にいた住民: その場で(元の家の位置に)`Homeless` になり、見える状態で立つ。動かず、外出も施設の利用もしない。需要・体力の**週の処理は続ける**(免除しない)。
- 外出中の住民(歩いている・施設の中・帰宅中): **今の外出を続け、帰り着いた時に、元の家の位置で`Homeless`になる**。経路の先頭は、元の家の位置なので、位置が飛ばない(ワープさせない)。
- 同じ位置に何人も立つ時は、`HomelessOffset`(ひまわりの種の並び=黄金角+平方根の半径)で、少しずつずらす。隣り合う点の間隔が、ほぼ一定になる。

### 3. 施設を解体した時の、進行中の外出
- 施設の中にいた住民: 利用を成立させず(売上・需要の回復なし)、施設の位置から、帰り始める。
- 施設へ歩いている住民: **その場で折り返す**。経路(自宅→施設)の「通り過ぎた所」+今の位置を、逆向きに並べて、帰る(`StartMove`は、出発地点へ位置を飛ばすので、使わない)。
- 帰宅中だった住民: 行き先の記録だけを消して、そのまま帰る。
- 経路が壊れている時の安全策(その場で、家にいる/住居なしの扱い)も入れた。

### 4. 売上の記録は、施設ごとに残す(1件に統合しない)
- `FacilityRecord::demolished` の印を足した。施設の種類・週・月・累計は、そのまま残る(合計にも入る)。後から、種類別の収益や配置の良し悪しを、分析できる。
- セーブには、`"facility": -1, "demolished": true` で保存する。読み込みでは、建物が無いので、GameObjectのidと重ならない仮のid(`0x80000000`から)を付ける。

### 5. 占有は「全部消して、材料から作り直す」
- `CellOccupancyGrid` は、(a) マスの集合(参照回数なし)と、(b) 矩形の一覧+索引でできていて、**1つだけを解除できない**(マスの集合は、他の建物・道路と共有されている)。
- なので、`Clear()` してから、道路の区間(`RoadSystem::ReregisterOccupancy`。`RestoreSegments` と同じ処理を共通化)と、建物の敷地(`BuildController::ReregisterOccupancy`。`SpawnBuilding` と同じ登録)から作り直す。建物の解体は稀な操作なので、作り直しの費用は問題にならない。

### 6. 操作(ドラッグ)の設計
- **選択は、idの集合**(`DemolitionSelection`)。同じ建物を何度なぞっても、1回だけ(多重請求の防止)。
- **速いなぞりでも、飛ばさない**: 前のフレームのカーソルから今のカーソルまで、画面上で4ピクセルずつ刻んで、各点で建物を当てる。
- **離した時に、一括確定**。払えなければ、**全体を取り消す**(一部だけ消さない)。UIの上で離した時も、取り消す。Esc・右クリックで、選びかけだけを先にやめる(道路の置きかけと同じ作り)。
- 費用の計算・選択は、画面に依存しない純粋な部分に分けて、単体テストした(`demolish_test`)。

### 7. 「道路がない！」の表示
- シミュレーションは、元々、建物ごとに「近くに道路があるか」を3秒ごとに調べていて、道路に接続できない住宅は外出せず、施設は、行き先の候補から外れる(=**機能停止は、既に実現していた**)。足りなかったのは、表示だけ。
- `DemandSystem` が、接続できない建物のidを覚え、`Game` が、画面の位置に直して、`GameUI` が、建物の少し上に赤い札で出す。
- 住居がない住民の上にも、同じ札の仕組み(`HudState::worldLabels`)で、「住居がない！」を出す(`DemandSystem::GetHomelessAgentObjectIds`)。

## 見つけた問題と直し方
- 住民が家を失った後の、セーブ・ロード: 元は、「家が見つからない住民は、保存しない(復元できないため)」だった。→ `home: -1` と `homePosition` で保存し、読み込みで、住居なしとして復元する。古いセーブは、そのまま読める(変更しない形式)。
- 帰宅中の住民で、行き先の施設が消えた場合: 元は、「行き先が見つからない外出は、家にいる住民として保存」だった(歩いている途中が消える)。→ 帰宅中は、行き先が無くても、途中のまま保存・復元する。
- Gate 0 の報告で、「混雑表示が、道路の添字を範囲外で読んで落ちる」と書いたが、**誤り**。混雑表示のループは、範囲を確かめていた(`segIndex < segments.size()`)。ただし、道路の添字が変わると、違う区間に混雑が付く(表示のずれ)ので、Gate 2 で、道路を変えた時に、添字を空にする対策は、必要。
- PowerShell の `R` は、`Invoke-History` の別名。関数名にしては、いけない(メモリにも記録済み)。

## 確認したこと
- 単体テスト: 選択(重複・0・順序)・費用(100円/棟)・払えるか・住居なしのずらし・売上の記録(解体後も残る・合計に入る・週の区切り・復元)・週末の処理が、住居なしでも、続く・メニューの配置(ツールの欄)。
- ゲーム本体(診断用の一時コード。確認後に削除): 歩いている住民の施設を解体 → その場で折り返す(`ReturningHome`)/ 施設の中の住民 → 帰宅を始める・お金が増えない / 家にいる住民の家を解体 → 住居なし・元の位置に立つ / 外出中の住民の家を解体 → 帰り着いて住居なし / 解体した施設の売上が、記録に残る / セーブ→ロードで、住居なしの住民・解体済みの施設の記録が、残る / 画面の位置から建物を当てる・速いなぞりで途中の建物を飛ばさない・お金が足りない時は全体を取り消す・UIの上で離すと取り消す・同じ建物を何度足しても1回分・解体済みの建物は何も起きない。
