# 街づくりのカメラ(平行移動とズーム)(勉強資料)

2026-10-22。Playing(実際に遊ぶ状態)のカメラを、シミュレーションゲームによくある「見下ろして、平面を動き、ズームする」形にした時のまとめ。
実装は `Core/CityCameraController.{h,cpp}`。

## 1. 用語

| 用語 | 意味 |
|---|---|
| 注視点(focus) | カメラが見ている、地面(y=0)の上の点。画面の中心に映る。 |
| 距離(distance) | 注視点からカメラまでの距離。**ズーム(縮尺)**は、この距離を変えること。 |
| 向き(yaw) | 水平に見る方向。0=+Z(奥)を見る。 |
| 見下ろす角度(pitch) | 水平から何度下を向くか。このカメラでは固定(55度)。 |
| 平行移動(パン) | 注視点を、地面の上で動かすこと。 |
| ドリー | カメラを前後に動かして、近づく・離れること(ズームの一種。ここでは、距離を変えることで実現)。 |
| なめらかな追従(スムージング) | 目標の値へ、少しずつ追いつくこと。 |
| 指数補間 | 毎フレーム `値 += (目標 - 値) * (1 - exp(-k * dt))` と進める式。フレームの長さ(dt)が変わっても、同じ時間なら、同じだけ追いつく。 |
| レイキャスト | 画面の点から、3D空間へ光線(レイ)を飛ばして、何に当たるかを調べること。ここでは、地面との交点を求める。 |

## 2. 設計

### 2.1 2つの要素
- **平面の移動**: キー(WASD・矢印)、または、中ボタンのドラッグ。
- **ズーム**: ホイール。
- 向き・見下ろす角度は固定。だから、状態は「注視点(x,z)・距離・向き」だけ。カメラの位置は、状態から**計算**する:
  ```
  位置 = 注視点 - (sin(yaw), 0, cos(yaw)) * 距離 * cos(pitch) + (0, 距離 * sin(pitch), 0)
  ```

### 2.2 キーでの移動
- 向きに合わせて、「奥」=(sin yaw, 0, cos yaw)、「右」=(cos yaw, 0, -sin yaw)(左手座標系)へ動かす。
- 斜め(W+D)で、速くなりすぎないよう、入力のベクトルの長さを1にそろえる。
- **速さは、距離に比例**させる(引いているほど速い)。そうすると、画面の上での動く速さが、ズームによらず一定に感じる。

### 2.3 ホイールのズーム: カーソルの下の地面を中心に
単に距離を変えると、画面の中心へ寄る・引くので、見たい場所からずれる。**カーソルの下の地面の点 H が、画面の同じ場所に残る**ようにする:
- カメラの位置と注視点を、H を中心に、同じ比率 r(=新しい距離/古い距離)で縮める。
  ```
  注視点' = H + (注視点 - H) * r        距離' = 距離 * r
  ```
- 向き・角度は同じなので、カメラの位置も、同じ比率で H へ寄る(=H の見える方向は変わらない)。
- H は、カーソルの位置からレイを飛ばして、地面(y=0)との交点で求める。当たらない時(空を見ている・UIの上など)は、注視点を動かさず、距離だけ変える。
- 距離は、最小(4)・最大(40)に収める。収めた後の**実際の比率**で注視点を縮める(収めないと、端でカーソルの下がずれる)。

### 2.4 中ボタンのドラッグ: 地面をつかむ
- 前のフレームのカーソルの下の地面の点 G と、今のカーソルの下の地面の点 N を求め、注視点を **G - N** だけ動かす。
  → つかんだ地面の点が、カーソルに付いてくる。**ズームの距離によらず**、手に付いてくる(キーの移動のような、速さの調整が要らない)。
- つかむ動きは、遅れずに付いてくる必要があるので、**今の値にも同じだけ足す**(なめらかな追従を通さない)。
- レイは、画面に**見えている「今の」カメラ**で飛ばす(目標のカメラでなく)。追従の途中でも、見えている点が手に付くように。

### 2.5 なめらかな追従
- 入力は、「目標」(`m_targetFocus`・`m_targetDistance`)を動かし、「今の値」は、毎フレーム `1 - exp(-k*dt)` の割合で追いつく。
- **フレームレートに依存しない**: dtが2倍なら、追いつく割合も、2フレームぶんと(ほぼ)同じになる。
- 1フレームの時間は、0.1秒を上限にする(ウィンドウを動かして長く止まった後に、カメラが飛ばないように)。dtが0や負なら、動かさない。

### 2.6 範囲
注視点は、フィールドの範囲(+余白2)から出られない。範囲外へ行きすぎて、何も見えなくなるのを防ぐ。

### 2.7 モードの切り替え
- **Playing**: `CityCameraController`。 **Editing**: 今までのフリーカメラ(`DebugEditor::UpdateFreeCamera`)。**Playingでは、フリーカメラを止める**(WASDの取り合いを避ける)。
- ゲームシーンが始まった時: `Reset`(フィールドの中心を見下ろす最初の見え方)。タイトル画面のカメラは水平で、地面が見えないので。
- EditingからPlayingへ戻った時: `AdoptFrom`(フリーカメラの今の視点を引き継ぐ)。視線が地面に当たる点を注視点、そこまでの距離を距離、水平の向きを yaw にする。水平や上向きのカメラでも、有限の値になる(その場合は、カメラの前方の地面を注視点にする)。
- **`Camera` の yaw / pitch の同期**: フリーカメラは、`Camera` の中の yaw / pitch を使う。別の方法で位置・注視点を決めると、この値が古いままで、**フリーカメラを動かし始めた瞬間に、視点が飛ぶ**。→ `SetPosition` / `SetTarget` で、位置と注視点から yaw / pitch を求め直す(`SyncYawPitchFromView`)。

### 2.8 入力まわり
- `InputAction` に、`CameraForward / Back / Left / Right / Fast / Drag` を追加(マッピングは `InputManager` に)。
- **ホイール**: `WM_MOUSEWHEEL` を `Window` が受けて、`Game::OnMouseWheel` → `InputManager::AddMouseWheel`(溜める)→ 1フレームに1回 `ConsumeMouseWheel`(取り出して0に戻す)。回転量は、1目盛り=120(`WHEEL_DELTA`)を、1.0(ノッチ)にして扱う。使わない時も取り出して捨てる(溜まって、後で一気に効かないように)。
- **ウィンドウが前面の時だけ、キー・ボタンを読む**: `GetAsyncKeyState` は、他のアプリで打っているキーも拾う。別のウィンドウで文字を打つと、カメラが動いてしまう(診断のテストでも、本物のキー入力が混ざっていた原因)。`GetForegroundWindow() == hwnd` の時だけ読み、そうでなければ「何も押されていない」にした。
- ImGuiのパネルの上・文字の入力中・ゲームのHUDの上では、カメラは動かさない(`WantCaptureMouse` / `WantTextInput` / `mouseOverUI`)。

## 3. 確認した方法
- **単体テスト(スクラッチ。全て通った)**: 位置の計算・Reset・キー(+斜め・Shift・距離に比例)・追従(遅れる・収束する・フレーム長によらない)・ズーム(目盛り・最小/最大・**カーソルの下の点が動かない**(寄る・引く)・カーソルが無効)・ドラッグ(**つかんだ点がカーソルに付く**・カーソルが無効)・範囲・時間の上限・フリーカメラからの引き継ぎ(下向き・横向き・水平・上向き)・地面への当たり(水平・上向き・大きさ0)。
- **ゲーム本体**: 診断用の一時コードで、ホイールとキーを再現して、描画結果を保存して確認した(最初の見え方、カーソルを中心にしたズーム、右への平行移動、引いて全体が見える状態)。診断コードは、確認後に削除した。

## 4. 落とし穴チェックリスト
- ズームの比率は、**範囲に収めた後の実際の比率**を使う。
- ドラッグ・ズームのレイは、**画面に見えているカメラ**で飛ばす。
- 速さは、距離に比例させる。
- 追従は、`1 - exp(-k*dt)` で、フレームレートに依存させない。dtに上限を付ける。
- 別の方法でカメラを動かしたら、フリーカメラの yaw / pitch も合わせ直す。
- 入力は、フォーカスがある時だけ読む。ImGuiの上・文字入力中は、ゲームの入力にしない。

## 5. 今は、やらないこと(割り切り)
- 向き(yaw)の回転(Q/Eなど)、見下ろす角度の変更。
- 画面の端にカーソルを持っていって動かす操作(エッジスクロール)。エディタのパネルが画面の端にあるので、誤動作しやすい。
- ゲームパッド・タッチの操作。
