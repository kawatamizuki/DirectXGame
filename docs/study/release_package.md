# 実行環境の提出用パッケージ(勉強資料)

2026-10-25。`GAME.exe` をダブルクリックするだけで動く、配布用のフォルダと zip を作った時のまとめ。スクリプトは `tools/make_release_package.ps1`。

## 1. 用語
| 用語 | 意味 |
|---|---|
| 作業フォルダ(カレントディレクトリ) | 相対パス(`Models/...`など)の基準になるフォルダ。ショートカットや別の場所から起動すると、exeのあるフォルダと違うことがある。 |
| CRT(C++のランタイム) | C++の標準ライブラリの実行部品。DLLで使うと、遠くのPCに、VC++の再頒布パッケージが要る。静的に組み込めば、不要。 |
| 依存DLL | exeが実行時に読み込むDLL。`dumpbin /dependents`で調べられる。 |

## 2. 必要な物を、どう決めたか
1. **コードの文字列から探した**: `.hlsl`・`.obj`・`.png`・`.json`・フォントのパスを、`grep`で洗い出し。実行時に、必ず読むのは、シェーダー3つ・モデル5つ・初期マップ。
2. **モデルのMTLが参照するテクスチャも、集めた**(`Textures/colormap.png`が、モデルのフォルダごとに要る)。
3. **依存DLLを調べた**: `KERNEL32`・`USER32`・`SHELL32`・`ole32`・`XINPUT1_4`・`D3DCOMPILER_47`・`d3d11`のみで、全てWindows標準。CRTは、設定が`MultiThreaded`(静的)で、組み込み済み。
4. **フォント**: Windows標準のメイリオ(`C:\Windows\Fonts\meiryo.ttc`)を使う。同梱しない。

## 3. 作業フォルダの問題と直し方
素材は、作業フォルダからの相対パスで読んでいる。ダブルクリックなら、作業フォルダ=exeのフォルダだが、ショートカットや、別の場所からの起動では違うため、起動しないことがある。→ **Release(エディタ無し)では、起動した最初に、作業フォルダを、exeのあるフォルダにする**(`Core/main.cpp`の`SetCurrentDirectoryW`)。Debug(開発用)は、プロジェクトのフォルダの素材を読むので、変えない。

## 4. 見つけた問題(実地テストで)
| 問題 | 原因 | 直し方 |
|---|---|---|
| パッケージのexeが、起動直後(1秒)に終了した(終了コード-1) | `SimpleShader.hlsl`が、`#include "Lighting.hlsli"`で、別のファイルを読み込んでいた。コード中の文字列には、出てこないため、洗い出しで漏れた | `Lighting.hlsli`を、一覧に足した。**テスト無しで渡していたら、渡した先で起動しなかった** |
| 診断用に、別の場所で試すまで、気づかなかった | 開発のフォルダには、全部の素材があるので、足りない物があっても、動いてしまう | **配布物は、必ず、別の場所に展開して、別の作業フォルダから起動して確認する**(zipを展開した物で、確認した) |

## 5. 確認した方法
- 一時コード(削除済み)入りのexeで、パッケージを、別の場所に置き、作業フォルダを別の場所にして起動。タイトル画面(街・ボタン・文字)とゲーム画面(HUD・建物・道路)が、画面を保存して、確認できた。
- 最終のzipを、別の場所に展開して、起動(8秒間、動いた)。

## 6. 今は、やらないこと(割り切り)
- exeの署名(Windowsの警告が出ることがある)。アイコンの設定。
- インストーラー。
- 素材をexeの中に組み込むこと(今は、exeの隣に置く。バックログの「素材を exe に組み込む」)。
