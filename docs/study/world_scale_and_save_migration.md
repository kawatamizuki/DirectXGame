# 世界の大きさの変更と、古いセーブの変換(勉強資料)

2026-10-22。マス目を大きくした時のまとめ。設計は [world_scale.md](../design/world_scale.md)・[save_load.md](../design/save_load.md)。

## 1. 用語
| 用語 | 意味 |
|---|---|
| ワールド単位 | 3D空間の長さの単位。1マスの大きさ(`cellSize`)も、この単位で決まる。 |
| マス基準の値 | 「マスの何倍」で決まる長さ。マスの大きさが変わっても、同じ比率を保つべき値(道幅・住民の速さなど)。 |
| 絶対の値 | 画面の上の動き(マウスの手ぶれなど)に関わる長さ。街の大きさが変わっても、そのままにする値。 |
| データの移行(マイグレーション) | 古い形式のデータを、新しい形式の意味に直して読むこと。 |

## 2. 考え方
1. **何を大きくしたいか**を決める。マスの数を同じにして、1マスの大きさを2倍にすると、建物・住民は2倍に大きくなり、同じカメラの距離からは、見えるマスの数が減る。「カメラを引けば全体が見える」(最大距離40で40x40が見える)。
2. **全ての長さを、2種類に分ける**: マス基準(街の大きさに連動させる)と、絶対(連動させない)。コードの数字を全部調べて仕分けた。多くは、もともと`cellSize`を基準に書いてあった。
3. 連動させる値は、**1か所の定数**(`WorldScale::kCellSize`)から作る。マスが1.0だった頃に決めた数字は、`FromLegacy(x)`で、今の大きさに換算する。`kCellSize`を1.0に戻せば、完全に元の動きに戻る(確認の足場になる)。

## 3. 古いセーブの扱い
- セーブは、ワールド単位の座標を持つ。マスを大きくすると、古いセーブの建物が、マスの途中に立ってしまう。
- **保存した時の`cellSize`を記録する**。無い古いセーブは「当時の大きさ(1.0)」とみなす。読む時に、`今 ÷ 保存した時`の倍率で、場所・大きさに関わる値だけを変換する。マスの番号・マスの数・角度は、変えない(同じマスを占め続ける)。
- 形式の版(`version`)は、上げない。項目を足しただけで、古いセーブも読めるため(「足りない項目は既定値」の方針どおり)。
- システムごとの区画(住民)は、各システムが自分で変換する。そのため、読み込みの情報(`LoadContext`)に、倍率(`spaceScale`)を足した。新しく、場所・速さを保存する区画を作る時の、忘れやすい点。

## 4. 見つけた注意点
| 注意点 | 内容 |
|---|---|
| 住民のセーブにも座標がある | 住民の位置・大きさ・速さ・経路の点を、別に変換しないと、大きくなった街の中で、住民だけ小さい・遅い・道から外れる。 |
| 速さの既定値 | 保存データに速さが無い時の既定値は、すでに今の大きさの値。変換の倍率をかける前に、倍率で割っておく(`既定値 ÷ 倍率 × 倍率`)。 |
| 絶対の値と、マス基準の値の見分け | マウスの手ぶれ・最小の区間の長さは、画面の上の動きの長さなので、そのまま。道幅・隣接の距離・住民の速さは、街の大きさの値なので、連動させる。 |
| 描画の奥行き(ファー) | 100のままだと、フィールドが大きい時に、遠くの端が欠ける可能性がある。400にした。 |

## 5. 確認した方法
単体テスト(変換・往復・古いセーブ・不正な値)と、ゲーム本体(古いマップを読み込んで、建物・道路がマスに揃うこと、新しく置いた建物が揃うこと、保存→読み込み、全体表示)を、診断用の一時コード(削除済み)で画面を保存して確認した。

## 6. 追記: 「何を変えずに、何を変えるか」を先に確認する(2026-10-22)
最初に「マスを大きくする」と受け取って、**フィールドもカメラも一緒に大きくした**ため、画面の見た目が変わらなかった。ユーザーの意図は「**緑の面積(見え方)はそのままで、マスを減らす**」だった。
- 「大きくする」「減らす」と言われた時は、**画面の上で何を固定するか**(全体の広さ・カメラ・建物の大きさ)を、図で確かめる。
- カメラの距離は、「マスの何倍」ではなく「フィールドの幅の何倍」で決めると、マスを変えても、緑の面積の見え方が保たれる。
- 詳しい経緯は [world_scale.md](../design/world_scale.md) の§6。
