# ゲーム内メニューとUIのスキン(勉強資料)

2026-10-22。カイロソフト風の「メニュー」を作った時のまとめ。実装は `UI/GameMenu.*`、`UI/UISkin.h`、`UI/ProceduralUISkin.*`、`Core/Game.cpp`。見た目の差し替えの設計は [ui_skin.md](../design/ui_skin.md)。

## 1. 用語

| 用語 | 意味 |
|---|---|
| スキン | UIの「見た目」(箱・ボタン・アイコン・文字の色)の描き方。配置・入力とは切り離す。 |
| 9スライス | 画像を縦横3x3に分け、四隅は拡大せず、辺と中央だけを引き伸ばして、どんな大きさの箱にも使えるようにする方法。 |
| MenuModel | メニューに出す内容(建物・道路の項目、値段、情報)。ゲーム側が毎フレーム作って渡す。 |
| MenuCommand | メニューで押された結果(建物を選ぶ・セーブ等)。ゲーム側が実際の処理につなぐ。 |
| 幕(Overlay) | メニューを開いた時、後ろのゲームを暗くして、クリックも受け止める画面全体の四角。 |
| 配置中のしるし | メニューを閉じている間、左下に出す「建築中: 住宅 [やめる]」。 |

## 2. 操作の流れ

1. 右下の「メニュー」(または、何も選んでいない時のEsc)で開く。**ゲーム内の時間が止まる**。
2. 左の項目(建築・情報・研究・システム)を選ぶ。中身が右に出る。
3. 建築で、建物・道路を選ぶと、**メニューが閉じて時間が動き出し**、選んだ物のゴーストが出る。何軒でも置ける。
4. 右クリック/Escで、置きかけの道路 → 配置ツールの順にやめる。何も選んでいない時のEscで、またメニューが開く。

## 3. 作り方のポイント

### 3.1 配置・入力・見た目を、3つに分ける
- `GameMenu`は、**文字の幅を測らずに決められる配置だけ**にした(文字は、描く時に左寄せ・右寄せ・中央を測る)。だから、描画の準備(D3D)が無くても配置を計算でき、画面の大きさを変えながら「はみ出し・重なり」を単体テストできた。
- 描くのは、全て`IUISkin`を通す。配置の側は、色も画像も知らない。
- ゲームの中身(建物の種類・値段)を`GameMenu`は知らない。`MenuModel`(データ)を受け取るだけ。建物が増えたら、`Game::BuildMenuModel`に足すだけ。

### 3.2 時間を止める
- 開いた瞬間に、今の`GameClock`の倍率を覚えて`0`にする。閉じたら、覚えた倍率に戻す(ImGuiの「Time」パネルで倍速にしていた人は、倍速のまま戻る)。
- 開閉は、どの経路(ボタン・Esc・項目を選んだ・タイトルへ戻った)でも、`SyncMenuTimeScale`が**前のフレームとの差**で見つけて処理する。開閉のたびに時間の処理を書くと、経路が増えた時に戻し忘れるため。
- 開いた時に、置きかけの道路は、やめる(閉じた後に中途半端な状態を残さない)。

### 3.3 Esc・右クリックの優先順位(`HandleMenuKeys`)
同じキーに、複数の意味があるので、決まった順で、1回に1つだけ処理する。
1. メニューが開いている → 閉じる。
2. 配置中 → 置きかけの道路があればそれをやめる(`RoadSystem`が行う)。無ければ、配置ツールをやめる。
3. 何も選んでいない時の**Escだけ** → メニューを開く(右クリックでは開かない)。

処理した時は`inputConsumed`を立てて、同じフレームの`BuildController`・`RoadSystem`が、同じキーで二重に動かないようにする。

### 3.4 クリックの扱い
- ボタンは、**マウスの左ボタンだけ**で押す。今までのHUDは`Decide`(Enter・Space・左クリック)を使っていたが、EnterやSpaceでカーソルの下のボタンが押されてしまうので、変えた。
- メニューが開いている間は、**画面全体がメニュー**(`mouseOverUI`)。後ろのゲームに、クリック・ホイール・カメラのキーが届かない。
- ImGuiのパネルの上では、メニューは反応しない(ImGuiが手前に描かれるため)。

### 3.5 配置ツールの初期値を「なし」に
`PlacementTool::None`を足した。以前は、起動した瞬間から建物のゴーストが出て、クリックで置けた。今は、メニューで選ぶまで、何も置けない。

## 4. 確認した方法
- **単体テスト**(スクラッチ。全て通った): 7通りの画面の大きさ(2560x1440〜720x420)x全タブで、ボタンが画面・枠の内側にあり、重ならないこと。開閉・タブ・建物/道路/引き方/セーブ/やめるの操作と戻り値、開いている時の「何も無い所」のクリック、バーの上・ImGuiの上の扱い、閉じている時のしるしの扱い。
- **ゲーム本体**: 診断用の一時コード(確認後に削除)で、クリック・開閉を再現して、画面を保存して確認した(閉じた状態・建築・情報・研究・システム(セーブの結果)・道路を選んだ後の左下のしるし)。ログで、開いている間は倍率0・閉じると1に戻ることと、選んだツールの値も確認した。

## 5. 見つけた問題
| 問題 | 原因 | 直し方 |
|---|---|---|
| 診断のクリックが効かなかった | 診断で上書きした「ImGuiの上か」の値を、後ろの本物のコードが、ImGuiの実際の状態で上書きし直していた | 診断の間は、ImGuiの状態を無視する条件を、その行に足した |
| ビルドエラー(`#`の前に文字) | ファイルの先頭の文字コード目印(BOM)が、2重になっていた(Writeが元のBOMを保ったまま、さらに足したため) | 先頭の3バイトを1つ削った。ファイルを作り直した後は、先頭6バイトを確認する |
| `std::min`/`std::max`が使えない | Windowsのヘッダーが、`min`/`max`というマクロを定義している | `(std::min)(a, b)`のように、関数名を括弧で囲む |
| 保存した画面の色が、赤と青で入れ替わっていた | 診断の保存コードが、画素の並び(RGBA/BGRA)を取り違えていた(ゲーム本体の色は正しい) | 診断用なので、そのまま。色の見方に注意 |
| 選択中のアイコンが見えなかった | 選択中はアイコンが白く、「抜き」の色(「i」の文字・歯車の穴)も明るくて、同化した | 白いアイコンの時は、選択中のボタンの色で抜く |

## 6. 今は、やらないこと(割り切り)
- 研究タブの中身(準備中の表示だけ)。
- ボタンの押した時の音・出る時のアニメーション。
- ゲームパッド・タッチの操作。
- メニューのキー操作(矢印・Enterでの選択)。
