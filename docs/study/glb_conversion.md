# GLB(glTF)のモデルを、ゲームの形式に変換する(コンビニ・スーパー・映画館)

2026-10-29。Sketchfab で見つけた3つのモデル(GLB形式。CC BY 4.0)を、このゲームのOBJローダーが読める形に変換して、施設の見た目にした。

## 1. 用語
- **glTF / GLB**: 3Dモデルの形式。GLBは、モデル・画像を1ファイルにまとめた物。右手系・Y上・正面は+Z(KenneyのOBJと同じ)。ノード(オブジェクト)が木構造で、位置・回転・拡大(行列)を持つ。
- **アトラス**: 小さな画像を、1枚の大きな画像に並べた物。モデルの材質ごとの画像・色を1枚にまとめて、UVを付け替える。
- **UV**: 3Dの面に、画像のどの部分を貼るかを表す座標(0〜1)。
- **巻き順(ワインディング)・裏面カリング**: 三角形の頂点を並べる向きで、表裏が決まる。ゲーム(Direct3D)は、裏を向いた面を描かない(カリング)。
- **両面描画**: glTFの材質は、裏面も描く設定(doubleSided)にできる。3つとも、全材質が両面。
- **リニアとsRGB**: glTFの基本色(baseColor)は、リニアの値。このエンジンは、色を画面の値(sRGB)のまま使うので、色を塗る時は、リニア→sRGBに直す。

## 2. なぜ「Blenderで変換するだけ」では足りないか
- Blenderでの変換自体は、簡単(GLBを読み込んで、OBJに書き出す)。形(頂点・法線)は、それで正しく渡る。
- しかし、**このゲームのOBJローダーは、モデル1つにつきテクスチャを1枚しか扱えない**(`ObjLoader::LoadMtl` は最初の `map_Kd` だけを採用し、他の材質は、`Kd` の色を頂点色にするだけ)。今回のモデルは、材質が24個(スーパー)、44個(コンビニ。テクスチャ43枚)、12個(映画館)。そのまま書き出すと、見た目が崩れる。
- 敷地ごと入っている(スーパーは、道路・駐車場・車まで)、巨大な地面が付いている(映画館は、2833x1973)など、**そのままでは、建物として置けない**。
- → Blenderの機能(読み込み・画像の縮小・PNG保存)を使いながら、足りない処理を、スクリプト(`tools/convert_model.py`)にした。

## 3. 変換の中身(tools/convert_model.py)
1. **読み込み**(Blender): GLBを読む。全オブジェクトの、位置・回転・拡大を、頂点に焼き込む(numpyで計算。拡大が鏡像=行列式が負の時は、三角形の表裏を入れ替える。法線は、逆転置行列で変換)。
2. **巻き順の修正**: 頂点の法線と、巻き順から求めた向きが逆の三角形は、頂点を入れ替える(スーパー30個、コンビニ158個)。
3. **範囲の切り出し**(`--crop`): 範囲をまたぐ三角形は、切って、新しい頂点(法線・UVも補間)を作る(Sutherland–Hodgman法)。スーパーの店舗部分だけを残す。
4. **地面の削除**(`--drop-ground`): 一番低い所から指定の高さ以内の、水平な面(上向き・下向き両方)を消す。
5. **両面化**(`--double-sided`): 全ての三角形に、裏向きの複製(頂点を入れ替え、法線を反転)を足す。
6. **アトラス**: 使う材質だけを、正方形のマス(既定128px)に並べる。
   - 色だけの材質: 単色で塗る(リニア→sRGB)。
   - UVが0〜1に収まるテクスチャ: マスの大きさに縮めて貼る。端を2px伸ばして、隣のマスの色が混ざらないようにする。
   - UVが0〜1を超えて繰り返す材質(床のタイルなど): アトラスでは繰り返せないので、平均の色の単色にする(街の画面では、建物は小さく見えるので、模様は見えない)。
7. **回転・正規化**: Y軸の回転(正面を+Zにそろえる)、中心を原点、足元をY=0、水平の最大の辺を1.0にそろえる。
8. **書き出し**: OBJ(重複する頂点をまとめる)、MTL(`Kd 1 1 1`、`map_Kd` はアトラス)、アトラスのPNG、CREDITS.txt(作者・出典・ライセンス・加工した旨)。

## 4. 見つけた問題と直し方
- **切り出しが逆側になった**: プレビュー画像(上から見た図)の、上下左右と座標の対応を読み違えて、スーパーの駐車場側を切り出した。→ カメラの向きから、画像の右が-X・上が+Zだと確かめ直して、店舗側(Z -7.6〜1.5)にした。正面は、もともと+Z(回転は不要)。
- **映画館の地面が消えない**: 地面は、「一番低い所」から約6.8高い所(1つの材質の巨大な面)にあった。許容の高さを7.0に。向きは、上向き・下向きのどちらも消す。
- **映画館の壁が、ゲームで見えない**: Blenderでは見えていたのに、ゲームの描画では、壁が消えた(裏面カリング)。巻き順と法線は、そろって内向きで、巻き順の修正では直らなかった。→ 映画館だけ、両面化(三角形が2倍。約3.1万)。
- **スクリプトが、PowerShellから止まる**: Blenderは、警告を標準エラーに出す。`$ErrorActionPreference = 'Stop'` のままだと、それだけで止まる。呼び出しの間だけ、`Continue` にして、終了コード(`--python-exit-code 1`)で失敗を判定する。
- **看板の文字が鏡文字に見えた**: ゲームのローダーで描いた時、プレビューのカメラが、建物の裏側から見ていた(`PREVIEW_BACK=1` で正面から)。正面から見ると、文字は正しく読める(左右反転ではない)。

## 5. 確認した方法
- Blenderで、元のGLBと変換後のOBJを、同じ角度から描いて比べた(Workbench)。
- **ゲーム本体と同じ**ローダー・シェーダー(`Model`、`ModelLoaderRegistry`、`SimpleShader.hlsl`)で描く、確認用のツールで、変換後のモデルを、Kenneyの建物と並べて描いた。
- ゲーム本体を起動して、モデルの読み込みが成功すること(キャッシュ `Cache/Models/*.mesh` が作られる)。
- まだ: ゲームの中に建物を置いた見た目(道路との向き・大きさ)は、実機で確認する。

## 6. 結果
| 施設 | 元 | 三角形 | アトラス | 縦横比(奥行き/幅)・高さ |
|---|---|---|---|---|
| コンビニ | "Mini Market"(Elbolillo) | 76,883 | 896x896(テクスチャ31・繰り返し12→平均色) | 0.81・0.30 |
| スーパー | "Lowpoly Supermarket"(Klieg3D)の店舗部分 | 14,554(元は124,513) | 512x384(単色11) | 0.56・0.23 |
| 映画館 | "Cinema"(TRYFIELD) | 30,978(両面) | 512x384 | 0.62・0.16 |
- コンビニの壁は、元のモデルが暗い色(ほぼ黒)。ゲームの光でも、暗く見える。明るくしたい時は、変換のオプションを足す(まだ無い)。
- コンビニは77k三角形で、他の建物(Kenneyは約2千)より重い。数軒なら問題ないが、大量に置く場合は、内部(商品棚など、外から見えない部分)を省く、などが要る。

## 7. 「OBJローダーを改修する」場合との比較
- 変換スクリプト(今回): エンジンの変更なし。1コマンドで再現できる。繰り返し模様は平均色になる。1軒につき描画1回。
- ローダーの改修(複数材質・複数テクスチャ): `ModelData`・`Model`・描画・モデルキャッシュの形式・FBXローダーなどに入る(10ファイル前後)。GLBを直接読むなら、glTFローダーも要る。元の見た目に近いが、材質の数だけ描画が増える(コンビニは44回/軒)。大量にモデルを入れる段階で検討する。

## 8. カフェ(FBXとOBJ、どちらを元にするか。2026-10-29)
ユーザーが、同じ内容の `coffee_store.fbx` と `coffee_store.obj` を持ってきた。**FBXを元に採用**した。
| | FBX | OBJ |
|---|---|---|
| 大きさ | 0.8MB(バイナリ) | 2.3MB(テキスト) |
| 材質(色) | ファイルの中に入っている | **`.mtl` が付いていない**(`mtllib coffee_store.mtl` と書いてあるが、ファイルが無い)。そのまま読むと、全て白になる |
| 読み込みの速さ(ゲームのローダー) | 約40ms | 約114ms |
| 内容 | 同じ(三角形33,322、頂点99,966。Blender 2.80で書き出し) | 同じ |
- 元のモデルには、**600x600(Blenderの取り込みで1185)の巨大な地面**が付いていて、店は、中央の小さな点だった。地面(一番低い所から0.3以内の水平な面)を削除して、店だけにした(118三角形)。
- 看板「Coffee Store」と入口は、元の**-Z側**を向いていた(+Z側は、室外機の並ぶ裏手)。180度回して、他のモデルと同じ「正面=+Z」にそろえた。縦横比は 1:0.90(ほぼ正方形)で、1x1の敷地に合う。三角形は 33,204。材質は6つ(単色)で、アトラスは 384x256。
- 変換スクリプトを、GLB専用から、FBX・OBJも扱えるようにした(拡張子で、Blenderの読み込みを切り替える。`tools/convert_model.py`)。
- **出所が分かった**(ユーザーが、CGTraderのダウンロードページを教えてくれた): "Coffee Store" by **w-murderface**、CGTraderの**無料**モデル(Model ID #2129997、2019-10-17公開)。ライセンスは **Royalty Free License (no AI)**。紹介ページのポリゴン数(17,846)が、持ってきたファイル(17,847面)とほぼ一致する。
- **ライセンスの要点**(CGTrader規約 21A): ゲームへの組み込みは可。ただし「素材が、独自形式で、ゲームの中で表示される形」で、**エンドユーザーが元の素材を取り出せないよう、合理的な対策を取る**こと。元の形での再配布(譲渡)は不可。AI学習への利用は不可。クレジットはライセンス上は必須でないが、ダウンロードページで求められているので、w-murderface を表示する。
- **配布用zip(`dist/GAME.zip`)の扱い**: zipの中のOBJ・PNGは、誰でも取り出せるので、条件に合わない。→ `tools/make_release_package.ps1` は、カフェだけ、**同じ場所・同じ名前で、Kenney(CC0)の建物を置く**ようにした(ゲームは、同じパスを読むので、そのまま動く)。手元で遊ぶ・開発する分には、問題ない。手元のカフェをzipに入れたい時は、モデルを専用の形式にまとめる仕組み(音のパック `sounds.pak` と同じ考え方)が要る(まだ無い)。GitHubにも、OBJ・MTL・アトラスPNGを入れない(`.gitignore`)。
- 他の3つ(コンビニ・スーパー・映画館)は、CC BY 4.0 なので、zipに入れてよい(作者の表示をREADMEと `CREDITS.txt` に書いた)。
- 注意: `make_release_package.ps1` は、**PowerShell 7**(`pwsh`)で実行する。Windows PowerShell 5.1 だと、BOMの無い `pack_sounds.ps1` が文字化けして、構文エラーになる(以前からの問題)。
