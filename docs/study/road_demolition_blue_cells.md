# 道路の解体で、青マスが残る不具合(勉強メモ)

## 1. 何が起きたか(症状)
- 初期マップで、建物と道路を解体すると、建物も道路も消えたのに、「建築できる青マス」が数個、残った(道路の折れ曲がりの外側)。
- 解体ツールで道路を選ぶ時、折れ曲がりの角の外側の1マスだけ、選択の印(赤い×)が付かない。(別件の見た目の問題。§8)
- 「道路そのものが消せない」と見えた件は、別件。クリーンな初期マップでは再現せず、調査対象に残している(§9)。

## 2. 用語
- **青マス(向きのチャンク)**: 建物を置く時に、道路や建物の向きに揃った格子を作るための、登録済みのマス(`GridOrientationRegistry` が持つ。1マス = 0.5×0.5)。
  誰が登録するか: ①道路(両脇2マスの帯 = **脇の帯**。道の端の外側にも、**端の延長**ぶん0.5だけ並べる)、②建物(敷地のマス)。
- **持ち主**: 青マスを、今も正当にしている物。残っている道路の脇の帯(`RoadSystem::BuildFrontageZones`)か、今も建っている建物の敷地。持ち主のいない青マスは、跡として残るだけの、ごみ。
- **スライス**: 解体の単位。道路に沿った、マス1つ分の長さ(0.5)×道幅の四角(`RoadCutWindow`)。
- **継ぎ目の埋め草(ノードのキャップ)**: 道路が2本以上つながる点に敷く、道幅の正方形(見た目の隙間埋め。`AppendNodeCap`)。

## 3. 調べ方(再現の技術)
1. **計算部分だけを切り出して、大量に試した**: 解体の切り取り計算(`CutRoads`)を、単体のプログラムにして、ランダムな範囲・順番で3000回。最後に全部なぞれば、毎回、全部消えた → 切り取りの計算は、正しい。
2. **ゲームの実コードで、画面の全ピクセルを走査した**: 全ピクセルについて、「建物が選ばれるか」「道路のスライスが選ばれるか」を調べた。道路の上は、全て道路として選べた → 選び方も、正しい(初期マップでは。建物の判定の箱が、道路の縁のクリックを横取りする弱点は、別のマップで見つかった)。
3. **実際の解体の流れ(`DemolitionController`)を、一括・2分割・5分割で動かし**、残る青マスの数を、解体の前後で、比べた → 建物と道路を全部解体しても、青マスが4個残った。**これで再現**。
4. 残った4個の位置を調べた → 道路の東端(折れ曲がりの外側)の、延長のぶんの青マス。

## 4. 原因
- 道路は、青マスを、始点・終点の**外側(端の延長)にも**登録する。
- 解体後の青マスの掃除は、「切り取ったスライスの四角(+両脇)」の**中だけ**を見ていた。
- 折れ曲がりの角では、延長ぶんの青マスは、どのスライスの四角の外にある。そのため、道路が消えて持ち主を失っても、掃除の範囲に入らず、残った。
- 最初は、「古いセーブの状態が残っているのでは」と疑った(ご指摘)。調べると、読み込み直後の青マスには、持ち主のいない物が0個(初期マップ・クイックセーブとも)。残った青マスは、古いデータの残りではなく、**正しく登録された物が、解体で持ち主を失った**物だった。

## 5. 対策(`Field/RoadSystem.cpp`)
1. 掃除の範囲を、切り取った範囲の「周り」まで広げた(両脇の列 + 端の延長 + 余白を、長さの方向にも)。
2. その範囲では、「残った道路の脇の帯」と「今も建っている建物の敷地」の、どちらにも重ならない青マスを、消す。残った道路・建物の持ち物は、残す。
   - 以前は、残す物は「建物の敷地」だけで、残った道路の帯は、見ていなかった(交差点で、通っている道路の青マスを巻き込む恐れもあった)。
3. 切り口(平らな端)には、延長がない。`BuildFrontageZones` を、端ごとに延長を決めるように直した(切った端の外側に、帯を残さない)。

## 6. 確かめたこと
- 初期マップ: 建物と道路を全部解体 → 青マス 0個(修正前 4個)。道路だけ解体 → 残るのは、家の敷地の8個だけ。途中の1スライスだけ切る → その脇の4個だけ消え、隣は触らない。行き止まりの端を切る → 端の延長ぶんも消える。
- **正常な青マスを消さないこと**: 診断用に、実際の登録処理で、T字路・近接した平行の道路・斜めの道路・建物5軒の隣接、がある街(青マス281個)を作った。持ち主のいない青マスは、0個 → 掃除の「持ち主」の考え方が、正常な青マスを、全て、含んでいる。その街で、建物の隣・T字路の分岐・近接した道路・斜めの道路を、順に切ると、消えたのは2〜4個で、持ち主のいない青マスは、残らなかった。
- 古いセーブの残りの扱い: 持ち主のいない青マスを、人工的に、切り取りの近くと遠くに作った。近くの物は、切り取りと一緒に消え、遠くの物は、残った。

## 7. 限界・注意
- 持ち主のいない青マスが、解体の場所から遠いと、消えない(解体の近くだけを掃除する。曲線の道路の外側の、わずかなずれで、正常な青マスを巻き込まないため)。全体の掃除が必要なら、別に作る。
- **曲線(Curve)の道路**は、実際の登録処理で作った検証には、入れていない(道路の作成が、入力操作に結びついているため)。直線・T字路・斜めの直線で確認した。曲線の外側の青マスが、帯からはみ出す場合は、解体の近くで、巻き込まれる可能性がある。見つかったら、帯の求め方を、見直す。
- 青マスの登録は「先着優先」。同じ場所に、複数の道路・建物の帯が重なる時、登録した持ち主が、後から消えても、別の持ち主の帯が残っていれば、青マスは残る(正しい)。

## 8. 角の選択の印が乱れる件(原因と、直し方。実機の確認待ち)
- スライスの印は、スライスの四角に、対角線2本(×)を引く。角では、一方の道の最後のスライスと、もう一方の道の最初のスライスの四角が、**重なる**。×が重なって、線が密になる。
- 角の外側の1マスは、どのスライスにも入らないため、印が付かなかった。これに、継ぎ目の埋め草の正方形(1×1)の印(大きな×)を足した(`DrawVanishingJointCaps`)。その大きな×が、小さな×と交差して、さらに乱れた。
- 直すなら: 埋め草の印は、×を引かず、その角の1マスだけ(スライスの四角と重ならない部分)に絞る、など。

## 9. 残っている別件
- 「道路そのものが消せない」: クリーンな初期マップでは再現しない(計算・選び方とも、全て消せる)。再現条件(消せなかった時のセーブ・操作手順)が、分かるまで、推測では直さない。

## 10. 学んだこと
- 「古いデータのせい」と決めつけず、読み込み直後に「持ち主のいない物」を数えたら、原因が、データではなく、掃除の範囲だと分かった。
- 再現できないうちは、直さない。計算部分(単体)→選び方(画面全体)→実際の流れ(分割して実行)の順に、層を切り分けて、疑いを消していくと、早い。
- 「持ち主がいない物は、ごみ」という、不変条件を作ると、正常な物を消していないことも、機械的に確かめられる。

### 直し方(`Field/DemolitionController.cpp`。見た目だけの変更で、当たり判定・解体の処理は、変えていない)
- 埋め草の印: 大きな×は、やめた。埋め草の正方形を4つの区画(半分×半分)に分け、**どの選んだスライスにも覆われず、残る道路の路面にもならない区画だけ**に、枠(×なし)を引く。折れ曲がりの角では、外側の区画だけが該当する。
- スライスの×の重なり: 角(2本が集まる継ぎ目)の埋め草の正方形の中にあって、先に選んだ**別の向き**のスライスと面積を持って重なるスライスは、枠だけにする(×は先の方に残る)。向きが同じ(直線)・3本以上が集まる継ぎ目(T字路・十字路)は、今までと同じ。
- 確かめたこと: ビルド(Debug/Release)と全単体テスト。L字の角の数値の見積もりでは、外側の区画だけが枠になり、重なる×は先の道路の分だけ残る。実際の画面での見た目は、ユーザーの確認待ち。

### 2回目の直し方(2026-11-10。1回目の画面確認で「角の一部しか選ばれていないように見える」)
- 1回目の結果: 角の正方形が、①横の道路の最後のスライス(左半分・×あり)、②縦の道路の最初のスライス(右下・枠だけ)、③外側の区画(右上・枠だけ)の3つに分かれて描かれ、×が半分にしか付かなかった。乱れは減ったが、「角の全体が選ばれている」ように見えない。
- 考え方を変えた: スライスを1つずつ描くのをやめ、**消える埋め草を1つのまとまり**として描く。
  - `FindVanishingJointCaps`: 切った後に、継ぎ目に残る道路が1本以下(=埋め草が無くなる)継ぎ目を探す。正方形を4つの区画に分け、**残る道路の路面にならない区画**を「消える」とする(選んだかどうかは見ない。埋め草ごと消えるため)。
  - `WindowInsideCap`: 消える正方形の中に、すっぽり入るスライスは、印を描かない(まとまりの印に含める)。
  - `DrawVanishingJointCap`: 4区画とも消える=正方形1つに×1つ。2区画(片方の道路が残る)=長方形1つに×1つ。それ以外(斜めの道路など)=区画ごとに×。
- 用語: **まとめて描く(グルーピング)** = 細かい部品を、見る人にとって意味のある単位(ここでは「角のマス」)に、まとめてから描くこと。データの単位(スライス)と、見せる単位(角)は、別でよい。
- 注意: 斜めの道路の角では、スライスが正方形からはみ出すため、スライスの印と、まとまりの印が、重なることがある(今回は、L字・T字などの、軸に沿った道路を対象にした)。
- 確かめたこと: ビルド(Debug/Release)と全単体テスト(15本)。画面での見た目は、ユーザーの確認待ち。
