# フォルダ管理・ビューワー・モデルキャッシュ・ドラッグ&ドロップ(勉強資料)

2026-10-21。Assets を「軽い一覧」に作り直し、重い処理を別ウィンドウ(Asset Viewer)へ分け、モデルをディスクに焼いて保存し、
ゲームの画面へドラッグして置き、エクスプローラーからドロップして取り込めるようにした時のまとめ。
(ドッキング・Editorメニュー・ヒントは [docking_and_editor_layout.md](docking_and_editor_layout.md)、サムネイルは [asset_browser_and_thumbnails.md](asset_browser_and_thumbnails.md))

## 1. 用語

| 用語 | 意味 |
|---|---|
| 時間分割(time slicing) | 重い仕事を、1フレームに少しずつ(例: 8ms)進めて、画面が止まらないようにする作り。 |
| ペイロード(payload) | ImGuiのドラッグ&ドロップで、「ドラッグしている中身」。種類の名前(例 `"ASSET_MODEL"`)とバイト列(モデルのパス)を持つ。 |
| HoveredWindow | ImGuiが「今カーソルの下にあるウィンドウ」として覚えている物。ドッキングの中央の透明部分の上では **null** になる。 |
| 焼く(bake) | 重い処理の結果を、速く読める形でファイルに保存しておくこと。ここでは、モデルの頂点データ。 |
| インデックス化 | 同じ頂点の重複をなくし、「頂点の表」+「表の何番目か」の並びで持つこと。サイズが減る。 |
| チェックサム | ファイルが壊れていないか確かめるための値。ここでは FNV-1a(1バイトずつ混ぜるだけの簡単なハッシュ)。 |
| アトミック書き込み | 一時ファイルに書き切ってから名前を付け替えて、「書きかけの状態」が他から見えないようにすること。 |
| WM_DROPFILES | エクスプローラーからウィンドウへファイルがドロップされた時に、Windowsが送るメッセージ。 |
| HDROP | そのメッセージに付いてくる、「ドロップされたパスの一覧」を指すハンドル。`DragQueryFileW` で取り出す。 |
| UIPI | Windowsの仕組み。権限の低いプロセス(通常のエクスプローラー)から、権限の高いプロセス(管理者で動くゲーム)へのメッセージを拒否する。 |
| ANSIコードページ(CP_ACP) | Windowsのシステムの文字コード(日本語環境ではShift-JIS系のCP932)。`std::string` のパスは、これで解釈される。 |
| ゴースト | 置く前に見せる、半透明のモデル。 |

## 2. 作った物と、使った技術

### 2.1 フォルダの木と整理(`AssetCatalog`)
- 探した全モデルの「フォルダ」から、**親をたどって木**を作る(`std::set<std::string>` に、フォルダとその全ての親を入れる。文字列の並びでは、親は必ず子より前に来るので、1回の走査で親子をつなげられる)。
- `Assets/Models`・`Assets/Incoming` の下は、**空のフォルダも**木に入れる(実行中に作ったフォルダがすぐ見えるように)。
- 各節に「配下のモデルの数」を、モデルごとに親へ足して持たせる(重複は除く)。
- **操作(作成・名前の変更・移動)を、画面に依存しない `static` 関数**にして、単体テストできるようにした。
  - 権限: `CanCreateIn`(Models/Incoming とその下)、`CanModify`(その「下」だけ。Models/Incoming 自体は不可)。
  - パスの安全: 空・`\`・`:`・先頭の `/`・`.`・`..` を含むパスは不可(`IsSafeRelativePath`)。
  - 名前: 英数字・`_`・`-`・スペースだけ。Windowsの予約名(CON など)は不可。
  - 移動の禁止: 自分自身・自分の下へ、同じ親の中へ、同名が有る、使用中(`FolderLockCheck`)。
  - `fs::rename`(同じボリュームでは、中身をコピーせず、名前を付け替えるだけなので、速くて、途中で止まらない)。
- **使用中の判定は、関数(`std::function`)を外から渡す**: AssetCatalog は、シーンの飾りのことを知らない(依存を逆にしている)。Game が「飾りのモデルのパスが、このフォルダの下にあるか」を答える。

### 2.2 ツリー描画の落とし穴(ImGuiのID)
- ツリーの各節の右クリックメニューを `BeginPopupContextItem("文字列")` にすると、**全ての節が同じIDのポップアップ**を開くので、全部の節の分のメニューが**重なって**出た(画面保存で発見)。→ `BeginPopupContextItem(nullptr)` にして、直前の項目(その節)のIDからポップアップのIDを作る。
- ルートの節のパスは空なので、`"名前###"` とすると、IDが「ウィンドウのID」と同じになり、ImGuiの `IM_ASSERT`(「ウィンドウの直下に空のIDは使えない」)が発動。しかも**Debugビルドのアサートは、ダイアログを出して待つ**ので、ゲームが止まって見えた(CPUがほとんど動いていない=待っている、というのが手がかり)。→ ラベルを `"名前###dir:パス"` にして、必ず中身のあるIDにした。
- 木の描画中に、ドラッグで「移動」を実行すると、描画中の木(`std::vector`)が作り直されて参照が無効になる。→ 移動したい内容を覚えておき、**描画が終わってから**実行する。

### 2.3 ビューワー(`AssetViewer`)の一括読み込み
- **時間分割**: `Update` で、8msを使い切るまで1つずつ読む。**最低1つは進める**(1つが8msより長くても、止まらず進む)。
- 上限(既定64)・大きいファイル(4MB超)の省略で、読み込みが暴走しない。
- モデルは `std::unique_ptr<Model>` で持つ(`std::vector` が再配置されても、Modelの住所が変わらない)。閉じたら `clear()` で全部解放(デストラクタがGPUのバッファを解放する)。
- **複数のモデルを1枚の絵に**: `ModelPreviewRenderer::RenderScene`。各モデルを `MakeFittedTransform`(中心を原点へ、最大の辺を一定に)で正規化して、格子の位置に置き、**軌道カメラ**(`MakeOrbitCamera`)で描く。
- **名前の札**: 3Dの位置を `Camera::WorldToScreen` で2Dに直して、ImGuiの描画リストに描く。札の幅は、となりのモデルまでの画面上の距離に収める。混んでいる時は、選んだ札と、カーソルに一番近い札だけ。
- 左手座標系の注意: +Z側から見ると+Xは**左**に見える。左から右へ読めるよう、列の位置のXの符号を反転した。
- **ウィンドウの大きさのテクスチャ**: 16ピクセル単位に切り捨てて作り直す(1ピクセルごとにテクスチャを作り直すと重いため)。ドラッグでサイズを変えている間も、作り直しは16ピクセルごとにしか起きない。

### 2.4 モデルキャッシュ(`BakedModelCache`)
- **何を保存するか**: 読み込み後の `ModelData`(頂点・境界・テクスチャのパス)。座標系の変換・色の変換が済んだ後なので、読み込み時は、それらを全て飛ばせる。
- **形式**: ヘッダー56バイト(識別子・版・頂点数・重複なし頂点数・インデックスの大きさ・境界・テクスチャのパスの長さ・チェックサム)+ テクスチャのパス + 重複なし頂点(1つ48バイト)+ インデックス(重複なし頂点が65536以下なら2バイト、それ以外は4バイト)。
- **インデックス化**: 頂点のバイト列(48バイト)を `unordered_map` のキーにして(ハッシュは FNV-1a、等しさは `memcmp`)、同じ頂点を1つにまとめる。`Vertex` の隙間(パディング)が無いことを `static_assert` で保証している(隙間があると、バイト列の比較が不安定になる)。
- **キー**: モデルの相対パス・ファイルサイズ・更新日時・同じフォルダの `.mtl` の「名前:大きさ:更新日時」の並び・版、を連結して FNV-1a(64ビット)にし、16桁の16進数にして、ファイル名に入れる。ファイルが変われば、キーが変わるので、**古いキャッシュは自然に使われなくなる**(消す処理が要らない)。
  - 同じフォルダに数百個のモデルが有る時に、毎回フォルダを列挙しないよう、フォルダごとの MTL の目印を**メモリに覚えて**おく。
- **検証(壊れたファイルを信用しない)**: 識別子・版・頂点数が3の倍数・上限(1億)・重複なし頂点数の範囲・インデックスの大きさ・**ファイルの大きさがヘッダーから計算した値とぴったり同じ**・チェックサム(ヘッダー自身も含める)・全てのインデックスが範囲内、を全て確かめる。1バイトずつ全部の位置を壊したテストで、**全て拒否される**ことを確認した。
  - 最初は、チェックサムが「ヘッダーの後ろ」だけだったので、**境界の値のバイトが壊れても検出できなかった**(テストで見つかった)。→ ヘッダー(チェックサム自身を除く)も、チェックサムの対象にした。
- **アトミック書き込み**: `.tmp` に書き切ってから `rename`。
- **保存の失敗は、読み込みの失敗にしない**: 保存先が使えなくても、モデルの読み込み自体は成功させる。
- **統合の場所**: `ModelLoaderRegistry::LoadFromFile` の中(ローダーを呼ぶ前)。呼ぶ側(Model、サムネイル、ビューワー、飾り)は何も変えなくてよい。
- **落とし穴**:
  - `kVersion` を上げ忘れると、古い内容が使われ続ける。
  - 保存時にあったテクスチャが、今は無ければ、キャッシュを捨てる(別の場所で見つかるかもしれないため)。
  - 最初の計測で、「ヒット(18.5ms)がミス(8.1ms)より遅い」結果が出た。1回きりの計測だったため、ファイルの初回アクセス(ウイルス対策ソフトの検査など)の揺れを拾っていた。**ウォームアップ+複数回の平均**で測り直すと、ヒットは12倍速かった。**計測は、1回で結論を出さない**。

### 2.5 ドラッグ&ドロップで飾りを置く(`PropPlacer`)
- **Assets側**(ドラッグ元): `BeginDragDropSource` → `SetDragDropPayload("ASSET_MODEL", パス)`。
- **ゲーム側**(落とし先): ゲームの画面は、ImGuiのウィンドウではない(透明な穴)ので、`AcceptDragDropPayload` が使えない。代わりに、毎フレーム `ImGui::GetDragDropPayload()` を見て、「ドラッグ中か」「カーソルがどのImGuiウィンドウの上でもないか(`HoveredWindow == nullptr`)」「ゲームのHUDの上でもないか」「ボタンを離したか(`IsMouseReleased`)」を `GameContext::assetDrag` に書く。
  - 書くのは `Game::Update`(NewFrameの直後)。ImGuiのドラッグ状態は、前フレームの描画で作られているので、Updateの時点で読める。
  - **Updateの先頭で毎回リセット**する(Assetsが閉じた・描かれなかった時に、古い「ドラッグ中」が残って、ゴーストが出続けないように)。
- **置き方の計算**(`ComputePropPlacement`)は、画面・GPUに依存しない純粋な関数にして、単体テスト: 倍率 = 1マス ÷ 最大の辺(幅・高さ・奥行きの最大)。XZはモデルの中心を地面の点へ、Yは足元(`boundsMin.y`)を地面の高さへ。大きさ0のモデルでも無限大にならない(最大の辺に下限)。
- **ゴースト**: `Renderer::DrawModel(model, transform, camera, 0.5f)`(半透明)と、1マスの枠(DebugRenderer)。
- **モデルの置き場(`ModelCache`)**: パス→`unique_ptr<Model>`。**住所が変わらない**ので、Propが `Model*` を持ち続けて安全。読めなかったパスは覚えて、毎フレーム読み直さない(ドラッグ中は毎フレーム呼ばれるため)。
- **セーブ**: `WorldSnapshot::props`(パス・位置・回転・拡大)。JSONの `"props"`。
  - 古いセーブに `props` が無ければ空。
  - 他のデータから添字で指されない物なので、**不正な1件は警告して飛ばし、街の読み込みは続ける**(建物は、添字がずれるので、不正なら中止する、と使い分けている)。
  - **パスの安全確認**(`IsSafeModelPath`): 絶対パス・`..`・`\`・`:` を含むパスは拒否。**他人からもらったセーブデータで、PCの任意のファイルを読ませない**ため。
  - 保存→読み込み→再保存で、**文字列が完全に一致する**ことをテスト。
- **カメラが水平だと、地面にレイが当たらない**: 初期のカメラは地面の高さ(y=0)から水平に見ているので、画面の中心の先に地面が無い。「シーンの中央に置く」は、地面に当たらなければ、フィールドの中心(0,0,0)へ置くようにした。

### 2.6 エクスプローラーからのドロップ(`Window`、`AssetImporter`)
- `DragAcceptFiles(hwnd, TRUE)` で受け付けると、`WM_DROPFILES` が来る。`DragQueryFileW(hdrop, 0xFFFFFFFF, ...)` で個数、`DragQueryFileW(hdrop, i, buffer, size)` で各パス。最後に `DragFinish`。
- **メッセージの中では、パスを溜めるだけ**にして(`Window::SetDropFilesCallback`)、コピーは**次のフレームの更新**(`Game::ProcessPendingDrops`)で行う(メッセージ処理を長く止めない)。ImGuiのバックエンドのメッセージ処理(`ImGui_ImplWin32_WndProcHandler`)は、WM_DROPFILESを横取りしない。
- **コピーの規則を、画面・OSの入力に依存しない `AssetImporter::Import` にまとめた**(テストできる): 使う拡張子だけをコピー、OBJ→MTL→テクスチャの参照をたどる(MTLのオプション付き `bump -bm 1 file` にも対応: 残り全部と、最後の1語、の2つを候補にして、存在する方を採る)、FBX→同じフォルダの画像と `Textures/`、同名は `_2`、合計の上限1GB、Incoming の中の物は取り込まない、など。
- **Windowsの文字コードの落とし穴**:
  - `std::filesystem::path::string()` / `generic_string()` は、システムの文字コード(ANSI)で表せない文字(絵文字など)があると、**例外を投げる**。最初のテストで、絵文字の名前のファイルを飛ばそうとして、警告の文字列を作る時に例外が出て、**プロセスが即死**した(終了コード `0xC0000409`)。→ 表示用・キー用には `u8string()` / `generic_u8string()`(UTF-8。例外にならない)、拡張子の判定はワイド文字から作る。
  - ファイルの中の参照(MTLの `map_Kd` など)を書き換えられないので、**ANSIで表せない名前のファイルは取り込まず**、理由を報告する(`WideCharToMultiByte` の `lpUsedDefaultChar` で判定)。
  - フォルダ名は、使える文字に直す(日本語だけの名前は `Imported`)。
- **UIPI**: ゲームを管理者として実行していると、通常の権限のエクスプローラーからのドロップは、Windowsに拒否される。
- **ポップアップが1フレームで閉じる問題(ImGuiのドッキング)**: 取り込み結果を出す「モーダルポップアップ」が、開いた直後に閉じてしまった。原因は、同じフレームに「Assetsを前面に出す(`SetNextWindowFocus`)」を出していたこと。ドッキングのタブの切り替えが数フレームかけて落ち着く間、親のウィンドウへのフォーカスが繰り返され、**親にフォーカスが移るたびに、子のポップアップが閉じられる**(ImGuiの `ClosePopupsOverWindow` の仕様)。→ 前面に出してから**3フレーム待って**からポップアップを開くようにした。

## 3. 起きた問題と直し方(まとめ)

| 問題 | 原因 | 直し方 |
|---|---|---|
| Assets を開くとゲームが固まる | ルートの節のImGui IDが空で `IM_ASSERT` が発動し、Debugのアサートのダイアログが、見えない所で待っていた | ラベルに `###dir:` を付ける。**固まった時は、別スレッドの見張りで、メインスレッドのスタックを取る**と原因が分かる(今回は一時的な診断コードで取った) |
| 右クリックメニューが何重にも出る | 節ごとに同じ文字列IDのポップアップを開いていた | `BeginPopupContextItem(nullptr)` |
| 取り込みの絵文字の名前で即死 | `path::string()` が例外 | `u8string()` を使う |
| ポップアップが1フレームで閉じる | 親へのフォーカスの繰り返し | 前面に出した3フレーム後に開く |
| ヒットがミスより遅い(計測) | 1回きりの計測の揺れ | ウォームアップ+平均 |
| 境界の値が壊れても検出できない | チェックサムの範囲が狭かった | ヘッダーも対象にした |
| 画面の保存に、他のウィンドウが写った | PowerShellの画面全体の撮影(高DPI) | 自分のバックバッファを直接保存する診断コード(他のウィンドウは写らない) |
| 診断のクリックが効かない・勝手に動く | 本物のマウス・キーボード(`GetAsyncKeyState` は、フォーカスが無くても拾う)と混ざる | 診断中は、ImGuiへの入力を、バックエンドの更新の後に上書きする。完全には防げないので、**複数回、同じ結果になることを確かめる** |

## 4. 確認した方法
- **単体テスト(スクラッチ。全て通った)**:
  - `AssetCatalog`: 木・空フォルダ・モデルの数・フォルダの絞り込み・権限・パスの安全・名前の検証・作成・名前の変更(大文字小文字だけの変更を含む)・移動(拒否の条件を全て)・使用中の判定。
  - `BakedModelCache`: 往復で完全一致・65536超(4バイトのインデックス)・-0/NaN・壊れ方21種類(+全バイトの破壊)・ファイル単位(ミス→ヒット、OBJ/更新日時/MTLの変化、壊れたキャッシュ、テクスチャ消失、無効化、保存先が使えない、存在しないモデル)・実モデルでの時間とサイズ。
  - `ScenarioFile`(飾り): 往復・再保存で一致・古いセーブ・不正な項目(絶対パス・`..`・欠落・型違い)だけを飛ばす・配列でない。
  - `ComputePropPlacement`: 倍率・位置・大きさ0。
  - `AssetImporter`: フォルダ/OBJ+MTL+テクスチャ/FBX/複数ファイル/混在/上限/Incomingの中/対象外/無いパス/空フォルダ/文字コード/日本語のフォルダ名。
  - `EditorSettings` / `ShortcutTable`(前の資料)。
- **ゲーム本体**(診断コードで、シーン切り替え・マウス・クリック・文字入力を再現して、バックバッファを保存): Assetsの木と一覧、ビューワーの一括読み込み(41モデル・64の上限警告)と札、ゴーストと配置、F5/F9相当の保存・復元、`WM_DROPFILES` を自分のウィンドウへ送っての取り込み(結果のウィンドウつき)、フォルダの作成(右クリック→ポップアップ→入力→Enter)。診断コードは、確認後に全て削除した。

## 5. 落とし穴チェックリスト
- ImGuiのID: ウィンドウ直下に空のIDを作らない。ツリーの節など、繰り返す物のポップアップは、項目のIDから作る。
- 描画中に、描いている配列を作り直さない(操作は、描画の後)。
- ドッキングのウィンドウへのフォーカスは、子のポップアップを閉じる。
- `std::filesystem::path` を `std::string` にする時は、例外に注意(UTF-8版を使う)。
- 外から来るファイル(キャッシュ・セーブ・ドロップ)は、全ての数値の範囲・大きさ・パスを確かめる。
- キャッシュの版(`kVersion`)の上げ忘れ。
- 計測は、ウォームアップして、複数回の平均で。
