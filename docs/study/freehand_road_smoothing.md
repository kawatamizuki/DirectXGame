# 自由描きの道路をきれいにする(均し+等間隔化+継ぎ目の整え)

## 何が問題だったか
自由描き(Curve)の道路が、ガタガタに見えた。原因は3つ重なっていた。

1. **入力が不規則**: マウスの点は、手ぶれを含み、間隔も不揃い(約0.3の短い区間が、たくさん)。短い区間は、少しの揺れでも向きが大きく変わる。
2. **継ぎ目のキャップ**: 区間のつなぎ目に敷く「四角いキャップ」は、軸に平行な正方形。曲がった縁から、角が飛び出して見えた。
3. **ミターの長さ**: 継ぎ目で縁をつなぐ「ミター(角の斜め線)」の長さを一定にしていたので、曲がるほど道幅が細くなり、外側にすき間が出た(キャップで隠していた)。

## 使った考え方・用語
- **ガウス平滑化(Gaussian smoothing)**: 各点を、近くの点の「重み付き平均」に置き換える。重みは、近いほど大きい(ガウス分布)。`sigma` が大きいほど、広い範囲で均す。手ぶれ(細かい揺れ)だけが消え、大きな曲がりは残る。
- **等間隔の取り直し(resampling)**: 線を弧の長さで測り、同じ間隔で点を取り直す。区間の長さが揃うので、曲がりが均一に見える。
- **端の処理**: 端の点は動かさない(描き始め・終わりの位置がずれると、道路の接続や費用が変わる)。端の外側は、端を中心に「点対称」に折り返して補う。こうすると、端の近くで線が縮まない(ただ端を繰り返すと、端が内側へ引き寄せられる)。
- **ミター(miter)**: 2本の線がつながる所の、縁の交点。向きの変化の半分の角を θ とすると、ミターの長さは `道幅の半分 / cos θ` で、この補正をして初めて、道幅が一定に見える。急な角で無限に伸びないよう、1.6倍で打ち切る。
- **共有する縁**: ミターで継いだ所は、隣の区間と縁の頂点が同じ位置になる。だから、キャップが要らない(=四角い角が出ない)。

## 実装の流れ
`CurveRoadPlacementStrategy`(点の間引き・EMA) → `RoadSystem::GetEffectiveCurvePendingSegments()` で **`SmoothAndResample`**(新規 `Field/CurveSmoothing.*`) → 区間 → `BuildRoadMeshVertices`(ミターの長さ補正・ミターした継ぎ目はキャップを敷かない)。

プレビュー・有効判定・費用・確定が、全て `GetEffectiveCurvePendingSegments()` を使うので、**見えている線と、実際に敷かれる道路が、一致する**(ここ1か所を直しただけで、全部に反映された)。

## パラメータ(`RoadSystem.cpp`)
- `kCurveSmoothingSigmaLegacyCells = 0.8` / `kCurveSegmentSpacingLegacyCells = 0.8`: 「旧スケール(1マス=1.0)のマス数」で持ち、`WorldScale::FromLegacy` で、今のスケールへ。世界の大きさ(`kCellSize`)を変えても、見た目が変わらない。
- 大きくすると、よりなめらか(ただし、描いた線から離れる)。

## 見つけた問題と直し方
- **テストの添字ミス**: 道幅を測るのに、頂点の添字を間違えて、「ミターが1.3倍に広がっている」と誤判定した(本当は正しかった)。頂点の並び(`v0 v1 v2, v0 v2 v3`)を、コメントに書いて、`v3` ではなく `v5`(同じ位置の2つ目)を使った。
- **「均一」の検査が厳しすぎた**: 弧の長さは均一でも、曲がった所の「弦(直線の距離)」は、わずかに短い。許容を持たせた。
- **確認の方法**: 新しい頂点の並びを、テスト内で上から塗って BMP にし、「揺れた線」と「均した線」を並べて目で見た(ゲームの実ウィンドウは操作しない)。

## 検証
`curve_test`(スクラッチ): 端の扱い・直線のまま・粗さ(約9分の1)・円弧の半径が保たれる・sigma=0・継ぎ目の縁の一致・道幅が保たれる・Straight のキャップは従来どおり。
