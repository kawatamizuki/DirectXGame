# タイトル画面(勉強資料)

2026-10-25。シンプルなタイトル画面(背景の街・スタート・終了)のまとめ。実装は `UI/TitleMenu.{h,cpp}`、`Core/Game.cpp`(`UpdateTitle`・`Draw`)。

## 1. 作ったもの
背景に初期マップの街、スタートと終了のボタン、タイトルの板。カメラが街のまわりをゆっくり回る。

## 2. 設計
- **メニューは、ゲーム内メニューと同じ作り**: `TitleMenu`は、配置(`ComputeLayout`。文字の幅を測らない)・入力(ホバー・クリック)・描画(`IUISkin`経由)だけを持つ。押された結果は`TitleCommand`(Start / Quit)で返し、実際の処理は`Game`がつなぐ。だから、描画の準備(D3D)無しで、配置と操作を単体テストできた。
- **背景の街は、`Game`が出す**: シーン(`TitleScene`)は、UIRenderer・カメラ・スキンに触れない作りなので、タイトル画面の更新と描画は、`Game`の中に置いた(`UpdateTitle`)。`TitleScene`は、ほぼ空(以前の「どこをクリックしても始まる」処理は削除)。
- **街の更新はしない**: 住民・需要の更新は、ゲームシーンの間だけなので、背景は静止した街。動くのは、カメラと昼夜の光(ゲーム内時計は常に進む)だけ。
- **カメラ**: 街の建物・道路の端が入る四角の中心を、見る点にする。そこから一番遠い点までの距離から、カメラの距離を決める。見下ろす角度は固定(約35度)で、向きだけが一定の速さで回る。街が変わっても(初期マップを差し替えても)、自動で中心に収まる。
- **終了**: ウィンドウに`WM_CLOSE`を送る(`PostMessage`)。`Window`が終了の処理(`WM_DESTROY`→`PostQuitMessage`)を行うので、`exit`などで強制終了せず、後片付けも通常どおり行われる。

## 3. 確認した方法
- **単体テスト**(スクラッチ。全て通った): 7通りの画面の大きさで、ボタンが画面の内側・横の中心にあり、重ならない。タイトルの板とボタンが重ならない(低すぎる画面を除く)。ホバーだけでは命令が出ない。ボタンの外のクリックでは始まらない。ImGuiの上では反応しない。
- **ゲーム本体**(診断用の一時コード。削除済み): ボタンを押した状態を再現して、スタートでゲームシーンへ移ること、終了で約1秒後にウィンドウが閉じること(強制終了の保険が働かないこと)、背景の街とボタンの見た目を、画面を保存して確認した。

## 4. 見つけた問題
| 問題 | 原因 | 直し方 |
|---|---|---|
| ボタンが、背景の街の真上に重なった | 街の中心が画面の中央に来るのに、ボタンも中央(画面の高さの52%)に置いた | ボタンを下(68%)に下げた。街がタイトルの板とボタンの間に収まる |
| 低い画面で、ボタンが下にはみ出した(単体テストで発見) | 位置を割合で決めて、高さの足りない画面を考えていなかった | はみ出す時は、ボタンを上へ寄せる |
| 画面に、街が小さく映った | カメラの距離を、街の広がりの2.6倍にしていた | 倍率を調整して、タイトルの板とボタンの間に収めた |

## 5. 今は、やらないこと(割り切り)
- ゲームのタイトルは文字だけ(`kDefaultTitle`。名前が決まったら変える)。ロゴ画像も未対応(スキンの差し替えと同じ仕組みで、後から画像にできる)。
- 「続きから」「設定」などのボタン、キー(矢印)での選択。
- タイトル画面の音楽・切り替えの演出。
- エディタのパネルを、一括で隠す機能(タイトル画面にも、エディタのパネルが映る。必要なら、後で足せる)。
