# 利用履歴と立ち寄り(P1)

2026-10-29。仕様書「住民行動と商店街の簡易試作仕様書」の **P1**(利用履歴・立ち寄り)を実装した。数値は全て仮(`Simulation/ResidentSimSettings.h`、City Stats > Settings で実行中に変えられる)。

## 1. 用語
- **主目的**: 外出を決めた時に選んだ施設(P0)。
- **立ち寄り**: 主目的の施設を使い終わった後、帰る前に、近くの別の施設に寄ること。
- **履歴(history)**: 住民が最近使った施設の記録(新しい順、最大8件)。P0から持っていたが、選択には使っていなかった。
- **重みの倍率(repeatFactor)**: 施設の選択の重みにかける係数。直近に同じ施設を使っていると、1未満になる。
- **食事系(foodLike)**: カフェなど。同じ外出で、食事系を使った後に、別の食事系へ寄るのを抑える印。

## 2. 同じ施設への連続利用を抑える(重みの倍率)
- 直近 `repeatVisitWindow`(3)回の履歴を見て、同じ施設があれば、重みに倍率をかける。
  - 直前の利用 = `repeatVisitWeightFactor`(0.5)。古いほど1に近づく(線形)。複数あれば、一番下がる物。
  - 例: 同条件の映画館が2つ、直前に#10を使った → #10:#11 = 0.5:1 → #10は約33%(0%にはならない)。
- **完全には禁止しない**: 重みの下限(`minimumWeight`)は守る。候補が1つしか無ければ、履歴があっても、その施設を選ぶ。
- **必要な日用品は妨げない**: 不足による日用品の外出(`needDriven && Daily`)では、下げ幅を `needDrivenDailyRepeatStrength`(0.25)に弱める(0.5 → 0.875)。コンビニしか無い住民が、不足なのに行けなくなることを避ける。
- `ComputeFacilityWeight`(品質・値段・適性・距離)は変えず、`ChooseFacility` の中で倍率を掛けた。デバッグには、`CandidateEvaluation::repeatFactor` を足し、City Stats の Decisions に「repeat x」列を出す。

## 3. 立ち寄り
### 流れ
1. 施設の利用が終わった時(`FinishVisit`)に、売上・回復を反映した後、`TryStartStopover` を呼ぶ。
2. `CanConsiderStopover`(立ち寄りの回数の上限・時刻・体力・帰る家が有るか)を満たし、確率 `ComputeStopoverChance`(基本0.25 × 0.4^今までの立ち寄り回数)に当たった時だけ、先へ進む(外出の判定の確率より低く、回数で下がる)。
3. 目的を決める(`ChoosePurpose`。不足が有ればその需要。無ければ自発的)。候補は、目的のカテゴリの、他の施設。
4. 各候補に、今いる施設からの経路(行き)と、立ち寄り先から家への経路(帰り)を作る。行きが範囲(`stopoverMaxDistanceLegacyCells` 8マス)を超える物は「範囲外」。体力は **行き + 帰りの合計** で判定する(帰れなくなる立ち寄りをしない)。
5. `ChooseFacility`(P0と同じ重み付き抽選)で選ぶ。今回の外出で使った施設(履歴の先頭から、`outingStopCount+1` 件)は「今回使用済み」として外す。
6. **食事系の連続**: 選ばれたのが食事系で、今回の外出で食事系を使っていたら、`foodChainAcceptChance`(0.2)の確率でだけ、実際に寄る(外れたら、寄らずに帰る)。
7. 寄るなら、経路「今いる施設 → 立ち寄り先」で歩き始める。立ち寄り先で利用が終われば、また 1. から(回数が増えるので、確率は下がる)。

### 立ち寄りの経路の持ち方
住民の経路(`waypoints`)は、これまで「自宅 → 施設」の1本で、帰りは逆向きに戻していた。立ち寄りでは、経路が **「前の施設 → 立ち寄り先」** になるので、次の点に気をつけた。
- 帰りは、必ず、立ち寄り先から家へ **新しく経路を作る**(`ReplanReturnRoute`)。逆向きに戻ると、家ではなく前の施設へ着いてしまう。
- `ReplanReturnRoute` は、元の経路より長いと「迂回」として体力・満足度を減らす。立ち寄りの後は、比べる経路が短いので、`applyDetourPenalty=false` にして判定しない。
- **行き先の施設が解体された**時(`AbortOutingToDemolishedFacility`): 立ち寄りへ歩いている途中なら、今の位置から家へ帰る経路を作る(`StartReturnFromHere`。位置は飛ばさない。道が無ければ立ち往生)。立ち寄り先の中なら、施設の位置から作り直す。立ち寄りの回数は、解体の処理の最初に控えてからリセットする(リセット後だと、立ち寄りだったと分からなくなるため)。
- 保存: `outingStopCount`・`usedFoodLike` は以前から保存していた。経路も `waypointsHomeToTarget` ごと保存しているので、立ち寄りの途中でも復元できる(経路の先頭が家である前提のコードは無い)。

## 4. 見つけた問題と直し方
- 立ち寄り先の候補の距離は、家からではなく、**今いる施設から**測る。`FacilityCandidate` に `walkLength`(行き + 帰りの合計)と `outOfRange` を足し、`pathLength` は距離の重み用(行きだけ)にした。体力の判定は `walkLength` があればそれを使い、無ければ従来どおり往復(2倍)。
- 立ち寄りで同じ施設に戻らないよう、`VisitedThisOuting` を足した。通常の施設選び(`visitsThisOuting=0`)では、履歴に有っても外さない(重みが下がるだけ)。

## 5. 確認したこと
- **単体テスト**(`p1_test`): 倍率(直前・古い・窓の外・複数・必要な日用品・設定0/1)、抽選の割合(33%付近、毎回は繰り返さない、候補1つなら必ず選ぶ)、立ち寄り候補の除外(使用済み・範囲外・到達不可・体力不足・往復の扱い)、確率(25% → 10% → 4%、20000回の試行で約25%、2回目は1/5未満)、条件(遅い時刻・体力・上限・家なし・設定で無効)、食事系(1/0.2/他は1)、従来の呼び出しと同じ結果。既存の `sim_test` も合格。
- **ゲーム内**(診断コード。確認後に削除。立ち寄りの確率を0.9に上げて、12倍速): コンビニ → 映画館 → カフェ → 帰宅、のように、1回の外出で最大2回寄り、同じ施設を2度使わない。位置の飛びは0回。立ち寄りの利用にも、回復・売上・集計が反映される。2つ目のカフェを置くと、食事系が続くので寄らなかった記録が出る。立ち寄り先の解体(歩いている途中・施設の中)で、位置を飛ばさずに家へ帰る。
