# P2-C1: 住民がエリアを目的に外出する(勉強メモ)

## 1. 何を作ったか
外出の理由「エリア」を実際に選べるようにした。理由が「エリア」なら、区画を重み付きの抽選で選び、その区画の所属施設の中から、いつもの施設選びで1軒決める。区画ごとの来訪・利用・売上は、`AreaLedger` に別々の数字で積み上げる。

## 2. 用語
- **重み付きの抽選(ルーレット選択)**: 重みの合計を1とみなして、乱数 [0,1) がどの区間に入るかで選ぶ。重みが0の候補は選ばれない。
- **頭打ち(飽和)**: 供給量 ÷ 上限を 1 で切る。店が増えても、効果が増え続けない。
- **同じ乱数で選び直す**: 「エリア」を引いたが、区画が無い時、乱数を引き直さず、重みから「エリア」を除いて、同じ乱数で選ぶ。乱数の消費回数が、状態に依らず、一定のまま(再現が壊れない)。
- **読み取り専用のインターフェイス(`IAreaSource`)**: 住民のシミュレーションが、区画の管理クラス全体に依存しないための、小さな窓口。
- **集計の主体の違い**: 「目的にした人数」(外出の意図)と「実際に使った人数」(結果)と「延べ利用」「売上」は、別の数字。同じ外出で同じ区画を2回数えない。

## 3. 使った技術
- 距離の重みを、施設の重みと区画の重みで、同じ関数(`ComputeDistanceFactor`)にした(評価を1か所に)。
- 区画の距離は、中心への直線距離ではなく、「使える所属施設までの、道路での道のり」。孤立した区画・道が繋がらない区画を、正しく不利にする。
- 区画の所属は、描画のフレームではなく、住民の判断の間隔で、`ComputeAreaMembers` から求める。
- 集計は、利用が起きた時点の所属で積み上げる(区画の移動・建物の解体で所属が変わっても、過去の数字が変わらない)。

## 4. 見つけた問題と、直し方
- 既定のエリア重みが0だった単体テストが、重み0.5で失敗 → テストを、「重み0なら選ばれない」「既定なら候補がある時だけ選ばれる」に分けた。
- 診断で、耐久試験が終わると世界が元に戻り、統計が消える → 終了前のフレームで書き出すよう、1フレームの持ち時間を小さくして、進める間に、毎フレーム書いた。
- PowerShell で、`-1.5` を関数に渡すと文字列になった(世界ファイルの位置が不正)→ 引数に型を付けた。

## 5. 確かめたこと(2026-11-09)
- 単体テスト 11/11(新規: 区画の抽選・理由の選び直し・集計)。
- 診断用の街(住民18・単独の店2軒・区画A(4軒)・区画B(2軒))で、12週・26週の耐久試験: 異常 0。決定論テスト: 指紋が一致。保存→読み込みの往復(区画を目的に外出の途中で保存): 続きの集計が一致。
- 区画の集計の合計 = 所属施設の施設別集計の合計(来訪・売上とも一致)。
- 未周知の区画: エリア目的の外出は 0、施設は、区画が無い街とほぼ同じ回数使われる。
