# テストマップ管理パネル(段階2)(勉強メモ)

## 1. 何を作ったか
- Editor に「テストマップ」パネルを追加した。手作業で作った街を、名前を付けて保存し、一覧から選んで読み込み、読み込む前の街へ戻せる。
- 保存・読み込みの規則は、画面に依存しない `TestMapStore`(段階1)と `TestMapSession`(今回)が持つ。パネル(`DebugTools/TestMapPanel`)は、その上の、薄い画面。

## 2. 用語
- **控え(original)**: テストマップを読み込む前の街を、メモリに写し取った物(セーブデータの文字列)。「元の街に戻す」で、これを読み込み直す。ファイルには書かない。
- **配置の指紋**: 道路・建物・青マス・飾り・商業エリアの形(位置・大きさ・周知の有無)だけのハッシュ。住民・時計・評判など、時間で変わる状態は含めない。「今の街が、読み込んだテストマップと、同じ配置か」を調べる。
- **初期状態の指紋**(段階1): 街の全体(時間で変わる状態も含む)のハッシュ。テストの実行条件の同一性に使う。

## 3. 動き
1. 保存: 「今の街を、新しいテストマップとして保存」。id(半角英数字)・表示名・説明・検証目的・注目する指標を入れる。保存先は、下書き(既定)か、正式。既存の名前は、上書きされない。
2. 読み込み: 一覧で選び、「読み込む…」→確認。最初の読み込みでは、今の街を、メモリに控える。読み込みに失敗しても、街は壊れない(既存のセーブと同じ検証が、街を消す前に、終わる)。控えも作らない。
3. 読み込んだ街は、通常どおり、建築・編集・時間進行できる。F5・メニューのセーブは、`Saves/` へ書く。`TestMaps/` へは、書けない(段階1の保護)。
4. 別のテストマップへ移っても、控えは、最初の街のまま。「元の街に戻す…」で、最初の街へ戻る(使用中の表示と、控えは、消える)。

## 4. 誤操作の防止
- 上書きの操作は、画面に存在しない(新規保存だけ。同じ名前は、断る)。
- 削除: idを打ち込まないと、押せない。正式マップは、Git管理のファイルである旨も出す。
- 読み込み・元の街に戻す・名前(id)変更・正式への採用・下書きへ戻す: 確認のダイアログつき。
- 「配置を変えています」の表示: 読み込んだ後に、建築・編集で配置を変えると、緑(同じ)から黄(変更あり)へ変わる。読み込む前の確認に、「その変更は、失われます」と出す。
- 耐久試験・乱数の再現・タイムラインが動いている間と、ゲームシーンの外では、街を入れ替える操作を無効にする。

## 5. 技術
- ロジックと画面を、分けた(`TestMapSession` は、ImGui を知らない)。そのため、控え・戻す・失敗時・配置の変更の検出を、ゲームを起動せずに、単体テストできる(`tests/sim_testmap_test.cpp`)。
- 街の入出力は、`std::function` で、外から渡す(`ScenarioManager::CaptureBytes` / `Load` / `LoadFromBytes` につなぐ)。テストでは、偽の入出力に差し替える。
- 「配置が変わったか」は、街を丸ごと書き出して指紋を取るので、重い。パネルは、1.5秒に1回だけ調べる。
- ImGui のポップアップ(`OpenPopup` → `BeginPopupModal`)は、同じ関数・同じ画面の階層で呼ぶ。開く合図(`m_openPopupRequest`)を、状態に持つ。

## 6. 確かめたこと
- 単体テスト: 配置の指紋(時計・評判が違っても同じ、建物・道路・周知の有無が違えば違う)、控え・戻す・失敗・使用中のテストマップの削除と名前変更、元のファイルが変わらないこと。
- 実際のゲームの部品(一時的な診断): 初期マップを保存 → 建築 → 別のテストマップを保存 → 読み込み → 配置が元と同じ(変更なし) → 読み込んだ街で建築(変更あり) → 通常のセーブは `Saves/` に成功、テストマップのファイルへの上書きは拒否 → 別のテストマップへ → 元の街へ戻す(配置が一致) → テストマップのファイルは、バイト単位で変わらない → 同じ名前の保存は拒否。

## 7. 見つけた問題と直し方
- 診断コードの文字列の中の、バックスラッシュが、ツールを通る間に、1本に潰れて、保存先のパスが変わった(診断の書き間違い。前回)。文字列の中のバックスラッシュを含む編集は、ファイルを直接書き出す方法に変えた。
- スクリプトで、ここ(終わりの改行)を足し忘れて、`}` と次の行が、同じ行に、くっついた(コンパイルは通る)。差分を見直して、気づいた。

## 8. 限界
- 既存の `imgui.ini` がある環境では、新しいパネルは、ドックされずに、浮いて現れる(「レイアウトを初期化」で、下のタブへ入る)。
- 読み込み時の街の入れ替えは、ゲームの描画を止めずに行う(既存のセーブ・ロードと同じ)。
- 実際の画面での、クリック操作(ボタン・ポップアップ・文字入力)は、まだ、実機で確かめていない(上の確認は、同じ部品を、プログラムから呼んだ物)。

## 9. 普段のクイックセーブの保護(追加対応)
- 問題: テストマップで遊んだ街のまま F5 を押すと、普段の街の `Saves/quicksave.json` を上書きしてしまう。
- 対策: テストマップ使用中は、クイックセーブの保存先を `Saves/quicksave_testmap.json` に切り替える(`TestMapSession::QuickSavePath`)。さらに、`ScenarioManager::SetBlockedSavePath` で、他の入口(Scenarioパネルなど)からの普段のクイックセーブへの保存も止める。ファイルの同一判定は `PathGuard`(大文字小文字・`..`・スラッシュ・末尾の空白/ドットでもすり抜けない)。
- 使用の終了: `ScenarioManager::LoadSerial`(ファイルからの読み込み回数)を毎フレーム見て、テストマップ以外のファイルを読み込んだ時に `EndSession` で使用を終える。メモリからの読み込み(元の街に戻す・巻き戻し・耐久試験)は数えない。
- 配置の比較の注意: 「配置が同じ」は形だけの比較で、街の全状態の比較ではない。画面にも明記した。
- 単体テスト: `QuickSavePath` の切り替え・`EndSession`・ブロック対象ファイルの同一判定(`tests/sim_testmap_test.cpp`)。
