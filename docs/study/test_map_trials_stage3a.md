# 学習メモ: テストマップの自動検証(段階3-A)

## 1. 何を作ったか
ゲームの中で作って保存した「テストマップ」から、住民のシミュレーションを、画面を描かずに何回も進める仕組み。
毎回、テストマップの原本から始めて、前の回の住民・時間を引き継がない。終わったら、実行前に遊んでいた街へ戻す。

## 2. 用語
| 用語 | 意味 |
|---|---|
| 試行(トライアル) | 原本から読み込んで、指定の週数を進める1回分 |
| 種(シード) | 乱数の列を決める数。同じ種なら、同じ乱数の列になる |
| 決定論(デターミニズム) | 同じ条件(原本・種・倍率・コード)なら、必ず同じ結果になる性質 |
| 指紋(ダイジェスト) | 起きたイベントと抽選を、順番どおりに混ぜた1つの数。2回の実行が同じだったかを、数1つで比べられる |
| ヘッドレス | 画面を描かずに、計算だけ進めること |
| 固定刻み | 1ステップの時間を、いつも同じ(1/60秒×倍率)にすること。PCの速さで、結果が変わらない |
| 往復(ラウンドトリップ) | 街を保存して、すぐ読み込むこと。完全に元通りになるのが理想 |
| xorshift32 | このゲームの乱数の作り方。速くて小さいが、種が近いと、最初のほうの乱数が似通う |
| ハッシュで混ぜる | 数を、掛け算とビットのずらしで、ばらばらな数に変えること |

## 3. 使った技術と、選んだ理由
### 3.1 既存の耐久試験を広げた(二重に作らない)
耐久試験(`SimEndurance`)には、「街をメモリに控える → 固定刻みで進める → 控えへ戻す」と「同じ所から2回進めて指紋を比べる」が、すでにあった。
新しいクラスを作らず、種類(`TestMapTrials`)を1つ足した。同じ進め方なので、耐久試験で確かめた性質(普段と同じ順番で進む・決定論)が、そのまま使える。

### 3.2 2つの控えを、別々に持つ
- 実行前の街(`m_baseBytes`): 終わったら戻す先
- 試行の原本(`m_trialBaseBytes`): 毎回、ここから始める

耐久試験は「今の街」が両方を兼ねていた。段階3では、テストマップの原本と、プレイ中の街が違うので、分けた。

### 3.3 試行ごとの種を、混ぜて作る
```cpp
inline uint32_t MakeTrialSeed(uint32_t baseSeed, uint32_t index)
{
    uint32_t h = baseSeed ^ (index * 0x9E3779B9u + 0x7F4A7C15u);
    h ^= h >> 16; h *= 0x85EBCA6Bu; h ^= h >> 13; h *= 0xC2B2AE35u; h ^= h >> 16;
    return h == 0 ? 1u : h;
}
```
種を 1, 2, 3 … のような連番のまま使うと、xorshift32 では、最初のほうの乱数が似通う。番号を混ぜて、ばらばらな種にする。
同じ基準の種なら、同じ並びになるので、後から同じ試行をやり直せる。

### 3.4 種を戻す順番
設定の種(`settings.seed`)は、「乱数の列」と「新しく生まれる住民の性格」の両方に使われる。
試行の間は試行の種に置き換え、終わったら**先に設定の種を戻してから**、実行前の街を読み込む。逆にすると、実行前の街で、これから生まれる住民の性格が、試行の種で決まってしまう。

### 3.5 決定論の判定は「同じ種の2回」だけ
違う種なら違う結果になる、とは限らない(住民がいない街なら、何も起きないので、同じ指紋になる)。
だから「違う種の指紋が違う」は合格の条件にしない。`EvaluateDeterminism` は、1回目と、同じ種の追加の1回だけを比べる。

## 4. 起きた問題と、直し方
| 問題 | 原因 | 直し方 |
|---|---|---|
| 耐久試験の最中に F5 を押すと、試験用の街が普段のクイックセーブに書き込まれる。F9 では、実行前の街の控えが失われる | 実行中のセーブ・ロードを、止めていなかった(以前から) | 実行中は、F5/F9・メニューのセーブ/ロードを断り、「Scenario」パネルを操作できなくした(`ImGui::BeginDisabled`) |
| 診断で、中止・F5の確認が、うまくいかなかった | 小さな街では、26週が0.1秒で終わり、F5を押す前に、もう終わっていた | 520週にして、実行中に操作が入るようにした |
| 実行の前後で、街の指紋が1回だけ違った | 住民の `visitHoursLeft` が -0.001。セーブの読み込みで、0未満を0にしている(以前からの丸め) | 違いの場所を、街のデータを書き出して比べて特定した。普段のF5→F9でも同じで、動きにはまず影響しないので、今回は直さない |
| `getenv` がビルドエラー | MSVC が、安全でない関数として、エラーにする設定 | 診断では `GetEnvironmentVariableA` を使った |

## 5. 確かめ方
- 単体テスト `tests/sim_trial_test.cpp`: 種(同じ入力なら同じ・5000通りが全て違う・0にならない)、種の並び、条件の検査、決定論の判定(違う種の一致・不一致は判定に使わない、途中で止まった回は比べない)。
- ゲームの中の診断(確認後に削除): 実行の前後で、街・時計・種・テストマップの使用状態・ファイルが同じか。中止、実行中のF5/F9、通常の耐久試験、倍率の違い。

## 6. 気をつけること
- 結果は**時計の倍率**にも左右される(同じ種でも、倍率5と20で指紋が違った)。倍率は、種と同じく、実行条件として残す。
- 異常の検出と指紋は、記録の仕組み(Editorのビルドだけ)を使う。Release版では、自動検証を始められない。
- 実行中に、建物を建てる・解体するなどの操作は、まだ止めていない(3-Bで止める)。
