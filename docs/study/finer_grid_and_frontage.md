# マスを4分割する・曲がった道の両脇に、きれいに青マスを並べる

## 1. 曲がった道の青マス(建物を置く格子)をきれいにする

### 何が問題だったか
自由描きの道は、短い区間(約0.8)の連なりでできている。以前は、区間ごとに「その区間の向きに揃った格子」を作って、道の両脇の列にマスを登録していた。
区間ごとに向き・原点が違うので、カーブでは、向きの違うマスが重なって捨てられたり、抜けたりして、青マスがバラバラに見えた。

### 考え方
- **区間単位ではなく、連なり全体(中心線の折れ線)で並べる。** 確定の時(`ConfirmPendingCurve`)に、全区間の確定が終わってから、まとめて1回登録する(`RoadSystem::ClaimOrientationAlongChain`)。
- **1つ1つのマスが、自分の向き・自分の原点を持つ。** マスは「原点+向き+ローカル番号」で表すので、ローカル番号(0,0)の1マスだけの小さな格子として登録できる。建物を置く時は、カーソルが載ったマスの向き・原点が使われる(`ComputePlacementFrame`)ので、そのマスにぴったり揃って建つ。
- **左右それぞれ、縁に接する列を、弧の長さに沿って「重ならない最小の間隔」で詰める。**
  - 縁を平行移動した線(オフセット曲線)を作り、その上に置く。角では、交点(ミター)へ(伸びすぎないよう上限1.5倍)。
  - 直線では、ちょうどマスの1辺おき(従来の1つの格子と同じ並び)。
  - カーブでは、前のマスと重なる間は、少しずつ先へずらす(`OrientedRectsOverlap`)。外側は、マスの扇の外側がわずかに開き、内側は、重ならない所まで間隔が広がる。
  - カーブの内側の列は、縁から少し離す(曲がった縁の弦の高さ = 長さ² / 8 / 半径)。そうしないと、曲がった道の縁が、マスの角に食い込む。
- 他の道路の路面に食い込むマス・既にあるマスと重なるマスは、登録しない(先着優先。従来どおり)。

### 純粋な関数に切り出した
`Field/FrontageCells.{h,cpp}`(`BuildFrontageCells`)。ゲームの状態を知らず、点列とマスの大きさだけで決まるので、単体テストできる(`frontage_test`)。
テスト: 直線で同じ向き・ちょうどcellSizeおき、道幅1.6で2列目、円弧・手ぶれ入りの線・きついカーブで重ならない・道に食い込まない、マスの大きさ0.5でも同じ形。

## 2. マスを4分割する(1マス → 2x2)

### ユーザーの要望
「今のグリッドを4分割にして、細かく道・建物を配置できるようにしたい」。

### 決めたこと(画面の上で、何を固定するか)
- **世界の広さ・建物の大きさ・道幅・住民の大きさ・カメラは変えない。** 変わるのは、「置ける位置の細かさ」だけ。
- 建物は、これまでと同じ大きさ。なので、占有するマスの数が増える(1x1 → 2x2、スーパー 2x1 → 4x2、映画館 2x2 → 4x4)。
- 道の建設費は、「長さあたり」の値段が変わらない(1マス=最初のマス1.0の長さあたり20円)。

### 実装
- `WorldScale.h` で、2つの大きさを分けた。**混ぜない。**
  - `kLengthUnit`(長さの基準): 道幅・建物・住民・速さ・カメラの大きさの基準。`FromLegacy(x)` は、これに連動する(今は1.0なので、値は変わらない)。
  - `kCellSize`(マスの細かさ) = `kLegacyCellSize / kSubdivision` = 0.5。マスの数は 20 → 40(世界は20x20のまま)。
  - 以前は、`FromLegacy` が「マスの大きさ」に連動していた。マスを変えると、道幅・住民まで一緒に変わってしまい、今回の意図(置ける位置だけ細かく)と合わない。
- `BuildingType.cpp`: 敷地の表は、「最初の1マス」単位で書き、`kSubdivision` をかけてマス数にした。
- `RoadType`: 値段の数え方に使う「1マスの長さ」は、`kRoadPriceCellLength`(最初のマス)。
- 道・建物に近い物を探す範囲(「2マス」)は、最初のマス基準(`FromLegacy`)のまま。`PropPlacer`(飾り)も、大きさの基準は、最初の1マス。
- **建物を置く位置**: これまでは、カーソルが載っているマスが、建物の角(最小角)だった。マスが細かいと、建物がカーソルから半分ずれるので、建物の中心がカーソルに一番近くなるマスを、角にした(1マスの建物では、これまでと同じ)。

### セーブの互換(古いセーブを、新しい格子で読む)
- セーブに `lengthUnit`(長さの基準)を足した。無い古いセーブは、「当時は、マスと長さの基準が同じ」なので、`cellSize` と同じとして扱う。
- 読み込み時に、2つを別々に変換する。
  1. 長さ(座標・大きさ・住民の速さなど): `kLengthUnit / 保存時のlengthUnit` 倍(今は1.0倍)。
  2. 格子(マス番号・マスの数): 保存時のマスの大きさを、今のマスの何倍かで割った整数 `f`(今は2)。
     - 建物の占有マス(開始番号・幅・奥行き)は `f` 倍。
     - 青マスは、1つが `f x f` 個の小さいマスに分かれる(優先順の位置は保つ)。
     - 座標・向きは変わらない(同じ場所を、細かい格子で数え直すだけ)。
  - 整数倍にならない時は、読み込まず、メッセージを出す。
- `RefineSnapshotGrid`(`WorldSnapshot.cpp`)。単体テスト(`snapscale_test`): 建物の番号・青マスの分割と順序・座標が変わらない・`lengthUnit` の保存/読み込み/無い/不正。

## 見つけた問題と直し方
- 建物がカーソルから半分ずれる → 最小角を、中心基準に変えた。
- `WorldScale::FromLegacy` を「マスの大きさ」に連動させたままだと、道幅・住民が半分になる → 長さの基準を、マスの細かさとは別の定数にした。
- ゲーム本体での確認: 診断コードで、初期マップ(古いセーブ形式)を読み込み(「2分割」の変換が走る)、自由描きの道を確定し、道の両脇に建物を置いて、画面を保存して目で確かめた(確認後、診断コードは全て削除)。

## 3. 追補(2026-10-28): 格子の位相をそろえる ─ 道路は「格子の交点」から引く

### 起きたこと
マスを細分化した後、(a) 新しく引いた道路の青マスが、既存の道路(初期マップなど)の青マスと、ずれて重なる・不揃いになる、(b) 道路を、従来の「マスの中心」から引けなくなった、(c) 初期マップで、青マスが道路の端から、はみ出して見える、が起きた。

### 原因: 格子の「位相」(線がどこを通るか)が、道路ごとにずれていた
- 道幅1.0は、細かい格子(0.5)の**2マスぶん**。中心線が、格子の線の上にあれば、道路の両端が、マスの境目にぴったり揃う。
- 道路の1点目は、「一番近いマスの**中心**」にスナップしていた。細かい格子の中心は、0.25・0.75…で、**最初のマス1.0の中心(0.5・1.5…)は、細かい格子の中心にならない**(線の上になる)。→ 従来の中心から、道路を引けなくなった。
- 青マスの格子は、「始点がマス(0,0)の中心」になる原点で作っていた。細かい格子では、この格子の線が、ワールドの格子・細分化して読んだ既存の青マスの格子から、**0.25ずれる**。道路ごとに位相が違うと、近くの青マスが重なって、先着優先で捨てられ、不揃いになる(道路を消して、引き直した所で、目立った)。
- 道路の端の延長は、マスの半分(0.25)に連動していて、青マス(最初のマス1.0の頃の半マス = 0.5)と、ずれていた。

### 直し方
- **1点目は、格子の交点(マスの1辺の整数倍の点)にスナップ**する。最初のマスの中心(0.5・1.5…)は、この交点の1つ。軸に揃った道路は、ワールドの格子と一致する。ホバーの四角は、道幅の四角を、点を中心に出す。
- **青マスの格子の原点を、始点そのもの(角)にした**(`ComputeChunkOrigin`)。中心を原点にする版は、曲線の道のマス1つ1つ用に、`ComputeOriginForCellCenter`として残した。細分化して読んだ既存の青マス(原点は、同じ格子の線の上)とも、ぴったり重なる。
- 青マスの列は、**道路の縁にぴったり接する列から、住宅が収まる厚み(2マス)**で並べる(以前は、道の縁とマスの間に、すき間があった)。曲線の道の青マス(`FrontageCells`)も、同じ厚み・縁に接する位置にそろえた。
- 道路の端の延長は、**道幅の半分(0.5。`WorldScale::kRoadEndExtension`)**に戻した(最初のマス1.0の頃と同じ。マスの細かさには、連動させない)。青マスの行も、この延長ぶんまで並べる。
- 道路を切り取った後に消す青マスの範囲を、青マスの厚みに合わせた。

### 確認
- ゲーム内: 道路を切り取った後に、格子の交点から、新しく直線の道を引くと、青マスが、既存の青マスと同じ格子の上で、道路の縁にぴったり接する。その脇に、住宅を置くと、道路の縁にぴったり接し、格子の線に揃う(footprintの原点が、0.5の倍数)。
- 単体テスト: `frontage_test`(縁に接する位置・厚み・重ならない・道路に食い込まない)。
