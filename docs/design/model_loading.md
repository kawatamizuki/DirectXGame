# モデル読み込みの設計(OBJ / FBX)

## 構成
```
Model::LoadFromFile(path)
   └ ModelLoaderRegistry::Default()      拡張子(.obj/.fbx、大文字小文字は区別しない)でローダーを選ぶ
        ├ ObjModelLoader  → 既存の ObjLoader(自作のパーサー)を包んだもの
        └ FbxModelLoader  → ufbx(External/ufbx)で読む
             ↓ どちらも ModelData(CPU側のメッシュ)を返す
Model::CreateFromModelData(data)         頂点バッファとテクスチャ(WIC)を作る
```
- 形式を増やす時は、`IModelLoader` を実装したクラスを作って `ModelLoaderRegistry::Default()` に1行登録するだけ。`Model` と描画側は変えない。
- `IModelLoader::LoadFromMemory` は、素材を exe に組み込んだ時にファイルを介さず読むための入口(FBX は対応済み。OBJ は未対応で、必要になったら足す)。

## FBX ローダー(`Graphics/FbxModelLoader`)
- **今は静的なモデルだけ**を読む(スケルトン・スキン・アニメーションは読まない。キャラクターを使う段階で追加する)。
- メッシュを持つ全ノードのワールド変換を頂点に焼き込んで、1つの頂点リスト(三角形リスト)にまとめる。四角形以上の面は三角形にする。
- ufbx で **右手系・Y上・単位メートル**に揃え(`ufbx_axes_right_handed_y_up`)、最後にエンジンの左手系へ変換する(下の「座標系の変換」)。UVのVは反転(OBJローダーと同じ約束)。法線が無いモデルは ufbx が面の向きから作る。
- ノードの変換が鏡像になる場合(行列式が負)は、三角形の頂点の順を入れ替えて向きを直す。
- **テクスチャの探し方**(1枚だけ使う。最初に見つかった物):
  1. FBX が参照しているファイル(相対パス → 同じ名前でモデルと同じフォルダ → 同じ名前の画像を探索)
  2. **マテリアル名と同じ名前の画像**(SimplePoly City は FBX にテクスチャの参照が無く、`Textures/<マテリアル名>.png` が対応するため)
  3. モデルのファイル名と同じ名前の画像
  4. 上の名前に `_1` を付けた画像(乗り物のように、色違いが `Bus_1.png`、`Bus_2.png`… と番号付きの場合は最初の色違い)

  画像は、モデルのフォルダから親へ最大4階層さかのぼり、各階層の直下と `Textures/`(サブフォルダ `Textures/Vehicle/` も含む)から、大文字小文字を区別せずに探す。
- テクスチャが無い面は、マテリアルの基本色を頂点色にする(OBJ の `Kd` と同じ扱い)。複数のテクスチャを使うモデルは、最初の1枚だけを使い、警告を出す(`Material` が1枚しか持てないため)。
- FBX に埋め込まれたテクスチャは未対応(警告を出す)。

## 確認した内容(2026-10-20)
- SimplePoly City の FBX 99ファイルすべてを ufbx で読める。建物26棟・乗り物9種・小物23・自然15・道路17を、本物の `SimpleShader.hlsl` とテクスチャで描いて目で確認した(`Cache/Previews/SimplePolyCity/`。Git には入れない)。
- 読み込み時間は FBX が1ファイル2〜5ms程度で、OBJ(Kenney の建物)は14〜16ms程度。
- 壊れた入力(空・テキスト・ゼロ埋め・途中で切れた FBX・先頭を壊した FBX・存在しないファイル・未対応の拡張子)でも落ちず、`false` を返す。
- メモリから読んだ結果が、ファイルから読んだ結果と(頂点・テクスチャ名まで)完全に一致する。

## 既知の制限・注意
- **座標系の変換**(2026-10-20 実施): OBJ/FBX は右手系で作られているが、描画は左手系(`XMMatrixLookAtLH`)なので、そのまま使うと画面が鏡像になり、看板の文字が鏡文字になっていた。
  読み込み時に **エンジンの座標系(左手系・Y上・+Zが前方)へ変換**して返す(`ModelData::ConvertFromRightHanded`。Zを反転し、三角形の2番目と3番目の頂点を入れ替え、法線・バウンディングボックスも直す)。
  OBJ・FBX のローダーが、返す前に1回だけ呼ぶ。新しい形式のローダーを足す時も、右手系のデータなら同じ関数を呼ぶ。
  費用: 20,040頂点(SimplePolyの競技場)で約0.025ms、100万頂点でも約7.5ms。読み込み時の1回だけで、描画の毎フレームの負担は増えない。
  この変更で、Kenney の建物の正面は -Z から **+Z(前方)** に変わった(既存の保存マップの建物は、位置は同じで、扉の向きが180度反転して見える)。
- **モデルの正面の向きがパックで違う**: 変換後、Kenney の建物は正面が +Z、SimplePoly の建物は正面が -Z(ufbx で変換しても、パック自身の宣言が実際と食い違う)。
  SimplePoly の建物を使う時は、建物の定義に向きの補正値(例: 180度)を持たせて合わせる(未実装。使い始める時に行う)。
- パスは、システムの文字コード(ANSI)の文字列として扱う。日本語を含むパスでも、ファイルを自前で開いてから ufbx に渡すので問題ない。
