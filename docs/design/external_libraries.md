# 外部ライブラリ・素材を使っている理由

「なぜそれを選んだか」を忘れないための記録です。ライセンスの条件は [THIRD_PARTY_LICENSES.md](../../THIRD_PARTY_LICENSES.md) にあります。
選び直す時は、ここの「見直す条件」を見てください。

---

## ufbx(FBX の読み込み)— 2026-10-20 に導入、v0.23.1

**何のために**: アニメーション付きのモデル(キャラクターなど)と、FBX だけで配布されている素材(SimplePoly City など)を読むため。建物などの静的モデルは今まで通り OBJ(自作の `ObjLoader`)でも読める。

**選んだ理由**
1. **速い**。Blender 開発者 Aras Pranckevičius の比較(9ファイル・合計2GB、1スレッド、Ryzen 5950X)で、他のローダーより大幅に速い。
   (数値は第三者の計測で、大きいファイルでの比較。このゲームの小さいモデルでは差は出にくい。)

   | ローダー | 読み込み時間 | 実行ファイルの増加 |
   |---|---|---|
   | **ufbx** | **9.8秒** | 457KB |
   | OpenFBX | 26.7秒 | 312KB |
   | assimp | 33.9秒 | 1060KB |
   | FBX SDK(Autodesk 公式) | 869.9秒 | 4508KB |
2. **導入が軽い**。ソース2ファイル(`ufbx.h`、`ufbx.c`)を入れるだけ。外部の DLL・ビルドツールが要らない。
3. **FBX 専用**で、静的モデルもアニメーション(スケルトン・スキン・アニメーションカーブ)も読める。軸と単位の変換(cm→m など)もライブラリ側でできる。
4. **信頼性**: Blender 4.5 の新しい FBX インポーターが ufbx で作られている。作者は多数のファイルでのテストとファジングを公開している。
5. **ライセンスが緩い**: MIT と Unlicense(パブリックドメイン)から選べる。Unlicense を選べば、帰属表示も不要。企業への提出物に入れやすい。

**他を選ばなかった理由**
| 候補 | 選ばなかった理由 |
|---|---|
| assimp | 多形式対応で便利だが、FBX は ufbx の約3.5倍遅く、実行ファイルも大きい(1MB 超)。「FBX に特化したローダーが欲しい」という要望に合わない |
| OpenFBX | 実行ファイルは最小だが、読み込み速度が ufbx の約2.7倍遅い(上の表) |
| FBX SDK(Autodesk) | 極端に遅い、並列読み込みで落ちた(上の計測)、実行ファイルが大きい |
| 自作の FBX パーサー | FBX は構造が複雑(バイナリ・ASCII・版ごとの差・軸と単位・スキン・アニメーションなど)で、以前も断念している。得るものが少ない |
| FBX を OBJ に変換して使う | アニメーションが失われる。素材を増やすたびに変換の手間も出る |

**見直す条件**: FBX 以外の形式(glTF など)を多く使うようになったら、多形式に対応したローダーも検討する。ufbx 自身も OBJ を読める。

## Dear ImGui(デバッグ用のパネル)
- **理由**: 即時モードの GUI で、パネル・スライダー・ログ表示などを数行で作れる。デバッグ・調整用に最適で、DirectX11/Win32 用のバックエンドが付属している。MIT ライセンス。
- ゲームプレイ用の UI(上部のバーなど)には使っていない(独自描画の `UI/` を使う)。ImGui はあくまで開発用。
- **見直す条件**: 配布版でデバッグ UI を完全に外したくなったら、`ENABLE_EDITOR` で切り離す(今の構成で可能)。

## stb_truetype / stb_rect_pack / stb_textedit(Dear ImGui に同梱)
- **理由**: ゲームプレイ用 UI の文字描画(`UI/FontAtlas`)が、フォントのグリフ(文字の形)をビットマップにするために `stb_truetype` を使う。ImGui に同梱されている物をそのまま使うので、追加の導入が要らない。パブリックドメイン(MIT とのデュアル)。
- **見直す条件**: 文字の品質(縁取り・SDF など)をもっと上げたくなったら、別のフォント描画を検討する。

## DirectXTK の WICTextureLoader のみ
- **理由**: PNG などの画像を読んで Direct3D のテクスチャにする部分だけを使う。Windows 標準の WIC(画像デコーダー)を使うので、画像ライブラリを追加せずに済む。MIT ライセンス。
- DirectXTK の他の部分は使っていない(必要になるまで入れない)。

## miniaudio(音の再生)— 2026-10-26 に導入、v0.11.25
- **理由**: ヘッダー1つ(`External/miniaudio/miniaudio.h`)をプロジェクトに入れるだけで使える。Windows(WASAPI)で、WAV・MP3(・FLAC)の読み込みと再生ができる。ライセンスはパブリックドメイン(または MIT-0)で、表記の義務がない。ストリーミング(長い曲を少しずつ読む)も持っている。
- **使い方の方針**: 距離による減衰・音量の層・ミュートは、**自分のコード(`Audio/AudioSystem`)で計算**し、miniaudio には「最終的な大きさ」だけを渡す。miniaudio は `Audio/MiniaudioBackend` の中に閉じ込めて(`IAudioBackend` の裏側)、他のコードは miniaudio を知らない。ライブラリを替える時は、この1ファイルを書き直すだけで済む。
- **実装の取り込み**: `Audio/MiniaudioImpl.cpp` だけで `MINIAUDIO_IMPLEMENTATION` を定義する(書き出し・波形生成の機能は切って、ビルドを軽くしている)。
- **見直す条件**: OGG など、組み込みで読めない形式を使いたくなったら、デコーダーを追加する。3D音響(左右・前後の定位)が欲しくなったら、miniaudio の空間機能を使うか検討する(今は距離による大きさの変化だけ)。

## 自作しているもの(外部のライブラリを使っていない)
| 部分 | 理由 |
|---|---|
| OBJ/MTL ローダー(`Graphics/ObjLoader`) | 形式が単純で、必要な機能(頂点・UV・マテリアル・テクスチャ)が少ない。学習も兼ねている |
| JSON の読み書き(`Scenario/Json`) | セーブデータ用に、キー順の保持・数値の往復の一致・壊れた入力でも落ちない、を確実にしたかった。形式を差し替えられる設計(`ISnapshotFormat`)にしている |
| UI の描画(`UI/UIRenderer`) | ゲームらしい見た目を完全に制御するため。ImGui は開発用に限定 |

## 3Dモデルの素材

### Kenney(City Kit の Commercial / Suburban / Roads、Mini Characters、3D Road Tiles)
- **理由**: CC0(パブリックドメイン)で、商用・提出物への同梱に条件がない。**同じ作者の素材は画風とテクスチャ(`colormap.png`)が揃う**ので、シェーダーで見た目をそろえる作業が最小で済む。OBJ 形式がそのまま付いてくる。
- **注意**: パックごとにモデルの原点やスケールが違っても、`BuildController` が実測サイズから自動でマスに合わせて拡縮する。

### Quaternius(LowPoly Buildings Pack)
- **理由**: CC0。モジュラー式の建物で、色違い・パーツの組み合わせで店の種類を作れる。OBJ/FBX/Blend が付いてくる。

### SimplePoly City(TRiMA29、CGTrader の無料素材)
- **理由**: 店の種類が多い(パン屋、八百屋(Fruits Shop)、本屋、服屋、スーパー、ガソリンスタンドなど26棟)。専用の店がほぼ無料素材に無いので、ここから得る価値が大きい。
- **条件**: ダウンロードしたままの再配布は禁止。ゲームに組み込む場合は、独自の形式にして、エンドユーザーが元ファイルに触れない対策を取る。AI の学習には使えない。作者(TRiMA29)のクレジットを入れる。
  → 元ファイルは Git に入れない。提出時の扱いは、アセットを exe に組み込む方針と合わせて決める。

## 「使わない」と決めたもの
- **有料素材の購入**: 今は無料の素材だけで進める。画風が揃わない部分はシェーダーで調整する。
- **モデルの手動変換(Blender で FBX→OBJ)**: ufbx で直接読めるので不要。
