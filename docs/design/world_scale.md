# 世界の大きさ(マス目の大きさ)

2026-10-22。マス目が小さく、建物・住民が画面で小さく見えたので、**フィールド全体の広さ(緑の面積)と、その見え方は変えずに、マスを粗く(数を減らして大きく)した**。
> **【現在の状態(2026-10-22の最後)】 マスの大きさは「最初の状態」(`kCellSize`=1.0、20x20、カメラ14 / 4 / 40)に戻してある。** 建物を大きく見せる調整は、試行錯誤したが、ユーザーの狙いと合わず、**ゲームの基盤ができてから、あらためて調整する**ことにした(保留)。以下の§1〜§9は、定数を変えるだけで大きさを変えられる仕組みの説明と、試した経緯。数値の例は、試した時のもの。


## 1. 1か所で決める
`Field/WorldScale.h`:
- `kCellSize` = 2.0(最初は1.0)。1マスの一辺(ワールド単位)。
- `kFieldWidthCells` / `kFieldDepthCells` = 10(最初は20)。マスの数。
- **フィールドの広さ = マスの大きさ x マスの数 = 20**(最初と同じ)。マスを2倍にして、数を半分にした(2x2を1マスにした)。

大きさを変える時は、`kCellSize`と、マスの数を、**広さ(掛け算)が同じになるように**一緒に変える(広さを変える時は、カメラの距離も、下の比率で自動で付いてくる)。

## 2. 何が連動するか
| もの | 連動のしかた |
|---|---|
| 建物・飾り | 1マスに収まるよう、モデルの大きさから自動でスケールを計算している(`BuildController` / `PropPlacer`)ので、マスが2倍なら建物も2倍に大きく映る |
| 地面 | フィールドの実サイズに合わせて自動でスケールされる(広さが同じなので、見た目は同じ) |
| 道幅(Narrow / Normal / Large) | `WorldScale::FromLegacy(0.6 / 1.0 / 1.6)`。「マスが1.0だった頃の長さ」を、今のマスの大きさへ換算する |
| 住民の大きさ・速さ | 同じく`FromLegacy(0.5)`、`FromLegacy(2.0)`(1秒に2マス) |
| 建物と道路が「隣接している」とみなす距離 | `FromLegacy(1.5)`(`DemandSystem`) |
| 道路と建物の向き合わせの「近く」 | マスの2倍。`cellSize`をかけて使う(`RoadSystem` / `BuildController`) |
| 街づくりのカメラの距離 | **フィールドの幅の何倍か**で決める(`kCameraDefault/Min/MaxDistanceFieldRatio` = 0.7 / 0.2 / 2.0。幅20なら14 / 4 / 40で、最初のカメラと同じ)。マスの大きさ・数に関係なく、フィールド(緑の面積)の見え方が保たれる |
| 古いセーブ | 読み込み時に自動で変換される([save_load.md](save_load.md)) |

もともと多くの処理は、`cellSize`を基準に書いてあった(道路の吸着・占有・建設費・マーカーなど)ので、そこは何も変えていない。

## 3. 連動させなかったもの(理由)
- **フリーハンドの道路の手ぶれの許容(0.12)・最小の区間の長さ(0.3)**: マウスの動き(画面の上の距離)に関わる値で、街の大きさには関わらない。
- **道路や青マスの、地面からの高さのずらし(0.02など)**: 重なって、ちらつくのを避けるための小さい値。
- **カメラの描画の奥行き(ファー)**: 400に広げたまま(フィールドが大きくなっても欠けない余裕)。

## 4. 新しい長さを足す時
- 「マスの何倍」で決まる値は、`cellSize`をかけて使う(`m_field->GetCellSize()`)。
- マスを持たない部分(`Simulation/`など)で「ワールド単位の長さ」を決める時は、マスが1.0の時の値を決めて、`WorldScale::FromLegacy`を通す。
- 長さ・速さをセーブする時は、読み込みで`LoadContext::spaceScale`をかける。

## 5. 古いセーブの変換と、チュートリアルのマップ
- 古いセーブ(マスが1.0)は、座標を2倍にして読む。**マスの番号は変わらない**(1マスが、そのまま2倍のマスになる)ので、旧い20x20のうち、中心の10x10に収まる街は、そのまま収まる。チュートリアルのマップは、旧い座標で、約7マス四方なので収まる(位置の平行移動は不要)。
- 10x10(旧い座標で-5〜+4マス)より外にあった建物・道路は、フィールドの外に出る(読み込み時の範囲チェックは、まだ無い)。

## 6. 経緯: 失敗した2回(2026-10-22)
1. **マスだけ大きくして、フィールドも、カメラも、一緒に大きくした**(マスを2.0→3.0→6.0にし、カメラの距離を「マスの何倍」で決めた): フィールド全体も大きくなり、カメラも引いたので、画面の見た目が変わらなかった(マスの数が減っただけに見えた)。
2. **マスを6.0・フィールド8x8にして、カメラは「フィールドの幅の1.5倍」まで引けるようにした**: 一番引くと、フィールドが画面の半分ほどになり、緑の面積が小さくなった。
→ ユーザーの意図は、「**緑の面積(フィールド全体の見え方)は、そのままで、マスを減らす**」。今の形(広さ20のまま、マス2.0x10)が、それ。

## 7. 確認したこと
- 変換の単体テスト(道路・建物・占有範囲・青マス・飾りが倍になり、マスの番号・マスの数・角度は変わらない。2倍して0.5倍で元に戻る。0以下・NaNの倍率は何もしない。`cellSize`の往復・古いセーブ・不正な値)。
- ゲーム本体(診断用の一時コードで確認し、削除済み): 最初の画面で、緑の面積と、カメラ(14 / 4 / 40)が最初と同じで、マスは10x10(最初は20x20)、建物は約2倍の大きさに映る。チュートリアルのマップは、位置を変えずに読めて、道路・建物がマスに揃う。新しく置いた建物もマスに揃う。

## 8. 3回目の失敗と、元に戻した(2026-10-22)
マス2.0・10x10(広さ20のまま。カメラは元と同じ比率)にしたが、ユーザーから「変わってない」「全然方向性が違う」と言われた。ユーザーが画面で見ていたのは、遠くから見たフィールド全体(緑の面積は画面の半分ほど)で、狙いと合わなかった可能性が高い(ホイールで引いた状態だった可能性)。**何を固定し、何を変えたいのか(緑の面積・カメラ・建物の大きさ・マスの数)を、ユーザーの図で確認するまで、最初の大きさに戻した。**

## 9. 最終的な形(2026-10-22): マスを大きくして、カメラの最初の距離は変えない
ユーザーの図(白線で「1マス」=いまの四角2x2を示した)と、「引いたときとか関係なくそもそも大きくしたい」「マス目の数はそのままに、2x2より大きくしてみる」を受けて、**マスの数は20x20のまま、1マスを3.0にした**。
- 世界は60x60になる。建物・住民・道幅は、マスに合わせて3倍になる。
- カメラの最初の距離(14)・一番寄る距離(4)は、絶対の値で、元のまま。だから、起動直後の見え方で、建物が約3倍に映る(見えるマスの数は減る)。
- 一番引く距離は、フィールドの幅の2倍(120)。引けば、全体が見える。
- 古いセーブは、座標を3倍にして読む(マスの番号は同じ)。チュートリアルのマップは、位置を変えずに読める。
- 調整は、`Field/WorldScale.h`の`kCellSize`(今3.0)だけ。もっと大きく・小さくしたい時は、この値を変える。

## 10. 保留(2026-10-22の最後)
§9の形(マス3.0・20x20)も、ユーザーから「見え方が変わらない」と言われた。何を固定し、何を変えたいのか(緑の面積・カメラ・建物の大きさ・マスの数)が、まだユーザー自身の中でも固まっていない、ということで、**元の状態(マス1.0・20x20)に戻して、保留にした**。ゲームの基盤(収入・需要・施設など)ができた後に、実際の遊び心地を見ながら、あらためて決める。
- 再開する時は、まず「画面の上で、何を固定するか」を、ユーザーの図で確かめる。
- 試したい大きさは、`Field/WorldScale.h`の`kCellSize`と、マスの数だけで変えられる(仕組みは、そのまま残してある)。
