# 音(BGM・効果音)の設計

2026-10-26。音の仕組みの設計と、決めたこと。実装の状況は、「進み具合」(§8)を参照。勉強資料は [docs/study/audio.md](../study/audio.md)。

## 1. 要望
- 音量の調整: **マスター**(全体)、**BGM・SEの種類ごと**、**音ごと**。
- **距離**によって、音が小さくなる・聞こえなくなる。
- **特定のタイミングで、ピンポイントに、ミュート**する(BGM全部・特定の効果音・同じタグの効果音)。
- ファイルは **wav と mp3**。
- 後から、エディタで音を読み込んで整理する機能(音の一覧・試聴・音ごとの設定)。

## 2. 決めたこと
- **ライブラリは miniaudio**(単一のソース。パブリックドメインか MIT-0。wav・flac・mp3を内蔵。Windowsは、標準の音の仕組みを使う)。検討した代案(XAudio2の自作寄り、SoLoud、DirectXTK Audio、OpenAL Soft、FMOD)との比較は、会話で行い、「全ての要望が、少ない作業で、揃う」ことから決めた。
- **距離の計算は、自前**(数行)。miniaudio は、「この大きさで鳴らす」だけに使う。ルール(距離・ミュート・音量の層)を、ライブラリ無しで、自動テストできるため。ライブラリを替えることも、簡単になる。
- **ogg は、標準では非対応**。素材は wav か mp3 にする。

## 3. 構造(3層)
```
ゲームのコード ──▶ AudioSystem ──▶ IAudioBackend ──▶ MiniaudioBackend(実際に鳴らす)
                     │                                 NullAudioBackend(何も鳴らさない代わり)
                     ├ SoundTable   音の表(Sounds/sounds.json)
                     └ AudioMixer   音量の層・ミュート
```
| ファイル | 役割 |
|---|---|
| `Audio/AudioTypes.h` | 種類(BGM/SE)、ミュートの対象(`MuteTarget`)などの型 |
| `Audio/SoundTable.*` | 音の表。1行=1つの音(id・ファイル・種類・タグ・音量・ループ・距離など)。壊れた行は飛ばして警告 |
| `Audio/AudioMixer.*` | 音量の層とミュートの要求。距離の関数(`DistanceGain`) |
| `Audio/IAudioBackend.h` | 実際に鳴らす部分の差し替え口と、何も鳴らさない代わり |
| `Audio/AudioSystem.*` | ゲームが使う窓口。鳴らす・BGMの切り替え・フェード・同時数の上限・距離とミュートの反映 |

## 4. 音の大きさの決め方
`最終の大きさ = マスター × 種類(BGM/SE)の音量 × 音ごとの音量 × ミュート × 距離による減衰 × フェード`
- 音ごとの音量は、0〜2(素材ごとの、元の大きさのばらつきをそろえる)。マスター・種類は、0〜1。
- **距離による減衰**(`spatial`が真の音だけ): 聞く位置(カメラ)から音の位置までの距離が、`minDistance`以下なら、そのまま。`maxDistance`以上で、聞こえない(0)。間は、直線的に小さくなる(`rolloff`が大きいほど、近いうちに急に小さくなる)。位置を渡さなかった音・`spatial`が偽の音(ボタン・BGM)は、距離に関係ない。カメラを引くほど、地上の音が小さくなる。
- 繰り返さない音が、遠すぎて聞こえないなら、鳴らし始めない。繰り返す音(環境音)は、遠くても鳴り始め、近づくと聞こえる。

## 5. ミュート
- **ゲームの都合のミュート**: `AddMute(対象, 秒数)`。対象は、全て・種類・特定の音(id)・タグ。秒数を渡すと、自動で解除される(0なら、`RemoveMute`で解除するまで)。**同じ対象に、複数の要求が重なっても、全部解除されるまで、ミュートのまま**(別々の理由でミュートした時に、片方の解除で、音が戻らないように)。
- **ユーザーのミュート**: システム画面のスイッチ(マスター・種類ごと)。ゲームの都合のミュートとは、別に持つ(`ClearMutes`で消えない)。保存する想定。
- **なめらかな変化**: ミュート・解除で、音の大きさを、約0.08秒かけて変える(一瞬で変えると、「プツッ」というノイズが出る)。
- ミュート中の、繰り返さない効果音は、鳴らし始めない。繰り返す音(BGM)は、無音のまま鳴り続け、解除すると、途中から聞こえる。
- 空のタグは、どの音にも当たらない(誤って、全部が消えないように)。

## 6. BGM
- `PlayBgm(id, フェードイン, フェードアウト)`: 今の曲は、フェードアウトして止め、新しい曲を、フェードインで出す(クロスフェード)。同じ曲なら、やり直さない。`StopBgm(秒)`。
- 長い曲は、`stream`で、少しずつ読みながら鳴らす(メモリの節約)。

## 7. 音が出せない環境
音のデバイスが無い・初期化に失敗した場合も、ゲームは落ちない。`NullAudioBackend`(何も鳴らさない)になり、全ての呼び出しは、安全に無音で終わる。

## 9. 素材のライセンス
提出物・公開リポジトリに関わるので、**使う前に、商用・ポートフォリオでの使用、クレジット表記の要否を確認**する。国内の無料素材サイトは、サイトごとに規約が違うので、使う時に最新の規約を確認する。
今入っているBGM(`bgm_title.mp3`)はフリーBGM OpenTracks(旧DOVA-SYNDROME)、効果音(`ui_open.mp3`)は効果音ラボ(2026-10-28 に、両サイトの規約を確認。要約は `THIRD_PARTY_LICENSES.md`)。**効果音は、操作音として組み込むなら許可**。**BGMは、音源ファイルをそのままの形で配布できない条件がある**ため、配布用 zip には、パック(§14)にして入れる。どちらも、公開リポジトリには入れない(`.gitignore`)。BGMの作曲者(かずち)の追加条件は、制限を足すものではなかった。

## 10. ゲームへのつなぎ方(今の音)
音の表(`Sounds/sounds.json`)には2つ: `bgm_title`(BGM・ループ・ストリーミング・音量0.6)、`ui_open`(SE・タグ`ui`・音量0.8・同時3つまで)。

| いつ | 鳴らす物 | 場所 |
|---|---|---|
| タイトル画面が始まった | `bgm_title` を1.5秒かけて出す | `Game::UpdateTitle` |
| 「スタート」(ボタン / Enter) | `ui_open`。同時にタイトルを離れるので、曲は1秒かけて消す | `Game::UpdateTitle` |
| ゲーム内メニューが開いた(右下のボタンでも、Escでも) | `ui_open` | `Game::SyncMenuTimeScale`(閉→開の瞬間) |
| メニューの左のタブ(建築・情報・研究・システム)を切り替えた | `ui_open` | `Game::UpdateGameUI`(`HudResult::menuTabChanged`) |

鳴らさない物: 建物・道路・モードなどの項目の選択、「戻る」・閉じる、セーブ/ロード、タイトルの「終了」。
- 聞く位置は、毎フレーム、カメラの位置(`Game::Update` の最後で `SetListenerPosition`)。`AudioSystem::Update` には、**実時間**の経過を渡す(メニューでゲーム内の時間が止まっても、フェードは進む)。
- 音を鳴らすコードは、miniaudio を知らない(`AudioSystem` だけを使う)。`Game::Initialize` で `MiniaudioBackend` を渡し、初期化に失敗したら無音で続ける。

## 11. 検査で分かったこと
- 曲(ストリーミング)を、実時間より速く波形に書き出すと、miniaudio の読み込みが追いつかず、約2秒で無音になる。**実際の再生(実時間)では起きない**(10ミリ秒ずつ実時間で進めると、途切れず鳴ることを確認)。検査では、実時間のペースで進める。
- 音量が実質0(聞こえない大きさ)のときは、繰り返さない効果音は鳴らし始めない(設計どおり)。検査で、マスター音量を0にして効果音の鳴り始めを確かめようとして、鳴らない結果になった。0.002にして確認した。

## 12. オプション(プレイヤーの音量設定)
- ゲーム内メニューに、5つ目のタブ「**オプション**」。全体・BGM・効果音の3つを、**0〜100**で調整する。1行に、スライダー、「-5」「+5」ボタン、数字の欄。
- **数字の入力**: 数字の欄を押すと入力モード。数字キー(テンキー含む)で最大3桁 → Enterで決定(101以上は100に収める)、Esc・ほかの所を押す・タブを替える・メニューを閉じる、でやめる。ゲームの画面に文字入力の部品が無いので、押されたキーを `MenuInput` に集めて、`GameMenu` が入力中の文字を持つ。入力中は、Esc・右クリックでメニューを閉じない(`HandleMenuKeys` が見る)。
- **スライダー**: 押した所へ動き、つかんだ間は、カーソルが外へ出ても追う。つまみの両端は、スライダーの左右から「高さの半分」内側(`GameMenu::VolumeFromSliderX` と `IUISkin::DrawSlider` が同じ決まりを使う)。
- **命令の形**: `MenuCommand{ SetVolume, arg=チャンネル(全体/BGM/SE), value=0〜100 }`。`GameMenu` は音を知らない。`Game::ApplyMenuCommand` が、ミキサーへ反映する。
- **保存**: `Settings/audio.json`(`AudioSettings`。個人の設定なので、Gitに入れない)。変わっていたら、**マウスのボタンを離している・入力中でない時**に、1回だけ書く(つかんでいる間に毎フレーム書かない)。起動時に読んで、ミキサーへ反映。壊れた・足りない・範囲外の値は、既定値(100)・収めた値にして続ける。
- 1フレームの遅れ: スライダーの表示は、前の命令を反映した値(ミキサーの値)を見せる。

## 13. エディタの Audio パネル
- `DebugTools/AudioPanel`。音の一覧(`SoundTable`)を表で出し、**音ごとの音量を%(0〜200)で**、数字(+/-・入力)とスライダーで調整する。「Play / Stop」で試聴。上の段に、全体・BGM・効果音の音量(ゲーム内「オプション」と同じミキサーの値)とミュートの切り替え。
- 変えた値は、すぐ反映される(`AudioSystem` が毎フレーム、表の値から大きさを計算し直すため)。**「音の表に保存」を押すまで、`Sounds/sounds.json` は変わらない**。保存は、`SoundTable::SaveToFile`(既定値と同じ項目は書かない。0.8 を `0.800000011…` と書かないよう、3桁に丸める。一時ファイルに書いてから置き換える)。
- 開いていない間は、何も処理しない。

## 14. 音のパック(配布版に mp3 をそのまま入れない)
素材(BGM)の規約で、「音源のファイルを、そのままの形で、利用者が取り出して複製できる状態で配ってはいけない」。そこで、**配布する実行環境には、mp3・wav を入れず、`Sounds/sounds.pak` に入れる**。
- **形式**(`Audio/SoundPack.h`): `"GSPK"`・版・個数、各ファイルの見出し(名前=sounds.jsonの`file`と同じ文字列・大きさ・元のデータのハッシュ)、その後ろに、各ファイルのバイト列を、**名前から決まる鍵で、かき混ぜて(XOR。xorshift32)**並べる。暗号としての強さは無い。「ダブルクリックで mp3 として開ける・コピーできる」状態を避けるためのもの。
- **作る**: `tools/pack_sounds.ps1`(`sounds.json` の `file` を全部まとめる)。`tools/make_release_package.ps1` が、配布物の `Sounds/sounds.pak` を作り、**配布物に mp3・wav・ogg・flac が1つでも残っていたら、止まる**(入れ忘れの防止)。かき混ぜ方は、C++(`SoundPack::Scramble`)と PowerShell の中の C# が、完全に同じ(テストで、PowerShell が作ったパックを C++ が読み、元のファイルと一致することを確認)。
- **読む**: `Game::Initialize` が `AudioSystem::LoadPack("Sounds/sounds.pak")`。中の音を、`IAudioBackend::RegisterMemoryFile` で、メモリ上の「ファイル」として登録する。登録した名前の音は、ディスクのファイルより先に使われる。パックが無い(開発中)・壊れている時は、何もせず、普通のファイル(`Sounds/*.mp3`)から鳴らす。壊れたパックは、警告して続ける(中身のハッシュが合わない音だけ飛ばす)。
- **鳴らし方**(`MiniaudioBackend`): 短い音は、登録したデータを、miniaudio のリソース管理にそのまま渡す(全部デコード)。**長い曲(`stream`)は、miniaudio の「ストリーミング」がディスクのファイルしか扱えない**ため、メモリ上のデータを、デコーダー(エンジンと同じ形式・標本数で出す)から、少しずつ読む形(`ma_sound_init_from_data_source`)で鳴らす。ループも効く(曲の長さ0:55を超えて、続くことを確認)。
- **Gitには入れない**: パックも、元の素材そのもの(の形を変えたもの)なので、`.gitignore`(`Sounds/*.pak`)。開発者は、mp3 を `Sounds/` に置けば動く。
- **確認**: mp3 が1つも無い作業フォルダで、パックだけから、効果音とBGMが鳴ること。mp3 が無く、パックも無ければ、鳴らせないこと(ディスクから読んでいない証拠)。配布用 zip を別の場所に展開し(mp3 無し)、起動して、BGMが鳴っている状態になること。

## 15. 音を追加する手順
1. **素材の規約を確認する**(商用・ゲームへの組み込み・再配布の可否・クレジットの要否)。`THIRD_PARTY_LICENSES.md` の「音声」の表に、名前・取得元URL・規約の要約・確認日を書く。**音のファイルは、Gitに入れない**(`.gitignore` 済み)。
2. **ファイルを `Sounds/` に置く**(wav か mp3。ogg は未対応)。
3. **`Sounds/sounds.json` に1行足す**: `id`(コードから呼ぶ名前)、`file`(`Sounds/xxx.mp3`)、`category`(`Se` か `Bgm`)、`tag`(まとめてミュートしたい時のグループ名。任意)、`volume`(音ごとの音量。素材の大きさをそろえる。1が元のまま、最大2)。曲・環境音は `loop: true`、長い曲は `stream: true`。位置で小さくしたい音(街の中の音)は `spatial: true` と `minDistance` / `maxDistance`(`rolloff` は任意)。
4. **コードから鳴らす**: 効果音は `m_audio.PlaySe("id")`(位置を持つ音は `PlaySe("id", &position)`)、曲は `m_audio.PlayBgm("id", フェードイン秒, フェードアウト秒)`。止める時は `StopBgm`。
5. **音量を調整する**: Editor の「Audio」パネルで、音ごとの音量を数字で変えて試し聴き → 「音の表に保存」(`sounds.json` に書き戻る)。プレイヤーの設定(全体・BGM・効果音)は、ゲーム内「オプション」。
6. **配布する時**: 何もしなくてよい。`tools/make_release_package.ps1` が、`sounds.json` に書いてある音を、全部 `Sounds/sounds.pak` にまとめて入れる(mp3は入らない)。`sounds.json` に書いたのに、ファイルが無いと、パックの作成が止まる。
- 今は、エディタに「音を追加する」「ファイルを読み込む」機能は無い(上の 2〜3 は、手で行う)。バックログ。
