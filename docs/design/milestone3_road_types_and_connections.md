# Milestone 3: 道路タイプ・建物-道路の接続点・T字路分岐

実装日: 2026-09-10

## 目的

プレイテストとChatGPTとの検討で固まった方針(建物はグリッド固定/道路は自由配置/斜め道路の土地効率低下はトレードオフとして残す/建物-道路は道路上の最近接点で明確に接続する)に基づき、「道路タイプ」「建物-道路の接続点(入口)」「T字路分岐」の3つを実装した。詳細な設計判断の経緯は`C:\Users\mizuk\.claude\plans\memoized-stargazing-bird.md`(このセッションで承認したプラン)を参照。

## 実装内容

### 道路タイプ
- `Field/RoadType.h/.cpp`: `Narrow`/`Normal`/`Large`の3種別と、それぞれの`width`(道幅)/`capacity`(交通容量の目安)/`cost`/`pedestrianFriendliness`(いずれも今回のロジックでは未使用、将来の経済システム・評価軸用のデータのみ)。
- `RoadSegment`に`RoadType type`を追加。`GameContext::roadType`(BuildパネルのUIで選択)を使って、道路確定時に`type`と`width`(見た目・占有判定に反映)を設定する。
- `BuildController`の「Build」パネルで、Roadツール選択中は建物種別の代わりに道路種別のラジオボタンを表示する。

### 道路配置のカーソル表示
- `RoadSystem::Draw()`で、Roadツール選択中のカーソル位置に丸マーカーを表示(緑=配置可能、赤=不可)。置きかけの区間がある場合は始点から現在位置までの区間全体で判定する。

### T字路分岐(道路の途中から伸ばす)
- `Simulation/RoadProximity.h/.cpp`: 点から道路区間上の最近接点を求める共通ユーティリティ(`FindNearestPointOnRoad`)。建物の接続判定と両方で使う。
- `RoadSystem::TryFindSnapPoint`を拡張し、①既存の端点への吸着(従来通り)→②既存区間の途中への吸着(新規)の優先順位で判定するようにした。
- `RoadSystem::SplitSegmentAt`を追加: 区間の途中に吸着した状態で道路が確定すると、その区間を2つに分割する。分割点は次回のグラフ構築で自動的に新しいノードとして扱われる。
- **既知の制約**: 新しい道路の始点・終点の両方が同じ既存区間の途中に吸着した場合、正しく分割されない(v1の割り切り。実際に発生する頻度は低い想定)。

### 建物-道路の明確な接続点
- `DemandSystem`内の`BuildingSnapshot`に接続情報(`hasRoadConnection`/`connectionPoint`/`nearestNode`)を追加。House/Officeそれぞれについて、道路上の最近接点を1回だけ計算して保持する。
- 接続判定のしきい値を、従来の「最寄りグラフノードまで3.0」から「道路区間そのものまで1.5」に変更。あいまいな距離しきい値ではなく、道路上の実際の最近接点を基準にすることで、新しい道路ができるたびに接続先が切り替わって見える曖昧さを減らした。
- 経路探索自体は引き続き、接続先の区間の近い方の端点(グラフノード)を起点/終点として行う(接続点自体は正確な最近接点を使うが、そこから先は簡略化)。
- House→Officeの割り当て条件に「両方が道路に接続していること」を追加。
- `DemandSystem::Draw()`で、道路に接続している建物から接続点までの短い線(入口/私道)を毎フレーム描画する。線が無い建物は道路に接続できていない。

## 検証項目

1. 「Build」パネルでRoadツールを選ぶと、建物種別の代わりにNarrow/Normal/Largeが選べること。選んだ種類によって道路の見た目の太さが変わること。
2. 道路配置中、カーソル位置に緑/赤の丸マーカーが出ること。
3. 既存の道路の**途中**をクリックして新しい道路を分岐できること(T字路)。分岐後、両側とも正しく道路として機能する(代表住民が通れる)こと。
4. House/Officeを道路のすぐ近く(隣接程度、目安1.5ユニット以内)に置くと、建物から道路への短い接続線(シアン色)が表示されること。離れすぎている場合は接続線が出ず、代表住民が通勤できずUnmet demandが増えること。
5. 代表住民が引き続き正しく通勤できること(既存の道路配置・混雑表示・Agent表示制御が壊れていないこと)。
6. 既存のBuildController(建物配置)・Editingモードの機能が壊れていないこと。
