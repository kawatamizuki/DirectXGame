# バックログ(先送りにした項目)

最終更新: 2026-10-22(ゲーム内メニュー対応時点)

会話の中で「後でやろう」「今回はやらない」と決めた項目を、忘れないようにここへ集約する。着手する時にこのファイルから削除(または「対応済み」節へ移動)する。優先順位は付けていない。関連する背景は[concept.md](concept.md)を参照。

## 道路まわり

- **道路幅の自動フィット**: 隙間の広さに応じて道路の幅を自動調整する(例: 基準幅1.0の道路が、狭い場所では0.9・交通容量-10%のような形で自動的に縮んで配置できる)。プレイヤーが手動で0.93のような細かい数値を操作するのは避け、ゲーム側が自動で行う想定。Milestone 3では見送り、種類ごとの固定幅のみ対応。占有判定も引き続き中心線ベース(道幅が広くても実際に塞ぐマスは変わらない)。
- **道路の拡張・アップグレード**: 既存の道路を後からより大きい種類に変更する。周囲に建物があれば拡張できない、または撤去が必要になる想定。経済システム(コスト消費)が前提になる。
- **建物を道路の角度に合わせて回転させる機能**: 三角形の余り地の角に建物を置いた時にはみ出さないようにする調整。建物がグリッド固定という前提を変える話なので別マイルストーンで扱う。
- **T字路分岐の既知の制約**: 新しい道路の始点・終点の両方が同じ既存区間の途中に吸着した場合、`RoadSystem::SplitSegmentAt`が正しく分割しない(Milestone 3のv1の割り切り)。

## 需要・人シミュレーションまわり

- **通勤以外の需要**: 買い物・観光・娯楽など、House→Office以外の需要フロー。Shop等は現状配置できるが需要ロジック未接続。
- **代表住民の帰宅・再割り当て**: 現状は職場に着いたらそこで完全に停止し、それ以降は何もしない。往復や離職・転職は未実装。
- **需要の奪い合い(施設間競合)の本格実装**: 現状はOfficeの雇用枠のみ。観光客の食事・宿泊・買い物など複数需要が競合する仕組みは未実装。
- **演出用の群衆NPC**: 代表住民とは別に、経済ロジックに関与しない「見た目だけのウォーカー」を一定数歩かせる案。実装は容易(需要フローから経路をサンプリングして歩かせるだけ)だが未着手。
- **混雑判定のバランス調整**: 現状、House1棟(代表住民最大6人)からOffice1つ(雇用枠5人)へ道を繋ぐと、ほぼ即座にdebugLoadが3を超えて道路が真っ赤になる。閾値や見え方の調整余地あり。
- **街の成長による問題発生**: 人口増加で渋滞・騒音・交通量増加などの問題が後から発生し、プレイヤーが道路整備で解決するループ。未着手。

## ビジュアル・UI

- **Kenney Road Kitによる道路の実モデル表示**: 現状は`DebugLineRoadMeshGenerator`による線描画のプレースホルダー。Milestone 2で設計したが実装は一時中断中(`Models/RoadModels/`に素材は導入済み)。
- **UIをテクスチャ(画像)に差し替える**(2026-10-22): UIの見た目は`IUISkin`(`UI/UISkin.h`)に集約済み。画像版のスキン(`TextureUISkin`)と、`UIRenderer`の画像描画(9スライス・アトラス)が必要。手順は [ui_skin.md](ui_skin.md)。
- **メニューの残り**(2026-10-22): 研究タブの中身(今は準備中の表示だけ)、キー操作(矢印・Enterでの選択)、ボタンの音・開く時のアニメーション、建物・道路の種類が増えた時のスクロール(今は、収まるように行を縮めるだけ)。
- **接続状態のわかりやすい表示**: 建物-道路の接続を「線の有無」だけでなく、建物自体の色や印、Inspectorの`Road Connected: Yes/No`表示などでもっと明確に示す案。Milestone 3では接続線(`DemandSystem::Draw`)のみ実装。「線が無い=未接続」という消極的な表現だけでは分かりにくい、という指摘が残っている。
- **道路配置のカーソル表示の高度化**: 現状は緑/赤の丸マーカーのみ。もっとゲームらしい見た目への差し替えは未着手。

## エンジン・技術基盤

- **Releaseビルドでの ImGui / カメラ操作**: 現状、`DebugRenderer`はENABLE_EDITORの外で初期化・描画しているが、ImGuiの`NewFrame`/`Render`自体とFree Cameraの移動処理は`DebugEditor`経由で`ENABLE_EDITOR`(Releaseでは未定義)の中に閉じている。Build/City Stats/Profilerパネルや視点移動が配布版で動作しない可能性が高い。配布可能な版を作る際に対応が必要。
- **GameObjectFactory::FindByIdの最適化**: 現状は線形探索。オブジェクト数が増えてボトルネックになったら、ハンドル+世代番号方式(id→indexの対応表)へのアップグレードを検討する(Profilerパネルで実測して判断)。
- **建物・道路の削除機能**: `GameObjectFactory::Despawn`は用意済みだが、ゲーム内から呼び出す削除UIは未実装。実装する際は、道路の占有解放(`SetOccupied(false)`)やDemandSystem側の参照(自宅/職場が消えた代表住民の扱い)も合わせて対応が必要。

## お金・経済まわり(2026-10-08 追加)

- **収入の仕組み**: 今は建設費で減るだけ。住民の税・オフィスの売上・ショップの売上などで `GameEconomy::Earn` を呼ぶ仕組みが必要(呼び出す側が未実装)。
- **道路の値段の割増し**: 曲がりの大きさそのものへの上乗せ(今は「うねるほど全長が伸びて高くなる」だけ)。道幅の種類ごとの単価の差(Large等)。
- **お金が足りない時の通知**: 今はゴースト/ホバーの赤とカーソル横の文字だけ。通知・効果音の仕組みは未実装。
- **店の種類(八百屋・魚屋・CDショップなど)**: 今のShopは1種(仮のモデル=Commercialキットの`building-d`)。`BuildingType`に値を足し、`BuildingType.cpp`に定義、`ScenarioFile::BuildingTypeKey`に保存名を足すだけで増やせる。モデルはユーザーがサイトから探して用意する(候補リンクは会話で共有済み。ライセンスはダウンロード元で要確認)。

## 素材・モデル読み込みまわり(2026-10-20 追加)

- **SimplePoly の建物の向きの補正**: 座標系の変換後、Kenney の建物は正面が +Z、SimplePoly の建物は -Z。SimplePoly の建物を採用する時に、建物の定義に向きの補正値(180度)を持たせる。詳細は [model_loading.md](model_loading.md)。
- **OBJ ローダーのメモリ読み込み**: FBX は `LoadFromMemory` 対応済み。OBJ は未対応(素材を exe に組み込む時に必要)。
- **アセットブラウザの次の段階**: 「採用」ボタン(`Assets/Incoming/<パック>` → `Assets/Models/<パック>` へコピー + `THIRD_PARTY_LICENSES.md` へのメモの自動生成)、既存の素材フォルダ(`CityKitCommercial` 等)の `Assets/Models/` への移動(パス・ライセンス文書・各文書の書き換えが一度に必要)、サムネイルの向きの選択(モデルごとに正面が違う)、複数選択・フォルダ階層の表示。基本の機能は実装済み([asset_browser.md](asset_browser.md))。
- **Quaternius の「Textured」版OBJにテクスチャを割り当てる**: MTLに参照が無く、灰色になる。`Textured Models/Textures/Texture_*.png`(色違いの atlas)を選んで割り当てる仕組みが要る(FBX版の扱いも未確認)。
- **取り込みのコピーを別スレッドに**(2026-10-21): エクスプローラーからのドロップのコピーは、ゲームの更新の中で行うので、数百MBの素材では数秒、画面が止まる。別スレッドで進めて、進み具合を出す。
- **Prop(飾り)のUndo・当たり判定・マスの占有**(2026-10-21): 今の飾りは、見た目と目印だけ。置いた・動かした・消した操作を、Editorの元に戻す履歴へ載せる、建物との重なりの扱い、などは未着手。飾りの削除UIも未実装(Hierarchyからの削除)。
- **テクスチャのキャッシュ**(2026-10-21): モデルキャッシュは頂点だけ。テクスチャ画像のデコードも、速い形(DDSなど)で焼く案。
- **シェーダーのホットリロードと調整パネル**(やることリスト1): シェーダーに取りかかる時にまとめて作る。
- **スキニングとアニメーション**(やることリスト4): キャラクターを使う時。
- **素材を exe に組み込む(最終提出用)**: 提出時に素材を exe の中に入れる。ローダーを「ファイルのパス」ではなく「バイト列」から読める形にしておくと後で楽(ufbx は `ufbx_load_memory`、テクスチャは `CreateWICTextureFromMemory` がある)。開発中は今まで通りファイルから読み、提出版だけ組み込みにする案。
- **素材のライセンス確認の残り**: `Models/cube.obj` の出所、`Models/RoadModels/` が City Kit (Roads) で正しいかの確認、取得したバージョンの記録。
