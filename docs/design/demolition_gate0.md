- 作れる。ただし、**道路の部分削除は、道路データの持ち方(区間の配列+添字参照)のせいで、建物の解体よりずっと重い**。道路の削除は、必ず「全部作り直す」形(ノード・占有・メッシュ・経路)で行う。

## 3. 道路の「1マス」を削る方法(OPEN-01・02)

現状の事実: 道路の幅は1.0、マスは0.5。直線は、区間の始点がマスの中心(セルにスナップ)で、長さがマスの整数倍。自由描きの区間は、約0.8の長さで、マスに揃わない。**幅1.0の道は、そもそも、マス目(0.5)にぴったり揃った形ではない**(中心線の左右に、0.5ずつ)。

### 案A(推奨): 道路に沿った「長さ0.5×道幅」のスライスを切る
- カーソルから、一番近い道路の点(`FindNearestPointOnRoad`、既存)を求め、その区間の上で、始点からの距離 d を、0.5刻みに丸める(スライスの中心 = 始点 + k×0.5)。
- 切る範囲 = その中心から、前後0.25ずつの、**全幅の長方形**(その区間の向き・道幅のまま)。長方形の中にある、**全ての区間の中心線**(別の道が交わっていれば、それも)を、長方形の外へ切り出す。
- 利点: 見える四角と、切れる所が一致する。直線は、始点がマスの中心なので、軸に揃った道では、表示のマス目と揃う。斜め・曲線でも、向きの揃った長方形で、自然に見える。区間の中を切るので、「道1本まるごと」にはならない。
- 欠点: 自由描きの短い区間(0.8)は、区間の途中が切れて、**区間が2つに割れる/ごく短い端切れ**が出る(0.1未満の端切れは、隣へ吸収する、などの規則が要る)。

### 案B: 画面のマス目(ワールドの0.5マス)で、中心線を切る
- カーソルのマスの正方形の中にある、中心線の部分を切る。
- 利点: 表示のマス目と、完全に一致する(ハイライトも単純)。
- 欠点: 道幅1.0は、マス目に揃っていないので、**1マス選んでも、見える欠け方が、場所によってまちまち**。斜めの道では、中心線が、マスの角をかすめて、0〜0.7の長さしか切れない(何度も選ばないと切れない)。

### 案C: 区間(ノードからノード)単位で削除
- 実装は簡単で、安全(割れ・端切れが出ない)。
- 欠点: 直線の長い道が、1回で全部消える(**FIX-07 に反する**)。自由描きの道は、区間が短いので、これに近い動きになる(約0.8=1.6マス)。**直線にだけ案Aを、自由描きの区間には案Cを、使う混合案**も、現実的な代替。

**推奨: 案A**(混合案は、端切れの処理が難しい時の、第2候補)。

### 共通で必要になる処理(案A・B・混合のどれでも)
1. 切った後の道路を、`RestoreSegments`と同じ手順で全部作り直す(ノード・占有・メッシュ)。区間の追加・削除をしてよいのは、この1か所だけにする。
2. **切った端の見た目**(§4-1)。
3. 切った所の青マスを消す(§4-4)。
4. 動いている住民の経路の扱い(Q5)。

### 道路の費用(OPEN-04)の推奨
- 今の建設費は、`CalculateRoadCost`: 長さを、最初のマス(1.0)単位に**切り上げ**て、×20円(全種類20円。仮)。
- 解体費の推奨: **切った中心線の長さの合計 L**(1操作ぶん)に、`costPerCell ÷ 1.0 × 0.5`(Normalで10円/1.0長さ)を掛けて、**操作ごとに合計してから、端数切り上げ**(最低1円。0円では消せない)。例: 0.5を1スライス = 5円。10スライスのドラッグ = 50円。
- 建設費は「切り上げ」なので、厳密な半額にはならない(短い道を作ると、切り上げで割高になる)。ユーザーの「制作時の半分」は、**長さあたりの値段の半分**と解釈している(Q4)。

## 4. 仕様書に無かった重要な問題(コードを読んで見つけた)

1. **切った端が、見た目だけ塞がる(設計に影響)**: 道路メッシュは、行き止まり(次数1のノード)の見た目を、マスの半分(今は0.25)だけ、区間の方向に伸ばす(`deadEndExtension`。直線の端点がマスの中心にあるため)。切った端も行き止まりになるので、**両側が0.25ずつ伸びて、0.5のスライスが、見た目では、ちょうど塞がる**(中身は切れているのに、見た目はつながって見える)。占有の矩形も、同じ延長を付けている。→ **「切った端は平ら(延長しない)」を表せるよう、区間に任意の項目(`flatStart/flatEnd`。既定false)を足す**案を、推奨(セーブに任意項目を足す。古いセーブはそのまま読める)。Q7。
2. **混雑表示の添字**: 住民の `segmentIndices` は、道路区間の添字(配列の位置)。**【訂正(Gate 1で確認)】混雑表示のループは、範囲を確かめていた(`segIndex < segments.size()`)ので、落ちはしない。** ただし、削除で添字が変わると、違う区間に混雑が付く(表示のずれ)。→ Gate 2 で、道路を変えたら、全員の `segmentIndices` を空にする(混雑表示は毎ティック作り直すので、害は無い)。
3. **施設を解体した時の売上の記録**: `FacilityLedger` の記録は、施設のidで持ち、セーブでは、建物が無い記録を捨てる。そのまま解体すると、**過去の売上・来訪者数が、集計から消える**(FIX-11)。→ 解体した施設の記録は、まとめて「解体済み施設」の1件に足して、残す(週・月・累計は、そのまま)。Q6。
4. **青マスの扱い**: 自由描きの青マスは、連なり全体の中心線から作り、**連なりの情報は保存していない**。道路の一部を削った後に、残りの道の青マスを、元の並びで作り直すことはできない。→ 推奨: 切った長方形(を左右に1マス広げた範囲)にかかる青マスだけを消す(建物の敷地にかかる物は、消さない)。残りは、そのまま残す。**建物の解体では、青マスは消さない**(同じ格子で、また建てられるように)。

その他(C: 安全に対処して報告):
- **道路が切れて「到達不可」になった住民**: 道路沿いに接続できる(隣接道路はある)が、どの施設にも、行けない状態。内部では、「隣接道路あり/なし」と「到達できる/できない」を分ける(仕様書の補足どおり)。表示の文言は、**「道路がない!」(隣接する道路が無い)/「道がつながっていない!」(道路はあるが、行ける施設・自宅に届かない)**の2つを推奨。
- **家が消えた住民のマーカー**: 同じ位置に複数人(今は1軒1人だが、将来の増員や、同じ場所に建て直して再び住民が増えた場合)は、小さな円状のずらしで重ならないようにする。新しい住宅を、同じ場所に建てても、**住居なし住民は、自動では入居しない**(住宅を建てると、新しい住民が、普通に生まれる)。
- **住居なし住民の週末処理**: 需要・体力の週の処理は、今のまま続ける(免除しない)。外出の判定だけ、止める。
- **人口の表示**: 「住民」の数は、住居なしも含める(消えたように見せない)。「人口」(住宅が表す数)は、住宅が減った分だけ減る。両方を別の数として扱う。
- **住民をクリックした時のパネル**: 今は、住宅のidから探す。住居なしの住民でも開けるよう、「住居がない!」の表示に対応する(Gate 1)。
- **エディタ(Hierarchy・Inspector)の選択の添字**: 削除で添字がずれるので、削除のたびに選択を解除する(ロード時と同じ)。

- 建築・道路の配置、カメラ、住民の選択・追跡は、変更なし。格子線は、建物・道路の配置中だけ出す(解体ツールの間は出さない)(Release)。
- セーブの形式: 住民に `home: -1`・`homePosition`、状態 `Homeless`、売上の記録に `demolished`、帰宅中は、行き先が無くても保存。**古いセーブは、そのまま読める**。

### 未解決の懸念・次のGateの前に
- 実際のマウス操作(クリック・ドラッグ)は、実ウィンドウを操作しない方針のため、**ユーザーの実機確認が必要**(診断では、同じ処理を直接呼んで確認)。

- Gate 2 の前に決めたい: Q5 の「満足度」。現在のコードに、独立した満足度のパラメータは**無い**(あるのは、需要の充足度 `lifeNeed`/`activityNeed` と、体力 `stamina`)。大きな満足度のシステムは足さず、**「満足度のペナルティ」を、需要の充足度(アクティビティ)を一定量、下げる形で実現する**案を、先に報告する(下げる量は、設定で調整できる)。
