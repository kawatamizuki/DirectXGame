# テストマップの管理(段階1: 保存形式と保護)(2026-11-10)

## 目的
手作業で丁寧に作った同一の街を、何度でも、同じ初期状態から検証できるようにする。自動テスト・通常のセーブが、元ファイルを書き換えないようにする。
(段階2 パネル / 3 自動検証 / 4 結果保存 / 5 比較 / 6 一括実行 / 7 コマンドライン は、段階1の確認後に進める。)

## 置き場所
- `TestMaps/<id>.json` … 正式に採用した物(Git管理)。
- `TestMaps/Drafts/<id>.json` … 作成途中・試作(Git管理外)。
- `TestResults/` … 検証結果(Git管理外。段階4から使う)。

## 保存形式
既存のセーブ(`ScenarioManager` が書く JSON)に、メタ情報 `"testMap"` を足しただけ。ゲームの読み込みは、知らない項目を無視するので、そのまま普通のセーブとして読める。
`testMap`: `schema` / `name`(表示名。日本語可)/ `description`(説明)/ `purpose`(検証目的)/ `focusMetrics`(注目する指標)/ `createdAt` / `gameBuild`。
ファイル名(id)は、半角の英数字・`_`・`-`、1〜48文字、先頭は英数字。予約名(CON/NUL/COM1…/Drafts)は不可(パスの細工と、文字コードの問題を避ける)。

## 初期状態の指紋
街の部分(メタ情報 `testMap` を除いた内容)の FNV-1a 64bit。名前・説明を直しても変わらない。同じ指紋 = 同じ初期状態。

## 保護(通常のセーブが、元ファイルを上書きしない)
- `ScenarioManager::Save` は、`TestMaps/` とその下へは、書かない(`ScenarioManager::IsProtectedPath`。既定で有効)。F5 などの通常のセーブは `Saves/`。
- 判定は `PathGuard::IsInsideDirectory`: 相対/絶対・`./` `../`・`\` と `/`・大文字小文字・末尾の `.` と空白(Windowsは無視して同じフォルダにする)・短い名前(8.3)・ジャンクション(既存の親を `std::filesystem::equivalent` で比べる)・まだ存在しないフォルダ、に対して、すり抜けられない。
  怪しい書き方(`:` で別の流れを指す・`\?\` `\.\` の接頭辞・制御文字)・判定できない・例外が出る(日本語を含むパスの変換失敗など)時は、**安全側(書かせない)**。
- 元ファイルを書き換えるのは、`TestMapStore` の操作だけ(新規保存・メタ情報の更新・名前変更・移動・削除)。新規保存は、既存の id(大文字小文字を区別しない。正式・下書きのどちらにも)を上書きしない。書き込みは、一時ファイルに書いてから置き換える(`WriteFileAtomic`)。
- 同じ id が正式と下書きの両方にある時(手でコピーした時など)は、どちらか分からないので、操作を断る。
- 「Save as tutorial map」ボタンは、デバッグ画面から削除した(`Scenarios/tutorial.json` の誤上書きを防ぐ)。「Load tutorial map」と、通常のセーブ・ロードは、そのまま。

## 確認したこと
- 単体テスト `tests/sim_testmap_test.cpp`: 名前の検査・パスの保護(上の全ての書き方)・安全な書き込み・保存/一覧/メタ情報の更新(指紋不変)/読み込み/名前変更/移動/削除・壊れたファイル・曖昧な名前。
- ゲーム本体(一時的な診断): `ScenarioManager::Save` に、保護された場所の 10 通りの書き方を渡し、全て拒否された(`TestMaps/` は作られない)。通常の保存先(`Saves/`)には、保存できた。

## 残る懸念
- 日本語を含む絶対パスは、標準ライブラリの文字変換が失敗することがある(以前からの制約)。保護の判定は、その時、書かせない側に倒れる。
- OSの読み取り専用属性は使っていない(ご指示)。保護は、このアプリの保存処理の範囲。他のツール(エディタなど)で、ファイルを直接書き換えることは、防げない。
