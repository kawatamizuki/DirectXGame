# テストマップ 段階3: 保存済みテストマップの自動検証

段階3は、3つに分けて進める(1つずつ、確認をもらってから次へ)。

| 段階 | 内容 | 状態 |
|---|---|---|
| 3-A | 実行の仕組み(SimEndurance の拡張) | 実装済み(2026-11-10)・未コミット |
| 3-B | 操作画面(テストマップのパネルから実行・中止・結果の表)と、実行中の編集操作の禁止 | 実装済み(2026-11-10)・未コミット・実機確認待ち |
| 3-C | 確かめ(決定論・初期状態・データの保護の診断)と学習メモ | 未着手 |

## 決定事項(2026-11-10)
- 複数回の試行: 指定の種(基準の種)と試行の番号から、試行ごとの種を作る(`MakeTrialSeed`)。
- 決定論の確認: 最後に、1回目と同じ種で、もう1回進めて、指紋を比べる。**違う種で指紋が違うことは、合格の条件にしない**(違う種でも、同じ結果になることがある)。
- 設定値: 使った値を記録するだけ(変更・比較は、段階5以降)。
- 結果: 画面に出すだけ(ファイルへの保存は、段階4)。
- 住民の停滞などの合否判定は、しない。
- 時計の倍率: **当面20倍に固定**(暫定)。実行条件に記録する。
- 通常の耐久試験は、これまでどおり使える。

## 3-A の作り
- `Simulation/SimTrial.h`(画面に依存しない。単体テストあり): 実行条件 `SimTrialConditions`・試行の結果 `SimTrialResult`・簡単な指標 `SimTrialIndicators`・決定論の判定 `EvaluateDeterminism`・種の作り方 `MakeTrialSeed` / `BuildTrialSeeds`・条件の検査 `ValidateTrialConditions`。
- `DebugTools/SimEndurance`: 新しい種類 `SimEnduranceMode::TestMapTrials`。`RequestTrials(原本, 条件)` で、次の Update から始める。
  - **2つの控えを、別々に持つ**: 「実行前の街」(`m_baseBytes`。終わったら戻す)と「試行の原本」(`m_trialBaseBytes`。テストマップのファイルの中身。毎回ここから始める)。
  - 試行ごとに、設定の種(`settings.seed`)を試行の種に置き換え、乱数の取り方を FixedSeed にして、原本を読み込む(`LoadFromBytes`)。乱数の取り方は、読み込んだらすぐ元へ戻す。設定の種は、全ての試行が終わるまで置き換えたまま(新しく生まれる住民の性格も、この種で決まる)。
  - 終わり方: 指定の週数 / 異常(条件で止める時だけ) / 1回の実時間の上限 → 次の試行へ。全て終わった・中止・読み込みの失敗 → **設定の種を戻してから**、実行前の街へ戻す(乱数の状態・時間の倍率も)。異常でも Held にはしない。
  - 結果はメモリだけ(CSV は書かない)。
- `Core/Game`: `StartTestMapTrials(id, 条件)`(原本を読んで、id・ファイル・指紋・ビルドを条件に書き足す)と、指標を集める関数(人口・住民・需要不足・住居なし・立ち往生・資金)。
- **実行中のセーブ・ロードの禁止**(耐久試験にも効く): F5/F9・メニューのセーブ/ロードは断る。「Scenario」パネルは操作できなくする。以前は、耐久試験の最中のF5で、試験用の街が普段のクイックセーブに書き込まれていた。

## 確かめたこと(3-A)
ゲームの中の一時的な診断コード(確認後に削除)で、小さなテストマップ(住民2人)を使った。テストマップを「使用中」にして、時間を進めてから止めた街を、実行前の街にした。
- 26週×3回+決定論の確認1回: 1回目と4回目(同じ種。間に別の種の2回を挟む)の指紋が一致。違う種の3回は、指紋が違った(参考)。
- 実行後: 週・時刻・倍率・設定の種・乱数の取り方・世界の種・配置・テストマップの使用状態(使用中・控え・配置の変更)・読み込みの回数が、実行前と一致。テストマップのファイル・普段のクイックセーブ・テスト用のクイックセーブは、変わらない。
- 中止(520週の途中): 中止した試行を記録して、実行前の街へ戻った。実行中のF5・F9は断られた。
- 通常の耐久試験(決定論テスト): これまでどおり一致。
- 無いマップ・週数0: 始めずに、理由を返す。
- 倍率の影響: 同じ種・同じ2週で、倍率5と倍率20の指紋が違った(イベントの数も違う)。**倍率20の結果は、通常の速度のプレイと同じとは限らない**。条件の倍率を変えて、後から比べられる(画面では、当面20倍に固定)。
- 速さ: 住民2人の街で、26週が約0.1秒。住民が多い街では、これより遅い(以前の耐久試験では、26週に約11秒)。

## 分かった、既存の小さな丸め(今回は直さない)
実行前と実行後の街のデータを比べると、住民の「施設にいる残り時間」(`visitHoursLeft`)が、実行前は -0.001、実行後は 0 だった。セーブを読み込む時に、0未満を0にしている(`DemandSystem::Load`)ため。普段のF5→F9でも同じことが起きる。0以下は「利用が終わる」扱いなので、動きへの影響は、まず無い。

## 3-B の作り
### 操作画面(Editor の「テストマップ」パネル)
- 一覧で選んだテストマップが、自動検証の対象。下の方の「自動検証の条件と結果」で、次を入れる:
  1回の試行で進める週数(1〜520・既定26) / 試行の回数(1〜100・既定3) / 基準の種(既定12345) / 決定論の確認(既定ON)。倍率は表示だけ(20倍に固定)。
- 「自動検証を始める」 → 実行中は、何回目・何週目・進み具合の棒・この回の経過時間・異常の数・「中止」。
- 結果: 前回の条件(マップ・週数×回数・倍率・基準の種・原本の指紋・ビルド・実行前の設定の種)、決定論の確認(一致 / 不一致 / 比べられない)、試行ごとの表(回・種・終わり方・週・異常・指紋・人口・住民・需要不足・立ち往生・資金・実時間)。
- **パネルの上の方にも、短い状況を出す**(実行中: 何回目・何週目と「自動検証を中止」。終わった後: 前回の結果の要約)。パネルが長く、下の方はスクロールしないと見えないため。
- 始められない時(Playing でない・耐久試験・タイムライン・再現が動いている)は、ボタンを押せず、理由を出す。
- 耐久試験のパネルは、自動検証の実行中、「自動検証を実行中です」と「中止」だけを出す(耐久試験の設定での進み具合を、出さない)。

### 実行中に止める操作(`Game::IsWorldLocked` = 耐久試験・自動検証が Running の間。異常で止まって見ている Held の間は、止めない)
| 操作 | 止め方 |
|---|---|
| 建築・道路・解体・商業エリアのツールを選ぶ(メニュー) | `ApplyMenuCommand` で断り、知らせを出す |
| 選んでいた・置きかけのツール | 毎フレーム、やめさせる(`EnforceWorldLock`) |
| 建築・道路・解体・商業エリアの操作そのもの | ツールの Update を呼ばない |
| 飾り(素材)の配置(ドラッグ・中央に置く) | `PropPlacer::Update` を呼ばない・`PlaceAssetAtViewCenter` で断る |
| 編集モード(オブジェクトの移動・削除・元に戻す) | 毎フレーム、Playing へ戻す |
| エディタの選択(インスペクターでの書き換え) | 毎フレーム、選択を外す |
| F5/F9・メニューのセーブ/ロード | 断る(3-A) |
| 「Scenario」パネル | 操作できなくする(3-A) |
| 設定値(City Stats)・住民デバッグ(行動テスト)・時計・資金・素材の一覧・商業エリアのパネル | 操作できなくする(見るだけ) |

## 今後の方針(2026-11-10 決定。今は実装しない)
### ① 倍率に左右されない結果
- 今は「1ステップ = 1/60秒 × 倍率」。倍率を上げると、1ステップで進むゲーム内の時間が長くなり(刻みが粗くなり)、結果が変わる(3-Aで、同じ種でも倍率5と20で指紋が違った)。
- 目標: 通常プレイと高速検証で、同じ初期状態・種・設定なら、原則として同じ結果。**更新の刻みと処理の順番は同じまま**、描画や待機を減らして(1フレームに多くのステップを回して)速くする。
- 最終的には、通常プレイと同じ1倍速での動作確認も必要。
- 今の作りへの配慮: 倍率は実行条件(`SimTrialConditions::timeScale`)として記録している。進め方は1か所(`SimEndurance::RunSlice` と、ゲームが渡す1ステップの関数)にまとまっているので、刻みを固定して回数を増やす方式に、置き換えやすい。
- 調べること: ふだんのプレイの刻み(実時間のフレーム間隔)と、検証の刻みの違い / 刻みを固定した時の速さ / 1倍速と高速で、指紋が一致するか。

### ② 夜間の無人自動検証
- 寝る前に、テストマップ・条件・回数を設定 → 夜の間に自動で実行 → 翌朝、ログ・統計を見る。
- 用途: 長時間の実行でのメモリリーク・異常の検出 / 抽選が設定の確率と統計的に合っているか / 住民AIの異常・長期の停滞の観察 / 複数の種・複数のマップでの長期検証 / 途中で異常終了した時の原因調査。
- 段階4〜6でログの保存・統計の比較・一括実行、段階7で画面を開かない無人実行。
- 今の作りへの配慮: 実行条件と試行ごとの結果を、データのまとまり(`SimTrialConditions` / `SimTrialResult`)で持っている(段階4で、そのままファイルに書ける)。画面は結果を読むだけで、進める処理は画面に依存しない。
- 課題: 異常の検出と指紋は、記録の仕組み(Editor のビルドだけ)を使う → 段階7で、画面なしでも記録を使えるようにする必要がある。途中で落ちた時に備えて、途中経過を少しずつファイルに書く(段階4)。
