# ゲームコンセプト・仕様まとめ

最終更新: 2026-09-10

このファイルは、企画検討で固まった方向性を随時更新していく「生きたドキュメント」です。実装の詳細は各マイルストーンの設計ドキュメント(`docs/design/milestone*.md`, `docs/design/v0_*.md`)を参照してください。未着手・保留にした項目は[backlog.md](backlog.md)にまとめています。

## ゲームの核

**道路を使って人流を意図的に作り、その通過客を利用して施設・地区を育てることを主役にした、カイロソフト寄りのコンパクトな経営シミュレーションゲーム。**

「道を自由な角度で引ける」という機能そのものが主役なのではなく、**道路を使って人の流れをデザインできる**ことが主役。

### コアループ

```
道路の自由度
  ↓
人流が変わる
  ↓
施設の利用状況が変わる
  ↓
地域の発展が変わる
  ↓
新しい交通問題・需要が生まれる
  ↓
また道路を整備する(最初に戻る)
```

## 差別化ポイント: 唯一の正解を作らない

カイロソフト系シミュレーションゲームは「格子状の道路+固定の施設コンボ」に収束しがちだが、本作では以下によって「唯一の正解」を作らない設計を目指す。

- 道路は縦横だけでなく、斜め・曲線・円状・放射状など自由に配置できる。
- 施設同士の固定コンボ(「パン屋の横にカフェ」)を作らず、**需要と人流から結果的に相性が生まれる**仕組みにする(後述)。
- 効率という言葉を1種類にしない。移動効率・土地効率・交通容量・景観・静かさ・回遊性・アクセス性など複数の評価軸を用意し、商業に強い街/住宅環境が良い街/観光に強い街/交通がスムーズな街、といった複数の「勝ち筋」が成立するようにする。

## 道路の種類とトレードオフ

| 道路 | メリット | デメリット |
|---|---|---|
| 格子状 | 建物を並べやすく土地効率が高い。経路も複数作りやすい | 対角方向への移動は遠くなりやすい |
| 斜め | 特定地点同士を短距離で結べる。人流を意図的に作りやすい | 三角形などの土地が発生して建築効率が悪くなる(**意図したトレードオフとして残す**) |
| 放射状 | ランドマークや駅など中心施設へのアクセスを高められる | 中心に交通が集中して渋滞しやすい |
| 環状 | 中心街を通らず別地域へ移動でき、通過交通を逃がせる。回遊性を作れる | - |
| 曲線 | 地形に合わせたり自然な街並みを作れる。山や川に適応しやすい | 直線より移動距離が伸びる場合がある |
| 細い路地 | 土地を有効利用できる。住宅地向き | 大量の交通・大型車には向かない |
| 袋小路 | 通過交通がなく住宅地を静かにできる | 商業・移動効率には弱い |
| 大通り・幹線道路 | 交通容量が大きい | 土地を多く使う・騒音が増える |

自由角度の直線道路(Milestone 1)、道路種類(細い/普通/大きい、Milestone 3)、道路の途中からの分岐(T字路、Milestone 3)まで実装済み。道路幅の自動フィット・拡張/アップグレードは未着手(`docs/design/backlog.md`参照)。

## 施設: 固定コンボではなく需要から生まれる相性

施設名同士を直接結び付ける固定コンボ(「パン屋+カフェで売上+20%」)は作らない。**プレイヤーが街の仕組みから相性を発見する**という考え方。

- ランドマーク(凱旋門等)は単純に観光客を呼ぶ施設。
- ホテルは宿泊需要がある場所で儲かる施設。
- 飲食店は食事需要や人通りがある場所で儲かる施設。
- 商店は買い物需要と通行量によって利用される施設。
- 結果として「ランドマークの周辺にホテルや飲食店を作ったら自然と相性が良かった」という状態が生まれる。

### ランドマーク起点の発展例

何もない田舎にランドマークを建てる → 観光客がそこへ向かう → プレイヤーが放射状道路を引いて人を周囲へ分散 → 道路沿いにホテル・飲食店・商店・公園・住宅を配置 → 観光施設を起点に新しい街が形成される。ランドマーク周辺を開発せず、道路で隣町へ人を流して既存商店街を発展させる、という使い方もできる。施設は「周囲にバフをかける建物」ではなく、**人を発生させたり人の目的地を作ったりする装置**。

## 人を中心にしたシミュレーション

施設そのものより、**人の行動**を中心に考える。住民や観光客は、家→会社→飲食店→公園→家、のように複数の目的地へ移動する。道路の形によって得意なことが変わる。

- 斜め道路: 特定2地点を最短で結ぶのが得意。
- 格子状道路: 多くの場所へ柔軟に移動するのが得意。
- 環状道路: 複数のエリアを巡ったり中心街を避けたりするのが得意。
- 放射状道路: 中心施設へ大量の人を集めるのが得意。

「この道路形状ならこの施設」ではなく、「**人をどう動かしたいからこの道路を作るか**」という思考にする。

## 人のシミュレーション方式

500人・1万人規模の個体を全員シミュレートするのは非現実的なため、以下のハイブリッド方式を採用(Milestone 2以降で実装)。

- 建物ごとに**代表住民(ResidentAgent)を少数だけ実個体としてシミュレート**する(例: アパート1棟＝人口50人、代表住民6人)。
- 建物が「実際には何人分を表しているか(人口)」は別の数値として持つ。
- 代表住民は実際に家→職場などを道路網に沿って歩く。個体としての情報(種別・目的地など)を保持する。
- それ以外の群衆(見た目だけのNPC)は将来追加予定(未着手、backlog参照)。

## 施設の競合(需要の奪い合い)

固定コンボを防ぐため、需要と供給を導入する。観光客500人が来ても食事需要が300人分しかなければ、レストランを10軒建てても全部儲かるわけではない。店同士で客を取り合う。観光客が食事・買い物・宿泊・娯楽・休憩など複数の需要を持てば、プレイヤーごとに飲食街/ホテル街/ショッピング街など異なる街づくりが生まれる。現状は通勤(House→Office)の需要のみ実装済み(Milestone 2)。

## 街が時間とともに変化する仕組み(未着手)

「以前の正解が正解でなくなる」という成長を作る。人口100人の頃は一本の道路で十分だったが、人口1000人で渋滞する。商業街が成長すると住宅に騒音問題が出る。工場が増えるとトラック交通が増える。プレイヤーはバイパス・環状道路・道路拡幅・街の分散などで対応する。**発展によって問題が起こり、その問題を道路設計で解決すること自体をゲームプレイにする。**

## 建物はグリッド固定、道路は自由配置(現在の方針)

- 建物は引き続きグリッド固定で配置する。
- 道路は自由配置(直線、Milestone 3でT字路分岐に対応予定)。
- 建物と道路は、隙間があっても近ければ「接続」扱いにする(Milestone 3で実装済み。あいまいな距離しきい値ではなく道路上の最近接点を使い、隣接程度の狭い範囲のみ対象)。
- 建物を道路の角度に合わせて回転させる/三角形の余り地の角で建物がはみ出さないようにする、といった調整は**未着手**(backlog参照)。

## 就活作品としての説明(想定)

> 一般的なグリッド型街づくりだけでなく、自由な道路形状をゲームシステムに組み込みました。施設が生み出す需要と住民の移動を道路ネットワーク上でシミュレーションすることで、同じ施設構成でも道路設計によって異なる街へ発展します。固定された配置コンボではなく、プレイヤー自身が人流を利用した相乗効果を作り出すことを狙っています。
