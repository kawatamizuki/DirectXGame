# セーブ/ロードの設計

## 方針: 「操作の履歴」ではなく「今の状態」をコピーして保存する

保存するのは**今ある状態そのもの**(スナップショット)で、置いた操作の履歴ではない。
理由: 履歴方式だと、プレイ時間が長いほど記録が膨らむ/建物の改築・パラメータ変化のように
「置いた操作」では結果が決まらない変化を再現できない/将来チャンクに分けると履歴に境界が無い、という問題があるため。
スナップショット方式なら、保存・読み込みの重さは**街の大きさだけに比例**し、プレイ時間に依存しない。

## 何が「本体」で、何が「派生」か

| 区分 | 内容 | 扱い |
|---|---|---|
| 本体 | 道路の区間(`RoadSystem::m_segments`)、建物(`GameObject`+`BuildingPlacement`)、時計、フラグ、住民 | **そのまま保存**する |
| 順序に依存する派生 | 青い隣接マス(`GridOrientationRegistry`。先に作られた方が優先) | 再計算すると結果が変わりうるので、**一覧を優先順のまま保存**する |
| 決まった手順で作り直せる派生 | 道路ノード、占有(`IOccupancyGrid`)、道路メッシュ、統計・接続線(`DemandSystem`) | **保存しない**。読み込み後に作り直す(`RoadSystem::RestoreSegments` など) |

読み込みは**再検証も再生もしない**(状態をそのまま戻す)ので、配置ルールが後で変わっても、保存した街はそのまま読める。

## 構成

- `Scenario/Json.{h,cpp}`: 形式に依存しない「値の木」と、JSONテキストの読み書き。キーは入れた順を保つ(出力が毎回同じになる)。
- `Scenario/ISnapshotFormat.h`, `JsonFormat`: 「値の木 ⇔ ファイルのバイト列」。**ファイル形式はここだけが知る**。
- `Scenario/WorldSnapshot.h`: 今の街の状態のコピー(道路・建物・青マス・システムごとの状態の区画)。
- `Scenario/ScenarioFile.{h,cpp}`: `WorldSnapshot` ⇔ 値の木(列挙は**名前**で保存。知らない項目は警告して無視、足りない項目は既定値)。
- `Scenario/ISaveable.h`: 状態を持つシステムが実装するインターフェース。`ScenarioManager::RegisterSaveable` で登録するだけ。
- `Scenario/ScenarioManager.{h,cpp}`: 保存(集めて書く)・読み込み(検証 → 全消去 → 復元)・登録・デバッグパネル。
- 保存先: `Scenarios/`(Git管理するマップ。`Scenarios/tutorial.json` はゲームシーン開始時に読み込まれる)、`Saves/`(プレイヤーのセーブ。gitignore)。
  操作: `F5`=クイックセーブ(`Saves/quicksave.json`)、`F9`=クイックロード、デバッグパネル「Scenario」。

## 読み込みの流れ

1. ファイルを読み、形式を判定し、構文チェックし、`WorldSnapshot` に変換して**検証**する(**ここまでは今の街に一切触れない**。失敗したら今の街はそのまま)。
2. 全消去(建物・住民・道路・占有・青マス・各 `ISaveable` を初期状態へ)。地面などの `Environment` は残す。
3. 建物を生成(`BuildController::SpawnBuilding`。通常の配置と同じ処理)→ 道路を設定(`RestoreSegments`)→ 青マスを戻す → 各 `ISaveable` の状態を戻す(住民など)。

書き込みは一時ファイルに書き切ってから置き換える(書き込み中に落ちても前のセーブは壊れない)。

## 新しい状態を足す時のチェックリスト

新しい「状態」(お金、建物のレベル、チュートリアルの進行、住民の新しい項目など)を足したら、**保存処理を足し忘れると、その状態は保存されない**。必ず次を行う:

1. **建物ごとの値**(レベル・人口・改築の状態など)→ `BuildingPlacement` ではなく、建物の `GameObject` に項目を足し、`SnapshotBuilding` と `ScenarioFile` の読み書きに**名前付きの項目**として足す(足りない項目は既定値になるように読む)。
2. **システムごとの状態**(お金・進行・解放状態など)→ そのシステムが `ISaveable` を実装し、`Game::Initialize` で `m_scenarioManager.RegisterSaveable(...)` を1行足す。
   - `SaveKey()` は一度決めたら変えない(古いセーブが読めなくなる)。
   - `Save` は名前付きの項目で書く。`Load` は足りない項目を既定値にし、知らない項目を無視し、**範囲外の値を丸める**(壊れた/手書きのファイルでも落ちない)。
   - 項目の意味を変えた時は `SaveVersion()` を上げ、`Load` で古い版を読み替える。
   - `ResetToDefault()` で初期状態に戻せるようにする(古いセーブに区画が無い時、全消去の時に呼ばれる)。
   - 他の保存データから建物を指す時は、**建物のuid**(`SaveContext::UidForBuildingObject` / `LoadContext::ObjectIdForBuildingUid`)を使う。実行時の `GameObject::id` は読み込みのたびに変わる。
3. **新しい種類のオブジェクト**(`ObjectKind`)→ 保存対象に追加する。追加しないと、保存時に「セーブ対象外の種類のオブジェクトがあります」という警告が出る(静かに欠落しない)。
4. **作り直せる派生データ**を足した時は、それが読み込み後に作り直されることを確認する(保存はしない)。
5. 確認: 保存 → 全消去 → 読み込み → 再保存して、**元のファイルとバイト単位で一致する**こと。

## 将来バイナリ形式に切り替える手順

容量・読み込み速度・改ざん対策が必要になったら:

1. `ISnapshotFormat` を実装する `BinaryFormat` を作る(値の木 `Json` をそのまま詰める形式+圧縮。先頭にマジックナンバー)。
2. `Matches` で先頭のマジックナンバーを判定し、`Extension()` を `"sav"` などにする。
3. `ScenarioManager::SetFormat` で差し替える(または読み込みで形式を自動判別する)。
4. `ISaveable`・`WorldSnapshot`・`ScenarioFile`・`ScenarioManager` は**値の木だけを扱う**ので、変更は不要。

開発中はJSONのまま(人が読めて、バックアップや差分確認、手での修正ができる)。

## 大きな世界(チャンク)への見通し

建物・道路・青マスは、それぞれ位置を持つ独立したレコード。将来チャンクに分ける時は、レコードを領域ごとのファイルに分けて、必要な領域だけ読み込める
(履歴方式では不可能だった)。住民の経路が参照する道路の添字(`segmentIndices`)は、保存した道路の並びと一致している前提。領域を分割する時は、この参照を領域をまたいで解決する仕組みが要る。

## 既知の割り切り

- 住民の保存は、今ある項目(家・職場・状態・経路・位置・予定表のずれ・速度・見た目の位置)だけ。
- 建物・道路の**削除**機能は未実装。作る時は、削除後の状態がそのまま保存される(スナップショットなので追加の対応は要らない)が、住民の `segmentIndices` や建物uidが指す先が変わるので、削除後に参照が壊れないかを確認すること。
- セーブスロットの一覧・選択UIは無い(クイックセーブ1枠+パスを指定する保存)。
- 地面(`Environment`)・フィールドの大きさは保存しない(コード側の固定値)。

## 確認の方法

- JSON・形式・`ScenarioFile`・`ISaveable` の往復の単体テスト(壊れた入力・知らない項目・版違い・NaNなど)。
- 実際の配置処理で作った街を、保存 → 全消去 → 読み込みして、道路・ノード・メッシュ・青マス(優先順)・占有・建物・住民(通勤途中)が一致すること、
  二重保存でファイルが一致すること、壊れたファイルでも今の街が壊れないこと、読み込み後も続けて置けることを確認した(ゲーム本体に一時的な診断コードを入れて確認し、削除済み)。
- 速度(Release): 道路2000本+建物1000棟+青マス1500で、保存 約29ms、読み込み 約24ms。
