# 住民シミュレーションのデバッグ・検証基盤

2026-10-29。ChatGPTと作った指示書「Claude Code向け｜DirectXGame デバッグ・検証基盤 段階別実装指示書」(`ClaudeCode_DebugSystem_ImplementationPlan.md`)を、このゲームの実際のコードに合わせて設計し、**段階0(基盤調査・仕様固定)と段階1(住民デバッグの基本)**を実装した。段階2以降は、ユーザーの確認を待つ(勝手に進めない)。
解説(用語・仕組み・見つけた問題・実測)は [docs/study/simulation_debug_system.md](../study/simulation_debug_system.md)。使い方は [docs/guide/asset_browser_guide.md](../guide/asset_browser_guide.md) の §21。

## 1. 目的と、守る条件
- 確率で起きる動き(外出・立ち寄り)は、目視だと「起きなかった理由」が分からず、速い値の変化も見逃す。**手で遊んだ手触りの評価と、数値で確かめられる検証を、両立**させる。
- 画面の文字は日本語。開発者向けの道具は **`ENABLE_EDITOR`(Debugビルド)だけ**。Releaseの遊びには出さない・動作を変えない。
- **記録のON/OFFで、行動の結果・乱数の消費を変えない**(最重要)。
- 全ての関数呼び出しは記録しない。**意思決定・分岐・状態遷移・資源変化・異常**だけ。
- シークバー(段階2)は「記録の閲覧」であり、街を巻き戻す機能ではない(段階2以降)。
- 既存のルール・数値(25%/10%/最大2回など)を、デバッグの都合で変えない。

## 3. 段階0: 調査の結果(指示書との照合)
最新のコード(`6c6fce3`)を読んで、指示書の見立てを確かめた。

| 指示書の内容 | 実際のコード | 扱い |
|---|---|---|
| 既存のDecisionLogは直近約40件。外出・立ち寄りの不成立は集まらない | `ResidentSimSettings::decisionLogCapacity = 40`。外出判定の**不発(確率に外れた)は、どこにも残らない**。立ち寄りの抽選の外れ・条件(時刻・体力・回数)で考えなかった理由も、残らない | 新しい記録(§5)で補う。既存の Decisions タブは、そのまま残す |
| 需要判定は3秒以上で1回、ゼロへ戻す | `DemandSystem::Update`: `m_tickTimer += dt; if (< 3.0f) return; m_tickTimer = 0;`。大きな刻みでも、1フレーム1回だけ判定する | **事実どおり**。早送りは、刻みの大きさで結果が変わる(段階5・6で扱う) |
| セーブは乱数の進行状態を保存しない | `Load` → `Reset()` → `m_random.Seed(m_settings.seed)`。**ロードのたびに、同じ種(12345)から乱数が始まる**(= ロード後の抽選列が毎回同じ) | **事実どおり**。指示書の懸念(毎回同じ結果)は、今まさに起きている。段階5で扱う。今回は変えない |
| 住民をクリックで追従、2回クリックで情報パネル | `Game::UpdateBuildingSelection`。追従は `m_followAgentId`、住宅の選択は `m_selectedBuildingId` | 新パネルは、この2つの変数を**読むだけ**(クリックの処理は変えていない) |
| 追従対象とデバッグ対象は別管理、選択に連動/固定(Pin) | 追従は `m_followAgentId`(カメラ用)。デバッグ対象は `ResidentDebugPanel::m_target`(別) | §6 |

**指示書との差**(設計に影響したもの):
1. 住民を区別する安定した番号が無い。**住民の識別には、見た目のオブジェクトの id(`ResidentAgent::objectId`)を使う**(ロード・リセットで別の世界になるので、記録の世界番号 `runId` と組にする)。
2. `ChooseFacility` / `ChoosePurpose` は、結果だけを返し、途中の値(各係数・引いた乱数)を捨てていた。画面が「別の式で計算し直す」ことを避けるため、**ルールの関数自身が、途中の値を書き出す**ように拡張した(§5.2)。
3. 外出判定の確率を求める式が、`RunDemandTick` の中にあった。画面の予測値と実処理が食い違わないよう、`ComputeOutingChance` に取り出した。
4. `CanConsiderStopover` は、真偽だけを返し、理由が分からなかった。`ExplainStopoverBlock`(理由を返す)を唯一の定義にし、`CanConsiderStopover` はそれを使う。

## 5. 記録の仕組み
### 5.1 イベント(`SimEvent`。1件104バイト。数値と列挙型だけで、文章は持たない)
共通項目: `eventId`(単調増加)、`runId`、`residentId`、`outingId`(外出の通し番号)、週・時刻、`kind`・`result`・`reason`(列挙型)、`stopIndex`、`facilityId`、`detailId`(判断の内訳への参照)、`a/b/c`(種類ごとの数値)、判断した時の住民の写し(`SimResidentSnapshot`)。

| 種類(`SimEventKind`) | いつ | a / b / c |
|---|---|---|
| OutingRoll | 外出判定に**当選**した | 確率 / 乱数 |
| PurposeChoice | 目的(カテゴリ・利用目的)を決めた | (内訳は detail) |
| FacilitySelect | 施設を抽選で選んだ(選べなかった場合も) | 重み / 選択確率 |
| OutingBlocked | 出られなかった(自宅の近くに道路が無い/施設が無い) | — |
| MoveStart | 施設へ歩き始めた | 道のり |
| Arrived | 施設に着いた | 滞在予定(時間) |
| VisitFinished | 利用が終わった | 売上 / 生活需要の回復 / 体力の消費 |
| StopoverCheck | 立ち寄りを考えた(**考えなかった理由・抽選の外れ**も) | 確率 / 乱数 |
| ReturnStart・ReturnRerouted・ReturnHome | 帰宅の開始・迂回・完了 | 道のり / 迂回の増分と体力 |
| OutingAborted | 行き先の施設が解体された | — |
| BecameStranded・StrandedRecovered・BecameHomeless・HomeDemolished | 立ち往生・復旧・住居なし・住宅の解体 | — |
| Anomaly | 不変条件の違反を検出 | 問題の値 |

- **結果の色**(`SimEventResult`): 経過=白、成功=緑、**不成立(確率・条件。普通の結果)=灰**、**注意(設計上ありえるが普通ではない)=黄**、**確認された違反=赤**。意外な抽選結果は、赤にしない。
- **外出判定の不発は、イベントにしない**。毎ティック全住民ぶんになり、リングバッファを埋めるため。代わりに、**住民ごとの集計**(判定回数・当選回数・連続の不発・直近の確率と乱数・どの場合か)と、**ティック全体の「新しく外出を考える時間か」**(就寝中・遅い時刻・施設なし)を持つ。これで「なぜ外出しないのか」を画面で見られる。
- **外出のまとまり**(`outingId`): `OutingRoll` で始まり、`OutingBlocked`・`ReturnHome`・`BecameStranded`・`BecameHomeless`・主目的の施設選びの失敗で終わる。`StrandedRecovered` で、新しいまとまりが始まる。立ち寄りの失敗は、外出を終わらせない(帰るため)。

### 5.2 判断の内訳(`SimDecisionDetail`)
施設選び1回ごとに、**判断した時の値を丸ごと**残す(後で設定や住民が変わっても、その時の計算を読み返せる)。
- 設定の写し(`ResidentSimSettings` 160バイト)・住民の特徴・体力・需要・利用履歴。
- 目的の決定の過程(`PurposeTrace`): 不足していたか・引いた乱数・確率。
- 候補ごと(`CandidateEvaluation` を拡張): 除外の理由・必要な体力・**重みの内訳**(`FacilityWeightBreakdown`: 適性・品質係数・値段係数・距離係数・積・下限・重み)・再訪倍率・再訪後の重み・最終の重み・選択確率・**抽選の累積の範囲**。
- 抽選の過程(`FacilityChoiceTrace`): 引いた乱数・重みの合計・乱数×合計。
- 立ち寄り: 確率・乱数、食事系の連続の確率・乱数。
- **計算は1か所**: `ComputeFacilityWeight` は `ComputeFacilityWeightBreakdown` の `weight` を返すだけ。画面は、記録された値を見せるだけで、別の式で計算し直さない(**画面とルールがずれない**)。

### 5.3 容量(リングバッファ)
| 種類 | 既定の上限 | 1件の大きさ | 上限での最大 |
|---|---|---|---|
| イベント | 20000 | 104バイト | 約2.0MB |
| 判断の内訳 | 2000 | 376バイト + 候補1つにつき120バイト + 履歴 | 候補4軒で約1.8MB |
- 上限で古い物を捨て、**捨てた件数・残っている一番古い番号**をパネルに出す。判断の内訳は、イベントより先に捨てられる(捨てられた内訳は「内訳は捨てられた」と出す)。
- 実測(テスト用の街、住民6人、111週): イベント 15056件、判断の内訳 1793件、合計約2.9MB。1人1週あたり約23件。**住民100人なら、イベントの上限20000件は約9週ぶん**(多い街で長く見たい時は、`SetCapacity` で増やす。段階2で、フィルタ・保存を検討)。

### 5.4 異常の検出(`CheckResidentInvariants`。純粋な関数)
ティックごと(約3秒)と、施設の利用の後に調べる。**新しく違反になった時だけ**イベントにする(続いている間は、繰り返さない。直ったら、再発をまた記録する)。
| 異常 | 条件 | 誤検出を避けた点 |
|---|---|---|
| NonFiniteValue | 体力・需要・満足度・時間・位置が NaN/Inf | — |
| StaminaOutOfRange | 体力が負、または、**住民の基準の上限**を超える | ペナルティで実効の上限が下がっても、今の体力は自動では下がらない(設計)ので、実効の上限とは比べない |
| NeedOutOfRange / SatisfactionOutOfRange | 需要が0〜100の外 / 満足度が0〜上限の外 | — |
| PenaltyOutOfRange | 段階が負、または100超 | 実行中に「最大の段階」のスライダーを下げても、誤検出しない |
| StopCountNegative | 立ち寄り回数が負 | 上限超過は見ない(スライダーで変わるため。段階6) |
| WaypointIndexOutOfRange | 移動中で、経路が2点以上あるのに、添字が経路の外 | 経路が2点未満の移動は「到着」として扱う設計なので、違反にしない |
| MissingTargetFacility | 向かっている・利用中なのに、行き先が0、またはオブジェクトが無い | 帰宅中・住居なし・立ち往生は、行き先が0でよい |
| MissingHome / HomelessWithHome | 家のidのオブジェクトが無い/家にいるのに家のidが0/住居なしなのに家のidがある | — |

## 6. パネル(「住民デバッグ」)と、既存操作との共存
- 住民または住宅をクリックすると、**既存の追従・選択の動きはそのまま**で、パネルの対象がその住民に切り替わる(`Game::Update` が `m_followAgentId` / `m_selectedBuildingId` を、`NotifySelection` で渡す)。住宅を選んだ時は、その住宅の住民を出す(家の中の住民は見えないため)。
- **固定(Pin)**: ONの間は、別の選択に切り替わらない。一覧(コンボ)から、住民を直接選ぶこともできる。
- 地面をクリックして選択を外しても、**最後の対象は残る**(情報を読み続けるため)。
- **ロード・リセット**で記録の世界(`runId`)が変わると、対象は無効になり「選ばれていません」と出る(別の世界の同じidを、誤って見せない)。タイトル画面では、対象を外す。対象の住民がいない時は、無効なIDを読まず、その旨を出す。
- **パネルを開いても、ゲーム内の時間は止まらない**(時間を止めるのは、これまでどおり、メニュー・住民情報パネル・配置ツールの選択だけ)。
- タブ: **現在**(住民・外出・需要と体力・特徴・移動の経路・次の外出判定・最近使った施設)/ **判断の詳細**(目的の決定・候補の表・抽選・日本語の計算式)/ **処理履歴**(外出ごとのまとまり。色分け。判断のある行から[詳細]で、判断の詳細へ移る)/ **異常**。
- 日本語の計算式の例(実際の値): `基本の重み = 目的への適性 1.80 × 品質係数 1.0878 × 値段係数 0.5605 × 距離係数 0.7786 = 0.85459` → `再訪補正後 = 基本 0.85459 × 直近利用履歴による倍率 0.833 = 0.71215` → `選択確率 = 0.71215 ÷ 合計 0.78945 = 90.21%`。

## 8. 段階2: 履歴の見返しと、一時停止(2026-10-29)

段階2として、**記録された履歴を、後から読み返す**道具を足した。街(ゲームの世界)を巻き戻す機能ではない(指示書の約束)。解説は [docs/study/simulation_debug_system.md](../study/simulation_debug_system.md) の §7。

### 8.1 ライブと履歴
| モード | 意味 |
|---|---|
| ライブ | 最新のイベントを追う(カーソルは、いつも最新)。処理履歴は、一番下を読んでいる間だけ、増えたイベントを追って下へ動く |
| 履歴 | 過去のイベント1件を「見る位置(カーソル)」にして、固定して読む。**新しいイベントが来ても、表示は動かない**。画面に「履歴を表示中(記録の閲覧です)。現在の街は巻き戻っていません。ゲームは、そのまま進んでいます」と出す |
- シークバーを動かす・イベントの行をクリック・「前」「次」などの移動で、履歴モードに入る。「ライブに戻る」「最新(ライブ)」で戻る。別の住民へ切り替えると、ライブに戻る。
- 履歴モードの「現在」タブは、**イベントに残した写し(その時点の状態)**を出す。写しに無い物(位置・経路・滞在の残り)は、記録していないので、**補間せずに、出せないと書く**。
- 「判断の詳細」は、カーソルの時点(そのイベントを含む)より前で、一番新しい判断に合わせる。

### 8.2 時間軸(シークバー)
- 時間軸 = この住民の、絞り込みを通ったイベントを、古い順に並べた物(`SimTimeline`。画面に依存しない純粋な関数)。ドラッグで、1イベントずつ選ぶ(街の時刻に比例しない。記録された「イベント」が、目盛り)。
- バーの上に、**注意(黄)・異常(赤)の目印**、下に**ブックマークの三角**を重ねる。
- 移動: 先頭 / 前 / 次 / 最新(ライブ) / 前の外出・次の外出(外出のまとまり単位) / 前の注意・異常・次の注意・異常 / 前のブックマーク・次のブックマーク。
- 絞り込み・検索: 不成立(灰)を隠す / 注意と異常だけ / 文字検索(イベントの種類・日本語の説明に含まれる文字)。時間軸と処理履歴の両方に効く。**ブックマークしたイベントは、絞り込みでは隠さない**。見ていたイベントが絞り込みで外れた時は、それより前の一番近いイベントに寄せる。
- 容量の上限で古いイベントが捨てられると、時間軸の範囲も縮む。見ていたイベントが捨てられたら、一番古い物に寄せて、その旨を出す。ブックマークも、捨てられたものは消える。
- ブックマーク: 全住民ぶん。一覧から、その住民・そのイベントへ移れる。世界が変わる(ロード・リセット)と消える。

### 8.3 一時停止の条件
- 条件(`SimBreakpoints`): ①確認された異常(赤)で止める ②注意(黄)以上で止める ③イベントの種類(複数)で止める + 結果の絞り込み(成功/不成立/注意/異常/経過/問わない) ④対象の住民(全住民 / 今の住民だけ。④は①〜③の全てに掛かる)。例: 種類=立ち寄り判定 + 成功 → 立ち寄りに当選した瞬間に止まる。
- 記録(`AddEvent`)の中で、イベントごとに調べ、当てはまったら**「止める印」を立てるだけ**(最初の1件。解除までは、次の印を立てない)。記録部は、時間を止めない・乱数・住民の状態に触れない。
- **実際に止めるのは、`Game`が、シミュレーションの更新(`DemandSystem::Update`)が済んだ、その直後の安全な所**。同じフレームで、すぐ止める(倍速では、次のフレームまで待つと、大きく進むため)。
- 既存の停止(メニュー・住民の情報パネル・入居パネル・配置ツール)と、**同じ仕組み**(`SyncMenuTimeScale`)に載せた。元の倍率を1回だけ覚え、止める物が全て無くなったら戻す。重なっても(止まっている間にメニューを開閉しても)、倍率は正しく戻る。
- 止まったら、パネルの上に「一時停止中: 住民 #n のイベント #m で、止まりました」と、**[再開]**・**[このイベントを見る]**を出す。固定(Pin)でなければ、そのイベント(の住民)を、自動で履歴として開く。
- 記録がOFFの間・世界が変わった時は、印を外す。条件そのものは、世界が変わっても残す。ReleaseのExeでは、記録が無効なので、止まらない。

### 8.4 やらなかったこと
- 街の巻き戻し・移動の動画再生・位置の低頻度サンプリング(指示書の「別途見積り」。必要になったら、選んだ住民だけで検討する)。
- 条件の保存(Settings)。今は、起動のたびに、条件はOFF。

## 9. 段階3: 行動テスト(2026-10-29)

段階3として、**住民に、意図した行動を、1回だけ実行させて、結果を確かめる**道具を足した。解説は [docs/study/simulation_debug_system.md](../study/simulation_debug_system.md) の §8。

### 9.1 指示 → 計画 → 消化(画面は、住民の内部を直接触らない)
```
画面(行動テストタブ) ── SimTestCommand ──▶ DemandSystem::SubmitTestCommand
                                              └ 対象を選び、住民ごとの SimTestPlan(待機中)を作る(状態は変えない)
次の安全なタイミングで、1回だけ消化:
  ・更新の最初(ProcessImmediateTestPlans): 帰宅させる / 行き先を変える / 体力を決める
  ・外出判定(RunDemandTick の住民ループ): 外出させる(確率の抽選だけを当選にする)
  ・立ち寄り判定(TryStartStopover): 立ち寄りを当選させる
```
- **3つに分けて持つ**: 行動(`SimTestAction`)/ 強制の範囲(`SimTestMode`: 通常ルール or 施設を指定)/ 対象(`SimTestTarget`: 今の住民・範囲・全住民)。実行のタイミングは、行動で決まる(上の3か所)。
- **計画の状態**: 待機中 → 実行中 → 成功 / 拒否 / 取消 / 期限切れ。「拒否」は、普通のルールに合わなかった(異常ではない。理由を一覧に出す)。**成功**は、強制した判定が、指示どおり行われた時(外出の後、頼んだ回数の立ち寄りが始まった、など)。
- 計画は、住民1人につき、同時に1つ(待機中の物があれば、新しい指示は「別のテストが実行中」で拒否)。**実行中**(外出が始まった後)の計画は、新しい指示で**置き換えられる**(取消。「外出させる」の後に、続けて「帰宅させる」や「立ち寄りを当選させる」を試せるように)。
- 待機中の計画は、**次の週が始まるまで**に消化されなければ、期限切れ(夜に出した外出指示は、朝まで待つ)。ロード・リセットで、全て期限切れ(住民が入れ替わるため)。

### 9.2 「通常ルール」と「施設を指定」
| モード | 強制する物 | 通常どおり通す物 |
|---|---|---|
| 通常ルール | 外出判定・立ち寄り判定の**確率の抽選だけ**(乱数を引いて、当選にする) | 時刻・体力・到達できるか(道路・距離)・今回使用済みの施設・経路探索・食事系の連続の確認。合わなければ、実行せず、理由を返す |
| 施設を指定 | 抽選の結果を無視して、**指定した施設**を選ぶ | 上と同じ。指定した施設が除外される(範囲外・体力不足・使用済み・種類の制限など)なら、**拒否**(理由は、除外の理由の番号つき)。除外を、飛び越えては選ばない |
- 食事系が続くので寄らない、という**確率の判定は、強制しない**(その結果は、拒否「食事系が続くので、取りやめた」)。
- **乱数の消費は、強制の有無で変わらない**: 抽選の乱数は、強制する時も、必ず1つ引く(当選にするだけ)。強制していない住民の動きを、乱らさないため。ただし、強制した住民は、その先の行動が変わるので、街の結果(来客・売上・所持金・以降の乱数の使われ方)は、強制した分、普通のプレイと違ってくる。

### 9.3 行動の一覧
| 行動 | 対象になる状態 | 内容 |
|---|---|---|
| 外出させる | 家にいる | 次の外出判定を当選にする。「外出の後、立ち寄りも当選させる回数」(0〜設定の上限)も指定できる。立ち寄りの回数が終わった時点で、計画は成功。外出が終わるまでに、立ち寄りが指定の回数に届かなければ、「判定が来なかった」で拒否 |
| 立ち寄りを当選させる | 外出中 | 次の立ち寄り判定(指定の回数)を当選にする |
| 帰宅させる | 外出中 | 今の位置から、家へ帰らせる(施設は使わない。売上・回復なし。位置は飛ばさない) |
| 行き先を変える | 施設へ向かう途中 | 今の位置から、指定した施設への経路を作り直す(帰りの経路・体力・今回使用済みも確認) |
| 体力を決める | 全て | 体力を指定の値(0〜上限)にする |

### 9.4 対象と安全
- 対象: 今の住民 / **範囲(四角)**: 実行ボタンを押した時の、住民の位置で選ぶ(辺の上も含む) / 全住民。**一度に実行する人数の上限**(既定50、最大500)。超えた分には、実行しない(画面に出す)。
- 11人以上に実行する時は、**確認の画面**を出す。実行後は、待機中・実行中の指示を**取り消せる**(済んだ行動は、戻らない)。
- 結果の一覧(新しい順): テスト番号(**[履歴]で、その時のイベントへ移る**)・住民・行動・状態・立ち寄り(始まった回数/頼んだ回数)・理由。

### 9.5 記録とのつながり
- 計画を消化した時に、**テスト指示**のイベントを1件記録する(`SimEventKind::TestCommand`。a=テストの番号)。拒否も、1件(灰色。理由の番号つき)。
- 計画が動いている間に、その住民が記録する全てのイベント・判断の内訳に、**テストの番号**(`testId`)が付く。処理履歴では、`[テスト#n]` の印が付くので、**普通の行動と区別できる**(段階4の統計で、除外するための目印)。
- 判断の内訳には、「施設を指定で、強制した」印(`forcedFacility`)も付く。

### 9.6 できないこと・注意(正直に)
- **街の状態の完全な復元はできない**。強制した行動の結果(来客・売上・所持金・満足度・ゲーム内の履歴)は、本物のプレイと同じように、街に反映される。**やり直したい時は、先にF5でセーブしておく**。ロードしても、乱数の状態は、戻らない(段階5)。
- 強制した来客・売上を、統計から除外する仕組みは、段階4。今は、`testId` の印が付くだけ。
- Releaseのexeでは、この機能は無い(エディタのビルドだけ)。
