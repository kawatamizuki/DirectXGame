# 商業エリア(商店街)P2-A: 計画区画と周知(2026-11-09)

仕様書 `DirectXGame_P2_商業エリア_段階的実装仕様書` の **P2-A**。区画を置き・動かし・消し・周知し、店舗数と進捗を見られるようにする。**住民の行動・売上・評判・期限には、まだ、何も影響しない**(エリア目的の外出は P2-C、猶予後の評判の変化は P2-D、施設の用途タグ・競争は P2-B、テナントは P2-E 以降)。仕組み・見つけた問題は [docs/study/commercial_area_p2a.md](../study/commercial_area_p2a.md)。数値は全て仮(`CommercialAreaSettings`。Editorの「商業エリア」パネルで、実行中に変えられる)。

## 1. 制作者と決めたこと
| 項目 | 決定 |
|---|---|
| 区画の形・操作 | 固定の 8×8 マスの正方形(ワールドの軸に沿う)。クリックで仮置き(無料)・ドラッグで移動・削除。道路の向きに沿った斜めの区画・大きさの変更は将来 |
| 区画どうし | 重ならない(隣接=辺が接するのは可)。これで「同じ施設は1エリアまで」が、自然に守られる |
| 周知後の移動・削除 | 許可する。履歴に記録し、進捗・猶予は、リセットしない(罰則逃れの防止は P2-D で使う) |
| **施設の所属(制作者の指定)** | **建物の敷地面積の50%以上が、区画の中にある時**。中心の位置では判定しない。`footprintRect` と区画の矩形の、重なり面積から判定。50%は仮設定(調整可)。区画の移動・建築・解体で、自動的に更新。二重所属しない |
| 仮の数値 | 計画規模 8 店舗・進捗の段階 4 / 6 / 8・猶予 8 週(P2-A では、残りを見せるだけ) |
| 道路 | 区画に含まれても、店舗数には数えない。道路・建物は、区画によって変わらない |

## 2. 仕組み
- **区画(`CommercialArea`)**: ID・矩形・公開状態・周知した週・周知した時の計画規模・達成状態(周知後に一度でも届いた最高の段階。下がらない)・履歴(周知した/動かした/…)。
- **所属は、保存せず、毎フレーム、求め直す**(`ComputeAreaMembers`): 各施設について、区画ごとに「敷地の何%が、区画の中か」を、多角形の切り取りで正確に求め、しきい値以上の区画のうち、割合が一番大きい区画(同じならIDが小さい区画)に所属させる。対象は商業施設(コンビニ・スーパー・映画館・カフェ)だけ(住宅・オフィスは対象外)。結果は、施設の並び順に依らない。
- **進捗(`ComputeAreaProgress`)**: 店舗数 ÷ 計画規模(計画達成率)と、今の段階(未達成 / 最低進捗 / 来訪範囲の拡大 / 計画の完成)。**計画達成率は店の数だけで、実際の商業的な魅力(集客力)とは別物**(画面にも、そう書いてある)。
- **周知**: 周知すると、週と計画規模が固定され、履歴に残る。猶予は、周知した週から数え、残り週を表示する(P2-A では、罰は無い)。周知していない実在の店舗は、通常の物理的な集積・実績による効果を、失わない(P2-A では、そもそも、効果は、まだ無い)。
- **撤回**: 周知済みの区画を削除すると、「撤回の記録」(周知した週・撤回した週・計画規模・達成状態)が残る。未周知の削除は、記録を残さない(置いただけの区画は、無かったことになる)。
- **ID**: 通し番号。削除した区画のIDも再利用しない(撤回の記録・保存が、別の区画と混ざらない)。

## 3. 操作(ゲーム内)
- 右下「メニュー」→ 建築 → ツール「**商業エリア**」。ツールの間は、時間が止まり、格子線が出る(建物・道路と同じ)。
- 何も無い地面をクリック: そこを中心に、区画を仮置きする。置けない場所(他の区画と重なる)は、緑=置ける・赤=置けない、の枠で見える。
- 区画をクリック: 選ぶ。押したままドラッグ: 動かす(離した位置が、他の区画と重ならない時だけ確定)。
- 画面右の「エリア」パネル(区画を選んでいる間): 店舗数と進捗のゲージ・今の段階・達成した最高の段階・周知した週・開発の猶予・履歴。ボタン: **周知する / 削除(周知済みは「撤回」)/ 閉じる**。周知・撤回は、確認の手順(はい / やめる)を踏む。選んだ区画に所属する施設は、白い枠で囲まれる。
- Esc・右クリック: 動かしている最中ならそれをやめる → 選びをやめる → ツールをやめる、の順。
- 区画の枠は、ツールを使っていない間も出る(非公開=水色・周知済み=金色)。

## 4. 保存
- ISaveable の区画 `commercialAreas`(版 1): 区画(ID・矩形・公開・周知した週・計画規模・達成状態・履歴)と、撤回の記録と、次のID。所属・設定は保存しない。
- 古いセーブ(この区画が無い)は、「エリアなし」で読める。壊れた項目(IDが0・重複・面積なし・他の区画と重なる)は、読み飛ばす(重なる区画・二重所属を作らない)。長さの基準が変わったセーブは、矩形を、今の大きさに合わせる(道路・建物と同じ)。

## 5. デバッグ
- Editor の「商業エリア」パネル: 設定(所属のしきい値・区画の一辺・計画規模・段階の店舗数・猶予)、点検(区画の重なり・ID・二重所属)、区画ごとの状態(所属する施設と、敷地の何%が区画の中か・履歴)、撤回の記録。メモリのパネルにも、1項目。
- 乱数を使わない。住民の行動は、変わらない(実機で、区画あり・なしの12週の指紋が一致することを確認)。

## 6. P2-B 以降への引き継ぎ
- 所属の結果(`CommercialAreaManager::Members()`)と、進捗(`ProgressOf`)が、施設構成・エリア目的の外出・評判の入力になる。施設の用途タグ(P2-B)は、`AreaFacility` に足せる。
- 周知後の猶予・評判(P2-D)は、`GraceWeeksLeft`・達成状態・履歴・撤回の記録を使う。
- `ChooseOutingReason` の `areaAvailable`(DemandSystem の外出の流れで、今は false)に、「周知済みで、到達できる区画がある」を渡す(P2-C)。
- 時間を巻き戻すタイムライン(GameRewind)の、構造の変化の判定(`Game::StructureSignature`)は、建物と道路の数だけ。区画の編集は、含まない(区画は、シミュレーションに影響しないので、問題は無いが、P2-C以降は、含める)。
